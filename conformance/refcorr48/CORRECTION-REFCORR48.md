## Settled mechanism: centered blocks reset loose-scope blank-line ownership

The grouped probe extends REFCORR45 rather than replacing it. When a Span or Size scope remains open across a complete centered `[[=]]...[[/=]]` alignment block, live treats the block boundary as a new paragraph-layout segment. The first blank-line separation after that centered block can again own up to two break atoms in the bare inline fragment, even when an earlier blank line before the centered block already consumed the ordinary REFCORR45 ownership. The measured repeat shape is `b-one`, blank, `b-two`, centered block, `b-three`, blank, `b-four`: live serves both the first bare fragment and the post-center `b-three` fragment with `<br /><br />`. A plain document-root control still produces ordinary paragraphs and no bare break pair, so this is not a property of every inline scope.

A complete centered block inside the loose scope also carries a leading empty inline fragment. When the scope has ordinary inline content before the centered block, or when a blockquote or another separator prevents the scope opener itself from supplying that fragment, live opens the centered div with `<span ...><br /><br /></span>` before the first centered paragraph. This is measured in the unquoted `c-one` shape and in the quoted centered shape. That ownership does not apply to a container-local scope that already has ordinary inline content before the centered block: cached canonical-live witnesses `scp-7141` and `scp-cn-367` keep their Size scope outside the centered div in that shape. The corpus `scp-2983` control likewise keeps only the breaks already supplied by repair. A document-root scope that has already crossed an ordinary blank-line paragraph boundary is also outside the manufactured leading edge when no horizontal rule intervenes, because repair already propagates the scope into the centered block; `scp-5188` is the duplication control. A horizontal rule before the centered block breaks that natural propagation, so the snake-soushi later-center witness still uses the manufactured fragment. Otherwise a scope at document root, or one that enters the container from outside, uses the matrix behavior. It is not doubled when the opener directly abuts the centered block and repair already supplies the empty fragment, nor when an earlier REFCORR45 blank-line ownership has already supplied the pre-boundary breaks. The rule is center-specific: the frozen h101 holdout control, a red Span crossing a left-alignment `[[<]]` block, already matched live with exactly two breaks and regressed if the same ownership was inserted for a non-center alignment.

A scope that has already crossed the end of its enclosing Div, alignment, or collapsible block is outside the mechanism; the cached `ambrose-thorn-valley` movement exposed that boundary, where a long unclosed Span survives past its enclosing menu div and live does not produce a new centered leading fragment. The first blank line after the centered block starts the post-block segment whether or not ordinary text precedes it. If the blank line is immediate, it reconstructs paragraph layout without a visible extra break fragment and consumes that segment; this is the `blankafter` control. If ordinary inline text intervenes first, the blank line produces the visible `<br /><br />` fragment. Later blank lines in the same post-block segment do not repeat the fragment.

`Newline.php` implements both halves before the Paragraph rule consumes blank-line separators. It recognizes the parser-generated blank run at the leading edge of a nested centered alignment block inside a loose Span/Size scope, subject to the direct-opener, prior-ownership, container-local-content, naturally-propagated-scope, and enclosing-block-escape exclusions. Independently, it tracks completed centered alignment blocks inside the scope and resets blank-line ownership once per post-center segment. The implementation does not apply the leading-edge insertion to left, right, or justify alignment blocks.
