# CORRECTION-REFCORR70: Module tokens are allocated before Raw tokens

## Adjudication

REFCORR70 used eight fresh immutable probes on `sandbox-for-codex.wikidot.com`: the byte-exact `scp-cn-048` control `muse-p-scp048-exact`; the allocation controls `muse-p-scp048-emptyraw` and `muse-p-scp048-nonemptyraw`; the Module/Raw precedence controls `muse-p-scp048-module-emptyraw` and `muse-p-scp048-module-nonemptyraw`; the Code-position controls `muse-p-scp048-code-before` and `muse-p-scp048-code-after`; and the module-body control `muse-p-scp048-module-bodyraw`. Every capture is valid, stable across repeated anonymous reads, and saved-source-byte-identical. No existing probe page was edited.

The empty/nonempty Raw controls and both Code-position controls were already exact in the reference and remain exact. They exclude three explanations for the stale cached production `.alt-block` insertions: empty Raw lines do allocate ordinary tokens, nonempty Raw atoms likewise allocate ordinary tokens, and a `[[code]]` block carrying the `.alt-block` CSS is inserted by a numeric collision at the same document-local index whether the Code block appears before or after the collision. Code position is therefore independent of the measured residue.

The module controls settle the live ordering. In both `module-emptyraw` and `module-nonemptyraw`, live renders the Rate widget once at the authored module position and again at the `�1` collision. The collision digit names the Module token; the leaked original Size index is `3` in both shapes. Under the fossil rule order the reference allocated the Raw token first, then the Module token, so the same collision did not name the module. Moving the Module family before Raw makes the reference token stream match that live allocation. After substitution of the harness's environmental `þmodule "Rate"þ` marker by live's Rate-widget HTML, both module probes are byte-exact live matches.

The final module-body control separates token allocation from body parsing. `muse-p-scp048-module-bodyraw` uses an unknown module whose body is `@@x@@`. Live emits one unknown-module error and then `<span style="font-size:large;">2z</span>` at the collision; the corrected reference is byte-exact. Thus the unknown Module token is allocated before the body Raw scan even though the body is not rendered for the unknown module.

## Implementation

The first implementation physically moved the module block family ahead of `Raw`, `Rawold`, and `Html` in the parse-rule list. It passed these probes but changed the fossil parser's cross-rule composition on corpus pages: module frames could swallow documented or HTML/JS-carried module closers before the opaque rules had claimed their atoms. The corpus landing bar rejected that ordering even though the probe allocation direction was correct.

The landed implementation therefore separates the two observations. `text-wiki/Text/Wiki.php` keeps the established fossil parse composition, then renumbers the finished token stream so `Modulepre`/`Module`/`Module654` allocations precede `Raw`/`Rawold`/`Html` allocations, with the relative order inside each family preserved. Before renumbering it compacts a Raw/Rawold/Html token that exists only inside an owning module body: the authored body bytes are restored in that module option and the unreachable opaque token is removed. This models the live allocation fact pinned by `module-bodyraw` without letting the ordering change reframe opaque corpus text as real module syntax. The pre-correction copy is `Wiki.php.before-refcorr70` in this directory.

## Pins and remaining discriminator

`cases.jsonl` contains the exact control and seven reduction/control sources. `captures.json` records the stable source-identical live captures; `tokens.jsonl` records the corrected reference post-parse token tables; `expected.json` pins the corrected reference bytes. `verify_refcorr70.py` checks capture validity, expected-render bytes, direct exact live fidelity for the five non-Rate controls, exact structural fidelity for the two Rate controls after the harness-module substitution, and the exact control's module-insertion structure. At the pin run all checks passed.

REFCORR70 does **not** close the whole `scp-cn-048` residue. On the byte-exact control, the corrected reference now inserts the Module token at both collision points, as live does, and does not insert the `.alt-block` Code block. The remaining live/reference difference is a constant two-token allocation gap: live leaks `70` before `LN5` and `937` after each `<S6m}S` collision, while the corrected reference leaks `68` and `917` at the same positions. The visible leaked digit is the concatenation of the following Typography placeholder (`91` reference, `93` live) with the next authored digit `7`, so both sides agree on token type and local collision mechanics; they differ only by two invisible token allocations earlier in the document. That +2 allocation residue is the named next discriminator, not part of the correction pinned here.
