# R2 Footnote and bibliography family stage: differential and correction catalog (2026-11-20)

Method. This stage runs as a team of six rule owners plus a root coordinator, one owner for each of the nineteenth-through-twenty-fourth pipeline rules in this batch: Footnote, Footnoteitem, Footnoteblock, Bibitem, Bibliography and Bibcite. The family is defined by shared document state: footnotes are numbered and collected across the whole document and rendered where the footnoteblock sits, and bibliography entries are keyed, ordered and resolved by citations that can appear before or after the bibliography, so per-rule differentials only mean anything inside whole documents. The shared reference harness (ref-php/harness/batch.php in expand, render and tokens modes, transform.php for the smoke run) is read-only for rule owners; harness problems go to root. Before any teammate starts, root audits batch.php for cross-case leakage of this family's document state (footnote lists and bibliography entries and their id maps) and adds the minimal per-case reset the evidence requires, disclosed here; a differential polluted by leaked state is worse than no differential. Root builds one shared ftml dumper at conformance-refphp/notes/rust-dump/ in the Form/Raw stage's style (preprocess_for_layout, tokenize, parse, HtmlRender over JSONL {"id","source", optional "tags"}) and records the read-only ftml checkout HEAD in that directory before any differential starts; every cargo invocation goes through heavy-build.sh with HEAVY_BUILD_NO_SPLIT=1 as a polled background job. Live probes use the wikidot-probe CLI through its scripts/wikidot-python wrapper against sandbox-for-codex, with prefixes partitioned per rule (muse-probe-r2notes-fn-, -fni-, -fnb-, -bibi-, -bib-, -bibc-) and root's cross-rule prefix muse-probe-r2notes-x-; fetch once, cache, reuse. Corrections land only in a rule's own two files under ref-php/text-wiki/Text/Wiki/Parse/Default/ and Render/Xhtml/, with pre-correction bytes preserved as conformance-refphp/notes/<rule>/<File>.before.php. Serving-layer scope is as in earlier stages: what a rule computes from page or site state is evaluated only as far as live's anonymous saved-page view makes it observable and deterministic, with the stage owning matching, tokenizing, numbering and ordering and the observable display shape. Each owner writes conformance-refphp/notes/<rule>/SECTION.md ending in exactly COMPLETE or a BLOCKED: reason, and root fills these parts as the sections land.

Harness audit (root). Root audited batch.php for cross-case footnote and bibliography state leakage before any teammate started, with a seven-case whole-document battery and a fresh-process control; the full record is conformance-refphp/notes/audit/AUDIT.md. No actual leak exists: the family's state lives in Text_Wiki::$vars, an instance property, and each batch case constructs a fresh Text_Wiki, so numbering restarts at 1, an empty footnoteblock stays empty and an undefined bibcite keeps its error span after earlier cases defined state. The only process-static on the family's path is Math's equationsArray (already reset by the LINK stage and read into an unused local by the Footnote render rule). Root still added a minimal, behaviour-neutral per-case reset of footnotes, bibitems and bibitemIds after wiki construction in the render and tokens branches as insurance, preserving the pre-reset batch.php as conformance-refphp/notes/audit/batch.php.before.php (SHA-256 f8640409b069c85779d0751fff32eea969483e7a52f908dbbc830459d4260c4b) and verifying byte-identical pre- and post-reset battery output. Root also made one second disclosed shared-harness change: the run-owned live page muse-probe-r2notes-x-inc-src was added to ref-php/harness/pages.php with source byte-identical to the sandbox page, so the reference's Include rule resolves root's focused included-content probe and the document-order numbering seam can be compared; the ftml dumper has no includer by design, which is a stated serving-layer boundary. A third disclosed harness change came from the Bibliography owner's evidence: batch.php previously injected $wiki->vars['page'] only for cases with a non-empty tags array, so untagged cases left the Iftags rule with no page object and it dropped its gated body before Bibliography ran, while tags:["unrelated"] made the same cases match live. Root changed all three mode branches to inject a RefPage unconditionally with an empty tag set when no tags are declared, which is the untagged-page semantics the R2-next comment always intended; verification is in conformance-refphp/notes/audit/iftags-fix-check.jsonl and its .out, where untagged, tags:[] and tags:["unrelated"] now render identically for both affected cases. Only Iftags reads vars['page'] in the reference tree, and transform.php is a one-document driver with no tags input and no Iftags smoke case, so it was left unchanged. These three harness changes are the only ones this stage makes.
