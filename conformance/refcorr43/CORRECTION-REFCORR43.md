## Size/Collapsible leading breaks

The reduced witness shape is an alignment div closed with exactly one newline, followed immediately by a `[[size ...]]` scope whose first block content is a `[[collapsible ...]]`. In that continuation context there is no paragraph boundary after the alignment div. The raw malformed serialization therefore places the Size opener directly against the collapsible block. Live's serving repair materializes the pre-block portion as an empty size span containing two breaks, closes it before the collapsible, and reopens the size scope inside the collapsible fold/link structure. The controlling variable is direct adjacency in that no-paragraph continuation, not the rate module, the number or form of preceding closed span pairs, alignment direction, plain versus span text, the collapsible body length, or whether the body begins with a blank line. A blank line after the alignment close creates an ordinary paragraph boundary and suppresses the extra fragment.

The correction is split between `text-wiki/Text/Wiki/Parse/Default/Collapsible.php` and `text-wiki/Text/Wiki.php`. Collapsible records when the Size opener it captured was separated from the collapsible opener by a newline. While rendering that marked collapsible, the reference checks whether the output immediately before the block is still the open Size span; only that no-paragraph direct adjacency receives the measured empty two-break Size fragment and reopened scope. A same-line Size/Collapsible in a table cell therefore remains unchanged, and a blank line upstream that creates a paragraph boundary also remains negative. The existing purifier then performs the same nesting repair as live. All six reduced live-probe pages are byte-identical after the correction, including the blank-line negative control, and the `scp-1722-jp` witness becomes live-canonical identical. This is recorded as an ftml parity item because ftml diverges in the same witness seam.

## Scored-div segmentation

REFCORR29's depth-zero blank-line stripping was too broad. Its live probe used two content lines inside each scored div, so the first line was a block-lead edge and the final line was a close-edge; no interior line existed that could expose paragraph segmentation. The new probes use three and ten interior segments. Live preserves ordinary blank-line paragraph formation inside `[[div_ ...]]`: the first edge remains bare, middle blank-line-terminated lines become `<p>` elements, and the final close-edge remains bare. Nested scored and unscored divs, collapsible content, center lines, and size-zero lines retain the same ownership; blockquote bodies remain opaque. A preceding CSS module does not alter the behavior.

The correction is in `text-wiki/Text/Wiki/Parse/Default/Div.php` and `text-wiki/Text/Wiki/Parse/Default/Paragraph.php`. Div no longer reparses or deletes depth-zero blank-line runs in scored content. It strips leading vertical edge whitespace and normalizes trailing vertical edge whitespace to one boundary newline, preserving the close-edge without turning it into a paragraph. Scored Div end tokens are marked, and Paragraph leaves a run containing such a close token bare so the final edge cannot be wrapped across the div boundary. The `their-own-vestiges-jp` witness becomes live-canonical identical under exactly one purify-equivalent comparison pass. A regression-reduction probe for explicit list edges additionally settles that a newline immediately after an explicit `[[li ...]]` opener and before a block div is layout, not a served break, while the newline before the item close remains a break; that guard is pinned in the same round. All nine grouped probe pages pass both expected-render byte pins and live-canonical pins in `verify_refcorr43.py`.
