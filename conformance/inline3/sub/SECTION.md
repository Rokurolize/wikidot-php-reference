# R2-INLINE3 section: Subscript (pipeline rule 51)

## Mechanism as corrected

Subscript pairs `,,` markers by first fit in the source text at Stage 1, and the render maps a start token to `<sub>` and an end token to `</sub>` with no css class by default; the render file needed no change. A non-empty body is accepted only when it opens and closes in non-whitespace, which is retained verbatim from the fossil regex, so an inner padded comma pair does not split a body and `,,a ,, b,,` renders `<sub>a ,, b</sub>` (sub11, live-confirmed), while a genuinely padded body such as `,, padded ,,` never pairs and stays literal (sub21 through sub23, all three sides). A comma-run body pairs with the earliest eligible closer, so `,,,a,,,` gives `<sub>,a</sub>,` (sub12) and `a,,b,,,` gives `a<sub>b</sub>,` (sub14). An adjacent empty pair `,,,,` is a real pair whose two markers are consumed and that renders nothing, and it wins at the same source position before a longer body can claim the markers: live renders `,,,,four,,,,` as `four` (sub13), `A,,,,B` as `AB` (sub20), and `,,,,,five,,,,,` as `,five,` (sub30). This is the same first-fit empty-pair drop the Emphasis owner settled for `////`, and it is now reproduced here by trying the four-comma empty branch before the non-empty branch. Unpaired markers stay literal (`a,, b`, `Smith,, Jones,, and Doe`, sub07 through sub09 and sub16 and sub17), and triple/quadruple runs that do not form an adjacent empty pair keep their fossil first-fit pairing (sub28 `,,,triple,,,` to `<sub>,triple</sub>,`). Crossings with `^^`, `**` and `--` (sub39 through sub41) pair flat in source order at Stage 1 and are re-nested by the Stage 2 repair stack on live and in ftml; this stage records that as frame-level and does not patch it, per the 2026-11-04 ruling.

## Corrections and classifications

C1 is the only correction and it is confined to ref-php/text-wiki/Text/Wiki/Parse/Default/Subscript.php. The fossil regex `/,,([^\s](?:.*[^\s])?),,/U` was replaced with `/,,,,|,,([^\s](?:.*[^\s])?),,/U`, placing the empty-pair alternative first because live prefers the empty pair at the earliest source position (sub13 is the decisive case), and process() now returns an empty string when the body group is absent, consuming both markers without emitting a Subscript token pair. The non-empty branch is otherwise byte-for-byte the fossil pattern, so every collision form that live already agreed on keeps its Stage 1 behaviour; only sub13, sub19, sub20 and sub30 changed in the after render, and no other case in the 55-case battery moved. Classification: fossil-era artifact at the Stage 1 first-fit empty-pair surface, equivalently a reference bug there; live settled it through probes sub13, sub19, sub20 and sub30 (all valid, stable and source-matching), the frozen ftml pin test/subscript/basic independently records `Then empty subscript: ,,,,` as `<p>Then empty subscript:</p>`, and ftml's own empty-container drop in parsing/rule/impls/subscript.rs corroborates the shape without any ftml edit. No correction was classified as a PHP-version artifact or a harness matter, and no shared harness file, stub, reset, dumper, other rule file or ftml file was touched by this owner.

## Questions, assumptions, and coverage gaps

Three questions arose mid-work and were proceeded on with recorded assumptions. The first was whether to adopt the broad `,,(.*),,` regex and padded-body rejection used by the Emphasis owner; the assumption adopted was no, because live and the frozen pin settle `,,a ,, b,,` as a real pair that reaches past an inner padded comma marker, which a padded-reject rewrite would break, so the minimal empty-pair alternation preserves every settled comma-run shape and was confirmed by sub11, sub12, sub13 and sub30. The second was whether the crossed-marker misnesting should be corrected in Subscript; the assumption was the standing 2026-11-04 two-stage ruling, which assigns cross-construct re-nesting to Stage 2, so those cases were recorded as frame-level. The third was whether the line-break trailing space belongs here; the assumption was that it is an output-shaping residual for the Tighten owner, so it was left frame-level. Coverage gaps are stated rather than padded: the probe tool creates untagged pages only, so no iftags or per-page tag seam was probed; Wikidot normalizes trailing whitespace on save, so no claim is made about pre-normalization trailing-space shapes; the explicit `[[sub]]` and `[[subscript]]` block forms are literal on live in the frozen test/subscript/basic pin and are not implemented in the reference, and the related explicit `[[ul]]`/`[[ol]]`/`[[li]]` block forms encountered in ftml's subscript pins are the ledger's M46 gap, explicitly not this stage's work, so both were recorded and not chased. The whole-map capture failed once on a transient ConnectTimeout and was recovered by disjoint chunked capture with only valid, stable, source-matching records merged, as disclosed above. The crossed-family corpus pins beyond the simple pair are large and often record ftml parity gaps, so this section cites only the pins that directly settle battery shapes and leaves the deeper crossed-shell families to ftml's own tests and root's cross-rule interactions.
