# R2-inline2 Underline rule (47): differential and correction section (2026-11-20)

Method. I compared three sides over a 60-case whole-document battery (battery.jsonl generated by make_battery.py, intent in battery-notes.md) covering plain __ pairs, pairs nested with and around ##color|, **, // and -- including the two crossed corpus-pin shapes, unpaired and tripled markers, marker runs of four-to-eight underscores, markers at word boundaries and inside words, padded and empty bodies, line breaks and block/heading/list boundaries, dunder and single-underscore identifiers, code and raw shields, headings, link labels and table cells. The reference side is the shared read-only harness ref-php/harness/batch.php in render and tokens modes, captured before correction as ref-render-before.jsonl and ref-tokens-before.jsonl and after correction as ref-render-after.jsonl and ref-tokens-after.jsonl, each with an empty stderr sidecar. The ftml side is the stage's one shared dumper at conformance-refphp/inline2/rust-dump/target/release/r2inline2-rust-dump over the same battery at the recorded HEAD 751e34491193374e771142632720e17ac32e2864, cached in ftml-dump.jsonl with an empty stderr sidecar; I did not run cargo. Live evidence is one saved-page campaign of 12 pages under the prefix muse-probe-r2in2-u- on sandbox-for-codex (cases.jsonl, create-map.json, captures.json, capture.err), all double-fetched with stable=true, saved_source_matches=true and valid=true; no page was deleted. Frame normalization in compare.py strips whole-document whitespace between tags and canonicalises <br /> to <br>, so frame padding owned by later rules is separated from Underline-layer output. Exact pre-correction bytes of both rule files were preserved as Underline.php.before.php and UnderlineXhtml.before.php before any edit.

Mechanism as corrected. The parse rule now uses the regex /____|__([^\s](?:.*[^\s])?)__/U: its first alternative deletes an adjacent empty __ pair outright and its process() method returns the empty string for that branch, while the original pair regex is retained unchanged as the second alternative so padded-body rejection and first-fit ungreedy pairing behave exactly as before. This reproduces live's symmetric-marker first-fit exactly, including the discriminating shape __a____b__, which live (probe p08, html_sha256 27e6ae8d19f56caccdd2e7a195f9cef9937c792e3c4db633334da47ca2ae51a9) and ftml render as two separate underline spans, not as one span around ab; a global collapse of underscore runs would have been wrong here, so the narrow regex alternative was chosen. A run of adjacent markers is consumed pairwise, an odd leftover marker stays as literal underscores, and a single underscore inside an identifier is untouched. The render rule was NOT changed: it already emits <span style="text-decoration: underline;"> and </span> byte-for-byte as live and ftml do, and its preserved .before.php is only a precaution.

Corrections and classifications. C1 is the empty-pair deletion in the parse rule and is classified as a fossil-era artifact: the fossil regex let one underscore of an adjacent marker stand as the body of a spurious pair, so ____, a____b, ______x, x________y, ______ ______, ____a____, ______[[/span]] and related runs produced underlined single underscores or literal runs where live discards empty pairs; this is settled first by the ftml corpus pins test/underline/native and the unit test wikidot_discards_complete_empty_underline_pairs_in_runs and then by live probes p02 through p08, all stable. C2 is behaviour-neutral and also a fossil-era artifact: the parse file's copied docblock described bold text surrounded by three single-quotes, and I corrected it to describe underlined text surrounded by double underscores. There is no PHP-version-artifact correction and no harness-matter correction in my files; the harness's trailing \n\n frame padding and process-static token numbering are harness matters left to root. The render file needed no correction. Note for attribution: the color owner's parallel semicolon fix landed in the shared tree at 17:47 between my before and after captures, so the color-style deltas at u10, u11, u15, u17 and u53 in the raw before/after diff are that owner's work, not mine; my Underline change is confined to u22 through u27, u57 and u58.

Battery and probe numbers. Of the 60 battery cases the corrected reference and the dumper agree on 48 after frame normalization, up from 38 before correction; exact byte agreement is 1 in both because the harness frame padding is unchanged, and all six driver stderr sidecars are empty. An ID-independent token comparison shows exactly six cases (u24, u25, u26, u27, u57, u58) losing spurious Underline start/end token pairs, while u22 and u23 lose raw underscore text without gaining tokens, which is the expected shape of the fix; raw token IDs shift for later cases because addToken uses a process-static counter, a harness matter. Of 12 live probes, 11 agree with both the corrected reference and the dumper after frame normalization, including p01, p03 through p09 and p11 and p12; p02 has the whitespace residual dispositioned below. Sixteen battery cases carry non-fatal ftml ParseError records for unpaired or rejected markers, all with literal output matching the reference; none is a driver failure.

Remaining disagreements and dispositions. The crossed marker cases u16 and u17 are Stage-2-only crossings: live and ftml re-nest into well-formed spans (corpus pins crossed-strike-bold-orphan-close and span-tagged-crossing-reopens-nearest), while the reference emits the flat Stage-1 pairing, so this is frame-level surface owned by the Stage 2 repair stack and is not patched. u22 leaves an empty <p></p> in the reference where ftml emits nothing, a Paragraph-rule frame surface. u37 and the block-frame cases u38, u39, u41, u45, u59 differ only in newline and inter-tag whitespace padding owned by the Newline, Paragraph and Tighten frame rules, not by Underline. u50 and u52 are the reference's anchor-rule shape: it leaves [[a href=...]] literal while ftml renders an <a>, a Link-rule and serving-layer scope owned by root's interactions, not this rule. u53 is a colour-plus-underline whitespace-hoist interaction settled by the corpus pin wscolor-lead-hoists and owned by root as a cross-rule interaction, not by Underline. The p02 trailing space (live <p>Empty underline</p>, corrected reference <p>Empty underline </p>) comes from the reference's whitespace trimming running before the empty-pair deletion: a plain trailing space is trimmed (t1) but the space exposed by deleting ____ is not, and ftml collapses x ____ y to x y where the reference keeps two spaces (t3 through t6). This is a general Tighten/whitespace frame surface exposed by any deletion, so it is recorded rather than patched in Underline.php.
