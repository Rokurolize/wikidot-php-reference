Mechanism as corrected. The parse rule pairs ** markers in source text at Stage 1, in the reference's linear token pipeline, with the fossil's ungreedy regex; the body must start and end with a non-whitespace character, so padded openers and closers stay literal, unpaired markers stay literal, and a pair may sit inside a word, in a heading body, or across a single line break while a paragraph break, horizontal rule, list or container boundary stops it. The process() callback emits a start and an end Strong token around the body, and the Xhtml renderer turns those into <strong> and </strong> with an optional css class. The corrected mechanism keeps all of that and adds one case: a bare **** is a legitimate empty bold pair, its four markers are consumed, and no tokens are emitted, so nothing renders while the surrounding line structure is untouched. The render file needed no change.

Corrections and classifications. C1 (fossil-era artifact) changes the parse regex from /\*\*([^\s\n](?:.*[^\s\n])?)\*\*/U to /\*\*([^\s\n](?:.*[^\s\n])?|)\*\*/U and makes process() return an empty string for the empty body. The fossil's requirement for a non-whitespace body character meant the four markers of **** never paired and survived as literal text; live consumes them. Saved-page probe muse-probe-r2in2-strong-p06 (source ****) renders to an empty page and p05 (source ****\nx) renders to <p><br />\nx</p>, both byte-identical to the corrected reference's marker handling; before correction the reference rendered <p>****</p> and <p>****<br />\nx</p>. ftml independently returns Elements::None for an empty bold body, pinned by test/bold/native (EMPTY **** renders as EMPTY) and test/bold/empty-pair-feeds-later-rule (x//**** a//b renders as x// a//b). This is a fossil-era artifact of the original regex, live-settled by p05 and p06, not a reference bug and not a PHP version or harness matter; nearby shapes are deliberately unchanged, since ** **, ***a**, **a***, **a****b** and wor**d**in are all three-way agreements on probes p03, p04 and p08 and in the battery. The exact pre-correction bytes of both owned files were preserved before editing as Strong.php.before.php (sha256 32c1253f0f47b1225946f2e1c9d8716824983bc15d286d263779242cca4c593b) and StrongXhtml.before.php (sha256 120148371b54541ab708b1cffd3e9b12285e56e215f954e75bab6adf6dda2212); the render file was examined but not edited, and its preserved copy documents the baseline. Remaining disagreements and dispositions. The inherited TABLE-stage cell-boundary residual (battery s40, probe p17, and the earlier muse-probe-r2table-tbl-p08) is settled as owned by the table cell parse-scope layer, not by the Strong marker rule: live and ftml both clip the span at the cell edge (p17 renders <td><strong>A</strong></td><td>B</td> while the reference renders <td><strong>A</td><td>B</strong></td>), ftml pins it at test/table/cell-scope-clipped and test/bold/split-close-table where the closer in the second cell is consumed and emits nothing, and a dump of the reference source at the Strong stage shows Table has already replaced the cell boundaries with \xFF token markers that the fossil regex's dot crosses. A Strong-only guard against those markers would instead leave **A literal in cell one and B** literal in cell two, which is not what live renders, so faithful clipping requires cell-scoped pairing at the Table/frame layer; this stage owns only Strong.php, R2-TABLE already classified the shape as not a table-form defect and not an ftml divergence, and I hand it to root as a serving-layer-scope cross-rule interaction rather than patching it or numbering a new ftml finding. Bold markers inside a malformed double-bracket literal block (s46, s48, probes p20 and p22) are a candidate ftml divergence: live and the reference agree on [[<strong>label</strong>|target]] and [[<strong>page</strong>]], while the dumper leaves [[**label**|target]] and [[**page**]] fully literal, with ftml reporting a Bold EndOfInput error on the opener; this is Strong-F1, handed to root for M-style numbering and routing, with ftml untouched and the reference left as the live-correct side. The empty-**** case still shows one canonical battery difference, s18 and probe p06, where the corrected reference retains <p></p> because the Paragraph rule wraps the source before Strong consumes its whole body while live and ftml emit an empty page; that is a frame-level rule-ordering surface owned by Paragraph, left unpatched here, and it is not a live-unsettled Strong shape. Battery s59 is an anchor-block link surface where the reference leaves [[a href="..."]] literal and autolinks the URL inside the attribute while ftml renders a proper anchor, a known reference-side Link-family incompleteness outside this rule and outside my two files. The remaining raw-only residuals (s31 through s38, s45, s53 through s56, s57, s60, and the Colortext semicolon pair s25 and s26) are the already-known frame-level line-break, block-newline, newpage-class and color-style surfaces, not Strong divergences. One question arose and is recorded with its assumption: whether the p05/p06 empty-**** difference belongs to Strong or to the Paragraph frame; I proceeded on the reading that marker consumption is Strong's (corrected in C1) and the retained empty paragraph is frame surface, which is why no further edit was made.
