# R2 Code rule: differential and correction catalog (2026-11-20)

Method: the reference harness (ref-php/harness/batch.php, modes render and tokens) against (a) 15 saved-page live probes on sandbox-for-codex.wikidot.com (muse-probe-r2code-*, all captures valid/stable/saved_source_matches=true, conformance-refphp/code/captures.json), (b) the ftml corpus pins under ftml's test/code/*/wikidot.html (live-adjudicated Wikidot-layout outputs), and (c) ftml's own parse-plus-render with the full preproc stage, dumped by a small Rust binary in this worktree's rust-dump/ (an ftml path dependency plus tokenize, preprocess_for_layout, parse and HtmlRender, modeled on lean-ftml-g14/rust-dump). The battery is 68 cases in conformance-refphp/code/battery.jsonl, generated by make_battery.py; reference outputs are ref-render-final.jsonl and ref-tokens-final.jsonl, ftml outputs ftml-dump2.jsonl, and the probe sources/outputs probe-cases.jsonl, probe-map.json, ref-probe-render.jsonl, ftml-probe-dump.jsonl and captures.json. The ftml checkout is read-only at 014eb6f95. The code closer's nesting discipline is G1.2 work and is not re-proved here.

## Mechanism summary

Parse rule (Text/Wiki/Parse/Default/Code.php, unchanged in R2 apart from the pre-existing PHP 8 signature fix &: the fossil's regex is ^\[\[code(\s[^\]]*)?\]\]((?:(?R)|.)*?)\[\[/code\]\](\s|$) with /msi, so an opener must start a line (^ with /m), may carry one whitespace-led argument tail, and a body recurses through (?R) to allow nested [[code]] openers while the lazy body stops at the first [[/code]] that is followed by whitespace or end of input; process() turns the argument tail into attributes via getAttrs (strict key="value" splitting on =", backslash unescaping, default attr type=''), stores the raw body in the token, and splices "\n\n" plus the token plus the trailing whitespace back into the source. Unterminated blocks, stray [[/code]] closers, mid-line openers and openers whose name has inner spaces ([[ code ]]) never match and stay literal; that disposition agrees with both ftml and the live probes. Arguments accepted at parse are effectively free-form (type, name, unknown keys, bare/unbalanced quotes); the render rule decides what they mean. The R2 parse rule needed no behavioral correction: the token dumps cover all 68 cases and show the expected presence/absence of Code tokens, and 15/15 live probe fragments plus 37/37 in-scope corpus pins agree with the corrected render.

Render rule (Text/Wiki/Render/Xhtml/Code.php, corrected this stage) receives the raw body token and the attributes. Live behavior, adjudicated from the probes and pins, is: trim whole leading blank lines and strip trailing ASCII whitespace while KEEPING first-line indentation; expand tabs to four spaces and blank whitespace-only lines to empty lines (pipeline Prefilter, confirmed in R2-FRAME); convert NBSP to a regular space but preserve ideographic space; escape " as &quot;, & < > as entities, and leave apostrophes literal; wrap the body in <div class="code"> with a newline before the <pre> (the R2-FRAME open item, settled by probe muse-probe-r2code-wrap-basic); emit a bare <div class="code"></div> for empty or all-whitespace bodies; for a recognized type run the highlighter and emit the nested <div class="hl-main"> DOM, otherwise emit <pre><code>...</code></pre>. The fossil render disagreed in five ways, catalogued below.

## Corrections made (all in the render rule; text-wiki/Text/Wiki/Render/Xhtml/Code.php)

C1. Highlighter fatal (fossil-era artifact). The fossil called Text_Highlighter::factory() statically; on this PHP 8 runtime that is a fatal Error ("Non-static method ... cannot be called statically"), so every type="php|css|python|..." case rendered as an error string (7 battery cases, including type case variants, and both live highlight probes). Corrected by instantiating the factory object and invoking factory() on that instance (it returns by reference, so the call binds with &), and treating a PEAR error as "no highlighter". The vendored ~2006 highlighter also emits empty <span class="hl-*"></span> tokens that current live does not; those are stripped with a targeted regex, after which the Python and CSS probe fragments are byte-identical to live and all 12 highlight-* corpus pins (cpp, css, diff, dtd, html, java, javascript, perl, php, python, ruby, xml) match. The wrapper newlines are inserted inside the single vendor hl-main div (not by adding a second wrapper).

C2. Empty-body wrapper (reference bug). The fossil emitted <div class="code"><pre><code></code></pre></div> for empty and whitespace-only bodies; live emits the bare <div class="code"></div> (probe muse-probe-r2code-empty-body and -blank-body, and the EMPTY/ALL-BLANK pins in ftml's code/basic and code/edge-whitespace). Corrected with an explicit empty-body branch after trimming; this also fixes the empty second block in arg-spaced-name.

C3. Body trim (reference bug). The fossil used PHP trim(), which strips leading indentation from the first content line and therefore rendered "\n  x  \n" as x where live renders "  x" (ftml code/edge-whitespace TRAIL-SPACES pin), and "\n\ty\t\n" as y where live renders "    y" (same pin's TABS case, after Prefilter tab expansion). Replaced with wikidotTrimCodeBody(): drop whole leading blank lines, rtrim trailing " \t\n", keep first-line indentation, and replace NBSP with a regular space (live renders NBSP bodies with plain spaces, same pin). Ideographic space is preserved. All nine edge-whitespace sub-shapes now match the pin.

C4. Escaping (PHP version artifact). PHP 8's htmlspecialchars() default (ENT_QUOTES) escapes apostrophes as &#039;, where live and the fossil's PHP 4/5 default (ENT_COMPAT) leave a bare apostrophe; probe muse-probe-r2code-entities-body shows live's "double" 'single' &amp; & < > shape. Corrected by passing ENT_COMPAT explicitly; the body-quotes battery case now matches live.

C5. Wrapper newline (pipeline-frame open item from R2-FRAME, settled here). Probe muse-probe-r2code-wrap-basic renders <div class="code">\n<pre>... on live, with the same newline inside highlighted blocks (<div class="code">\n<div class="hl-main">\n<pre>..., and a newline before the outer closing </div>); the fossil emitted the tight <div class="code"><pre> shape. Corrected for both the plain and highlighted branches. Note that ftml's recorded wikidot.html pins are tight here: that is the post-purifyHtml/Tighten shape, not the Code rule's own output, and the live probe is authoritative for this rule's render target (R2-FRAME's note about output shaping belongs to Stage 2). This one correction settles the open item recorded in conformance-refphp/R2-FRAME.md.

## Classification of the battery disagreements

Before correction, 38 of 68 cases disagreed with ftml after stripping the known frame-level join whitespace. They classify as: C1 highlighter fatal, 9 cases (arg-type-python, arg-type-PYTHON, arg-type-css-inline, arg-type-name, arg-tab-after, arg-multi-space, arg-two-attrs, arg-newline-after, crlf-args — the recognized-type subset); C2 empty-body wrapper, 9 cases (empty, empty-lines, empty-two-lines, ws-body-spaces, ws-body-tabs, ws-body-blank-lines, crlf-empty, spaced-opener's second block, body-code-closer-literal's first block); C3 body trim, 4 cases (body-tab, body-tab-middle, body-leading-space-first, frame-tab-newlines after the corpus-pin comparison found the tab expansion belongs to Prefilter and the trim to the render); C4 escaping, 1 case (body-quotes); C5 wrapper newline, every non-empty block case, a surface correction to live's shape; and the remaining differences are frame/tighten output shaping only (extra \n between adjacent blocks and before following text, the leading space after a suffixed closer, and blockquote indentation), which is class S (surface) and is not a Code-rule divergence. After correction the full rendered output of the corrected reference matches all 15 live probes byte-for-byte modulo that same frame shaping (15/15), and the corrected reference's code fragments match 37/37 in-scope corpus pins; the one out-of-scope pin, code/anchor-copy-inside, carries an empty <a> injected by ftml's anchor-copy/Anchor-rule plumbing rather than by the Code rule, so it is recorded here as a neighbor-rule interaction and left for the Anchor stage.

## Final outcome

The reference Code rule now matches live on every live-adjudicated expectation available: 15/15 live probes (full page output, modulo the Stage 2 frame shaping), 37/37 in-scope ftml corpus pins, and all 68 battery cases when compared at the level the Code rule owns (code fragment plus its immediate wrapper). No ftml divergence candidate survives at the Code rule: an initial appearance of tab/blank-line/NBSP divergence in ftml was traced to this stage's first dumper omitting ftml's preproc stage; after adding preprocess_for_layout to the dumper (ftml-dump2.jsonl) ftml agrees with the corrected reference on every body-content case. The remaining ftml-vs-reference differences on the battery are exactly the output-shaping surface (wrapper newlines on ftml's side vs live's, tight block joins, <br /> vs <br>, blockquote indentation), owned by Tighten/purifyHtml in Tier 2 and already recorded in R2-FRAME.md. The parse rule was not corrected; the render rule is the only changed reference file, with its pre-correction bytes preserved at conformance-refphp/code/Code.render.before.php. There is no open question from this stage that required an assumption: every classification turned on a valid live probe, a corpus pin, or both.
