Method. I compared three sides over one 60-case battery and one 39-case saved-page probe set. The reference side is the shared read-only harness ref-php/harness/batch.php in modes render and tokens, run before and after correction with stderr captured in ref-render-before.err, ref-tokens-before.err, ref-render-after.err and ref-tokens-after.err (all empty). The ftml side is the one shared dumper at conformance-refphp/next/rust-dump/target/release/r2next-rust-dump over the same sources, at the read-only checkout HEAD 97bed049ddeadc54981f6d9577bd78fcb212abd9 recorded in conformance-refphp/next/rust-dump/FTML-HEAD.txt. ## Mechanism as corrected

Parse rule (ref-php/text-wiki/Text/Wiki/Parse/Default/Date.php). The rule now uses three ordered patterns. The first requires a Unix timestamp after the opener, with an optional leading minus sign, plus an optional whitespace-prefixed attribute tail, and emits a Date token with the timestamp and the getAttrs-parsed options. The second matches a blank value that is followed by whitespace or the closer, capturing any attribute tail; the third matches a blank value with a single space and no tail. Both blank patterns emit a Date token with an empty timestamp, which the renderer turns into no output, so live's empty render for blank values with or without attributes is reproduced. A non-numeric value that is not blank (foobar, now, ., ISO and RFC 3339 strings, plus-prefixed numbers, quoted numbers) stays literal, which is what live's Wikidot layout does; the harness Prefilter and the earlier Comment rule still join comments and Iftags seams into the value before this rule runs. No date-context stub is needed: the current date for bare or now/dot forms is not observable in live's Wikidot layout because those forms stay literal, and the anonymous saved-page view makes no locale or timezone computation observable for the shapes the stage owns.

Render rule (ref-php/text-wiki/Text/Wiki/Render/Xhtml/Date.php). For a numeric timestamp the rule now emits the live/ftml Wikidot span `<span class="odate time_<timestamp>[ format_<encoded>]">static UTC date text</span>` instead of the fossil `<span class="odate">timestamp|format</span>`. The timestamp class is canonicalized by dropping leading zeros and clamping integers outside the signed 64-bit range to the nearest bound; the static text is the default `%d %b %Y %H:%M` value rendered in UTC with a proleptic Gregorian calendar even at the extremes, computed with Euclidean division so PHP's 64-bit arithmetic does not overflow. The optional format class is derived from the authored format with every `%g` replaced by `ago`, with unreserved ASCII bytes kept and every other byte percent-encoded in uppercase hex; an empty or absent format produces no format class, and percent-encoded raw-escape markers are carried through. The authored format never changes the visible text in live's Wikidot layout, and an unrelated hover or tz attribute is ignored there, which the corrected renderer also does.

## Corrections made

C1 (fossil-era artifact manifesting as a reference bug). The fossil render rule emitted the raw timestamp and pipe-joined format inside a bare `<span class="odate">`, while live and ftml's Wikidot layout emit the canonical odate/time_/format_ span with static date text; root's cross-rule probe and my probes basic and format-year settle this byte-for-byte, and ftml's test/date/legacy-format-class, out-of-range-timestamp and raw-format-placeholder pins agree. The render helper methods for canonicalization, encoding and proleptic-Gregorian formatting were added and the token() body replaced; this changed 36 of 60 battery render outputs and all Date-bearing live probes. Pre-correction bytes are preserved as Date.render.before.php (SHA-256 d3d2119e242108f73705fdd28fe06569b2c38a0103d56c24e267ad762bdf366a).

C2 (fossil-era artifact manifesting as a reference bug). The fossil value group [0-9]+ rejected negative timestamps, leaving them literal, while live and ftml render negative Unix timestamps as odate spans; probes negative and neg-huge and ftml's out-of-range-timestamp pin settle it. The value group now accepts a leading minus sign, changing four battery token cases and six battery render outputs. Pre-correction parse bytes are preserved as Date.parse.before.php (SHA-256 c7c169d17df74e53b1a077236eb27763b96b3ef5886e3dd9bcff9ec57d8c113f).

C3 (fossil-era artifact manifesting as a reference bug). The fossil rule left blank values literal, while live renders nothing for a blank value with no attributes (probes blank and blank-single) and also for a blank value followed by whitespace and attributes (probes blank-format, blank-two-attrs, blank-unknown-attr and blank-unquoted-attr). The two blank patterns above were added, changing two battery token cases and two battery render outputs. The no-attribute half is also in ftml's out-of-range-timestamp pin; the with-attributes half is finding F1 below, where ftml diverges from live and was not changed.

No PHP-version artifact required a correction, and no harness-matter correction was made to either rule file. One question arose: raw-escape markers arriving in the format attribute carry the fossil harness's global token IDs, whereas live and ftml use document-local %FF<n>%FF numbers; I proceeded on the interim assumption that this is a frame-level harness residual owned by root rather than a Date-rule divergence, and root confirmed that decision, asking that it be disclosed in R2-NEXT.md rather than normalized in the shared harness.

## Battery and probe numbers

The battery is 60 cases. Before correction it split into 22 agreeing with ftml under frame normalization, 3 surface-only differences and 35 substantive differences; after correction it is 55, 3 and 2. Corrections changed 36 render outputs and, semantically, 6 token outputs; the raw token-mode diff names 54 cases because the new blank tokens shift the harness's global token numbering for every later case. No battery case errored on either side and all stderr sidecars are empty. The two remaining substantive battery differences are d21-blank-with-format (F1) and d56-date-then-math (serving-layer Math stub), and the three surface differences are d26-leading-tab, d40-raw-format and d60-date-in-code. Of the 39 live probes, 31 agree on the canonicalized full output across all three sides, 5 agree between the corrected reference and live (the four F1 blank-with-attributes probes plus the in-code frame difference), 3 agree between ftml and live (the three raw-placeholder numbering probes), and none disagree all around. On the Date-owned span itself, 38 of 39 probes agree across all three sides; the sole exception is probe raw-format and its two companion raw probes, where the fossil marker numbering is the disclosed residual.

## Remaining disagreements, dispositions, and candidate findings

Class S (frame-level surface owned by later rules or shared framing, not Date divergences): the reference's empty paragraph wrapper for blank values where live and ftml emit no HTML at all; the fossil tab-expansion and ftml space-normalization of [[    date ...]]; the Iframe rule's trailing space before > and the <br /> versus <br> spelling in d55 and probe after-iframe; the Code rule's surrounding newline and paragraph framing in d60 and probe in-code; and the harness token-ID renumbering visible only in token mode. These were not corrected, and the neighboring-rule cases are itemized in x-notes.md for root's integration.

Serving-layer scope: d56-date-then-math shows this harness's stubbed LaTeX-failure error block against ftml's rendered equation, which is the Math rule's serving-layer path, not a Date matter; the corrected Date span is identical on both sides. Bare, now, dot, plus-prefixed, quoted and ISO/RFC 3339 values are literal on all three sides, so no current-date, locale or timezone evaluation is needed for any shape this section owns.

F1 (candidate ftml divergence, route to coordinator). Live renders nothing for a blank date value followed by attributes, while ftml's Wikidot layout returns the call as a literal paragraph. The legacy branch in src/parsing/rule/impls/block/blocks/date.rs returns Elements::None only when arguments.is_empty(), so [[date  format="%Y"]], [[date  format="%Y" tz="+8"]], [[date  foo="bar"]] and [[date  format=%Y]] stay literal there; the four correspondingly named live probes under muse-probe-r2next-date- are valid and render an empty page body, and the corrected reference now matches live. Battery case d21-blank-with-format shows the same split. The fossil was wrong here, so the reference was corrected rather than ftml being called wrong on an unsettled shape.

Harness/frame residual (root-owned, disclosed, not an ftml finding): probes raw-format, raw-two-dates and raw-preceded show live and ftml using document-local raw-escape numbers %FF1%FF and %FF2%FF, while the shared harness's Raw rule places fossil global token IDs in the format marker, so the corrected reference emits %FF348%FF and similarly large numbers. The Date renderer already percent-encodes that marker faithfully; changing the shared Raw rule would disturb previously completed stages and the smoke baseline, so root decided to accept and disclose this residual in R2-NEXT.md, and no shared file was edited. This is the recorded interim assumption under Corrections made as well.
