# R2-next Iftags rule: differential, correction, and section (2026-11-20)

Method. I compared three sides over one 80-case battery and one 25-case live probe set. The reference side is the shared read-only harness ref-php/harness/batch.php in modes render and tokens, with per-case "tags" arrays injected as a tagged RefPage by the root-owned stub; outputs are ref-render-before.jsonl, ref-tokens-before.jsonl, ref-render-after.jsonl, ref-tokens-after.jsonl and the four ref-probe-* counterparts, with empty stderr on every reference run. The ftml side is the one shared dumper conformance-refphp/next/rust-dump/target/release/r2next-rust-dump over the same battery and probe sources at the read-only checkout HEAD 97bed049ddeadc54981f6d9577bd78fcb212abd9 recorded in its FTML-HEAD.txt; outputs are ftml-dump.jsonl and ftml-probe-dump.jsonl with empty stderr. The live side is 25 saved anonymous page views on sandbox-for-codex.wikidot.com under prefix muse-probe-r2next-iftags-, cached in probe-cases.jsonl, probe-map.json, captures.json, make_tagged_probes.py, resilient_capture.py, probe-create-*.log and probe-capture.log; all 25 are stable=true and saved_source_matches=true. The bundled wikidot-probe CLI has create/capture/norm but no page-settings or tag subcommand, so a question arose about observing both tag polarities live; the assumption proceeded on was that the CLI is the measurement loop and tag setting is a wikidot.py page-settings operation through the same scripts/wikidot-python wrapper. I created the 9 untagged pages with wikidot-probe create and the 16 tagged pages with site.page.publish(tags=[...]) from make_tagged_probes.py, then captured all 25 with the probe's own helpers in resilient_capture.py after the bundled capture subcommand aborted twice on transient Wikidot 503 and connect-timeout responses. Both polarities were therefore observed live, not silently narrowed. Evidence order when sides disagreed was ftml corpus pins, then frozen captures, then live probes, and live behavior won every disagreement. The battery is reproducible with make_battery.py and the three-way view with compare.py; its full output is compare-report.txt.

## Mechanism as corrected

Parse rule (ref-php/text-wiki/Text/Wiki/Parse/Default/Iftags.php). The rule still matches [[iftags spec]]body[[/iftags]] with the recursive /msi regex, splits the spec on runs of commas and spaces, classifies each token as a required +tag, a forbidden -tag or a bare any-tag, and returns the body only when every required tag is present, no forbidden tag is present and at least one bare tag is present when bare tags exist. An empty or whitespace-only spec yields one empty bare token, so on a tagged page the gate fails and the body is dropped, which live confirms on p-empty-spec-tagged. Untagged pages take the fossil's DB fallback, find no page and drop the body, which live confirms on p-false-gate-lines. The one behavior correction is that tag comparison is now case-insensitive: a local $hasTag closure uses strcasecmp on each page tag, matching ftml's check_ignore_ascii_case and the live corpus. The fossil's in_array comparison was case-sensitive, so [[iftags +ALPHA]] against tag alpha, [[iftags ALPHA]] against tag alpha and [[iftags -BETA]] against tag beta all diverged; live p-case-plus-spec, p-case-bare and p-case-minus settle all three in favor of the corrected form. Comma-separated conditions, the dangling bare minus, newline-in-spec and comment seams were deliberately left on the fossil side because live agrees with the fossil there, not with ftml. The line-start/line-end/blockquote and paragraph-seam behavior in the fossil is a flat source replacement, so the seam shaping that ftml performs in literal_span_gate and the kept-body paths is produced downstream by the frame rules and is not owned here.

Render rule (ref-php/text-wiki/Text/Wiki/Render/Xhtml/Iftags.php). The rule still emits the empty string for an Iftags token: the parse rule injects the kept body back into the source, so later rules render it and the Iftags token itself contributes no markup. Live probes with a kept body (p-basic-plus-hit, p-case-plus-spec, p-comma-plus-both) and ftml's HtmlRender agree on this shape, so no render correction was made. The fossil class docblock calls this an Iframe element, a copy-paste artifact with no behavior effect, left untouched.

## Corrections made

C1 (fossil-era artifact, manifesting as a reference bug, behavior-changing). Replaced the three case-sensitive in_array($t, $tags) checks with a strcasecmp-based $hasTag closure evaluated over the page tags. Live probes p-case-plus-spec, p-case-bare and p-case-minus and the ftml pin test/iftags/tag-spec-case/wikidot.html establish ASCII-case-insensitive tag comparison; the fossil's case-sensitive comparison is a Wikidot-era artifact that no longer matches live. The closure replaced the dead statement $tag0 = $tags0[0]; that sat before $tags0 was assigned; that statement was the suspicious line flagged in the brief, and testing showed it was a harmless fossil-era artifact that only produced an undefined-variable warning under non-suppressed error settings and never affected output, so its removal is classified with C1 rather than as a separate behavior correction. The correction changed 6 battery render outputs (opener-and-closer-upper, case-plus-spec-upper, case-plus-tag-upper, case-bare, case-minus-spec, case-minus-tag); the seventh changed output, body-iframe, is a one-space trailing-attribute wobble from the Iframe render rule that reruns reproduce as stable and that is not produced by this rule. Pre-correction bytes are preserved in Iftags.parse.before.php (SHA-256 1c2a34c9c71c80c191212224a6d42c39e977bb3657becef06c9ce66a030463cc) and Iftags.render.before.php (SHA-256 fa76372e46f5e37a76e78b9eb91fad32d975be25cdca36a44c8bb4ac22adcb26); the render file was preserved as a deliverable but not edited, and no PHP-version artifact or harness matter required a correction.

## Battery and probe numbers

The battery is 80 cases. Before correction, 21 of 80 matched ftml strictly and 65 matched after canonicalizing later-rule frame surface; after correction the numbers are 23 strict and 71 canonical, with 6 behavior-changing outputs from C1. The 9 canonical disagreements after correction split into 6 ftml-side findings F1 through F4 and 3 serving-layer or frame-surface cases (body-math, math-contains-false-iftags, body-span-seam). No battery case errored on either side. Of the 25 live probes, 17 agree under canonicalization on all three sides, 6 agree on reference and live against ftml (exactly the F1 through F4 shapes), 1 agrees on ftml and live against the reference only because the Math render stub takes its fossil error-block path (p-math-contains-false), and 1 disagrees on all three because of Div wrapper surface (p-adjacent-div). Gate polarity, that is whether KEEP survives, agrees on every probe where all three sides render the source; the F1 through F4 probes are the six where live and the corrected reference keep or drop the body while ftml takes the opposite polarity.

## Remaining disagreements, dispositions, and candidate findings

Class S (frame-level surface owned by later rules, not Iftags divergences): the fossil's trailing \n\n and inter-block spaces versus ftml's tight joins (line-start-body, body-next-line, blockquote-opener, body-paragraph-breaks, false-gate-newlines, true-gate-newlines, p-false-gate-lines); <br /> versus <br>; the one-space Iframe render wobble on body-iframe; the empty style attribute on span on body-span-seam; the <div > wrapper and newlines on p-adjacent-div and after-block-div; and the double-space versus single-space residue when a complete comment is stripped from a spec that falls to literal (p-spec-comment-tagged and spec-comment-complete). These are join, whitespace and attribute shaping by the Paragraph, Iframe, Span and Div rules and were not corrected here.

Serving-layer scope: body-date shows the fossil <span class="odate">0</span> against ftml's formatted odate span, body-math and p-math-contains-false show the Math render stub's error block against ftml's and live's rendered equation, and the kept Iframe body shows attribute shaping differences. The stage owns matching, tokenizing, argument handling and the observable gate shape, all of which agree; the rendered equation, current date and iframe widget are out of scope exactly as in R2-MODULE.md.

F1 (candidate ftml divergence, route to coordinator). ftml's ElementCondition::parse splits the spec only on spaces, while live and the corrected reference also split on commas. Live p-comma-plus-both, p-comma-bare and p-comma-space-mixed all keep the body, and p-comma-plus-one drops it, exactly as the fossil's preg_split(';[, ]+;', ...) does; ftml drops the first, second and fourth and leaves battery comma-plus-both, comma-bare and comma-space-mixed as literal or empty. Evidence is in captures.json and ftml-probe-dump.jsonl; no reference change was made.

F2 (candidate ftml divergence, route to coordinator). A dangling minus condition is an empty prohibited tag. The fossil leaves it unsatisfied so the body survives on a tagged page, and live p-bare-minus keeps the body; ftml's ElementCondition::check returns false for any empty condition value and drops it (battery bare-minus-only). The dangling plus case agrees on both sides (p-bare-plus drops). No reference change was made.

F3 (candidate ftml divergence, route to coordinator). A newline inside the spec is a failed gate live: p-newline-in-spec renders an empty page and the battery newline-in-spec case drops the whole span in the reference, while ftml falls back to a literal paragraph containing [[iftags +alpha<br> +beta]]KEEP[[/iftags]] with five parse errors. No reference change was made.

F4 (candidate ftml divergence, route to coordinator). When a complete comment in the spec consumes the head's first closing bracket, live drops the whole span (p-spec-comment-straddle, battery spec-comment-straddle), matching the reference, while ftml falls back to a literal paragraph containing [[iftags +alpha ]KEEP[[/iftags]] with four parse errors. The adjacent shape where the bracket stays outside the comment (p-spec-comment-tagged and the ftml pin spec-comment-complete-literal) does fall to literal on all three sides, so the finding is specific to the fused head close. No reference change was made.

No ftml file, shared harness file, or git state outside this worktree's deliverables was changed, and no git identity variables or -c user.* overrides were used.
