# R2-next Iframe rule: differential, correction, and section (2026-11-20)

Method. I compared three sides over one 83-case battery and one 16-case live probe set. The reference side is the shared read-only harness ref-php/harness/batch.php in modes render and tokens (outputs ref-render-before.jsonl / ref-render-after.jsonl, ref-tokens-before.jsonl / ref-tokens-after.jsonl, ref-probe-render-before.jsonl / ref-probe-render-after.jsonl, ref-probe-tokens-before.jsonl / ref-probe-tokens-after.jsonl, with empty stderr sidecars throughout). The ftml side is the shared dumper at conformance-refphp/next/rust-dump/target/release/r2next-rust-dump, run over the same battery and probe sources at the read-only checkout HEAD 97bed049ddeadc54981f6d9577bd78fcb212abd9 recorded in conformance-refphp/next/rust-dump/FTML-HEAD.txt (ftml-dump.jsonl and ftml-probe-dump.jsonl). The live side is 16 saved anonymous page views on sandbox-for-codex.wikidot.com under prefix muse-probe-r2next-iframe-, created and captured with the bundled wikidot-probe CLI through the wikidot-python wrapper (probe-cases.jsonl, probe-map.json, captures.json, probe-create.log, probe-capture.log); all 16 are valid, stable and source-matching, with LF-only sources and trailing newlines stripped. Evidence order when sides disagreed was ftml corpus pins, then frozen captures, then live probes; live behavior won every disagreement, no ftml file was edited, and no git commits or git identity variables were used. The battery and probe sources are reproducible with make_battery.py and the three-way view with compare.py in this directory; cross-rule cases left for root are in x-notes.md.

## Mechanism as corrected

Parse rule (ref-php/text-wiki/Text/Wiki/Parse/Default/Iframe.php). The rule still builds its URL regex from the parse-conf schemes http://, https://, ftp://, gopher://, news://, mailto: and mms:// (case-insensitive at match time, confirmed live by p-schemes and the upper/mixed-case battery cases), still matches a bare head or a head with raw attributes, still uses getAttrs for align, frameborder, height, scrolling, width, class and style, and still emits src first in the token. The single correction is that process() now strips carriage returns and line feeds from the captured URL before putting it in src. The fossil regex's greedy tail absorbs a following closer-shaped span into the URL but keeps the newlines it crossed; live and ftml drop them, so `[[iframe http://e.com/]]\n[[/div]]` yields src `http://e.com/]][[/div` on all three settled sides. The URL character class itself was deliberately left unchanged: live confirms the fossil's distinction that a single quote before a later slash breaks the match while a single quote only in the final segment does not (p-sq-mid, p-sq-final), and live also confirms that a greedy tail ending in a bare `[[URL]]` is absorbed by the reference rather than stopped at the first `]]` (p-freelink-tail, matching root's captures-x.json), so neither shape warranted a parse change.

Render rule (ref-php/text-wiki/Text/Wiki/Render/Xhtml/Iframe.php). The rule still emits `<iframe k="..." ...></iframe>` with attributes in insertion order, escaped with htmlspecialchars; fixes are scoped to three details of that emission. The per-attribute loop no longer appends a space after every attribute, so the tag closes immediately after the last quoted value as live and ftml do. The src value alone is passed through a bytewise percent-encoder that turns every non-ASCII UTF-8 byte into uppercase %XX before escaping, matching ftml's percent_encode_non_ascii and live's pinned URL encoding. htmlspecialchars is now called with explicit ENT_COMPAT | ENT_HTML401 and UTF-8, restoring the pre-8.1 default so a single quote in src stays a literal `'` as live emits it rather than becoming `&#039;`. Attribute values unknown to the rule are never emitted because process() only copies the seven recognized keys, and duplicate quoted keys resolve last-wins through getAttrs; both behaviors are live-confirmed and unchanged. Remote frame loading is serving-layer scope and out of scope here; matching, tokenizing, attributes and the observable display shape are in scope.

## Corrections made

C1 (render rule, fossil-era artifact manifesting as a reference bug). The fossil loop appended a trailing space to each attribute and then emitted `></iframe>`, producing `<iframe ... style="" ></iframe>`. Live captures and the ftml wikidot pins use `<iframe ... style=""></iframe>`, and root's cross-rule probe x-iframe-url-sameline settles the style=background:url(...) shape the same way. Rebuilding the tag with implode removed the extra space and changed 69 battery render outputs, namely every case that renders an iframe.

C2 (render rule, fossil-era artifact manifesting as a reference bug). Non-ASCII URL bytes were emitted raw by the fossil render, while the frozen pins test/iframe/iframe-url-encoding and -query-fragment and probe p-utf8 show percent-encoded src values (`%E6%97%A5...`, `%C3%A9`, `%C3%BF`). A small bytewise encoder in the render rule now matches ftml exactly; it changes 3 battery outputs (if-url-utf8-path, if-url-utf8-query, if-url-delim-u00ff) and the p-utf8 probe.

C3 (parse rule, fossil-era artifact manifesting as a reference bug). The greedy tail kept literal newlines in captured src where live drops them, settled by pins test/iframe/iframe-greedy-closer, -text-closer, -args-newline-closer and by probe p-tail-closer. Stripping CR and LF in process() changes the src token in 10 battery cases (if-tail-newline-closer, -two-closers, -text-closer, -blank-span, -surviving-close, -invalidates-div, if-adj-greedy-iftags-failing, -kept, -math-after, if-adj-freelink-tail) and the p-tail-closer probe; the rendered effect on the first four plus the iftags cases is visible beyond C1.

C4 (render rule, PHP version artifact). PHP 8.1 changed htmlspecialchars' default flags from ENT_COMPAT to ENT_QUOTES, so the fossil's unqualified call began emitting `&#039;` for a single quote in src; live probe p-sq-final shows the raw quote `<iframe src="http://example.com/a'b" ...>`. Passing ENT_COMPAT | ENT_HTML401 explicitly restores the behavior the fossil was written against and changes 1 battery output (if-url-singlequote-final) plus the p-sq-final probe. No correction was classified as harness matter: the shared Prefilter and dumper preprocessing pad and normalize frame whitespace identically on both sides, which is a frame-level matter rather than an Iframe divergence. Pre-correction bytes are preserved as Iframe.parse.before.php (SHA-256 6c23bd90bbeb374825e106f3c56ce25dc48799e8fab68e74919762ae755a1ef3) and Iframe.render.before.php (SHA-256 caea706cd18afcfd2388e37a467cc906b58f4527adca2ed97cb1b81a01cca9fb), both byte-identical to the original rule files before editing.

## Battery and probe numbers

The battery has 83 cases covering all seven schemes and upper/mixed-case variants, refused schemes, slash/quote/space/tab/backslash/delimiter/percent/UTF-8/query/fragment URL edges, all seven attributes plus unknown, duplicate, quoted, spaced-equals, empty and single-quoted values, malformed and unterminated openers, mid-line and line-start positions, the greedy-tail boundary, and adjacency with Iftags, Comment, Code, Date, Math, Div, Anchor, Span and Url in pipeline order. The corrections changed 69 of 83 render outputs. After correction no output is raw-equal to the dumper because the reference retains its frame-level trailing blank lines, but 73 of 83 agree once frame-level surface is normalized, and 10 remain substantive. No battery case errored on either side; the dumper reports parser errors on 17 cases that stay literal, which is expected and not a render failure. The 16 live probes split, after the same surface canonicalization, as 15 where the corrected reference agrees with live (the only mismatch is p-git, a Url-rule edge), 13 where ftml agrees with live, 12 where all three agree, and 12 where the reference agrees with ftml. Four decisive probes are raw byte-identical between the corrected reference and live after stripping the frame-level trailing newlines: p-basic, p-utf8, p-tail-closer and p-sq-final.

## Remaining disagreements, dispositions, and candidate findings

Class S (frame-level surface owned by later rules, not Iframe divergences): the reference's trailing `\n\n` after each paragraph and around block output; `<br />` versus `<br>` (current saved-page live captures emit `<br />`, while the older frozen wikidot pins show `<br>`, so this is a later-rule and live-version surface rather than an Iframe error); `<div >` and `<span  style="">` spacing; code-block padding and tab expansion in literal tail text. These were not corrected. Serving-layer scope: a framed remote page is never fetched or evaluated by the reference or the dumper, and probes use inert example.com URLs; only the emitted display shape is compared.

F1 (candidate ftml divergence, route to coordinator). ftml escapes a single quote in an iframe src as `&#39;`, while live probe p-sq-final and the corrected reference both emit the raw `'` inside the double-quoted src attribute. Evidence: p-sq-final, battery if-url-singlequote-final, ftml test/iframe pins' legacy renderer. F2 (candidate ftml divergence, route to coordinator). ftml accepts a single quote in a non-final URL segment as a valid iframe, while live probes p-sq-mid and battery if-url-singlequote-mid / -two leave the whole opener literal with the URL rule linkifying its prefix; the fossil character class is live-correct here and was not changed. F3 (candidate ftml divergence, already routed by root). A greedy tail ending in a bare `[[URL]]` is absorbed into src by live and the reference, while the dumper stops at the first `]]` and renders a link; evidence p-freelink-tail, battery if-adj-freelink-tail and root's x-iframe-then-url / x-iframe-url-sameline captures. No ftml file was edited for any finding.

Cross-rule items left for root are in x-notes.md: the refused-scheme linkification gap (p-git / if-scheme-git, Url's own stage), the anchor foster-parenting surface (if-adj-anchor-around), and the Iftags and Comment seams that already agree. No serving-layer or frame-level disagreement was turned into an Iframe correction.

Two questions arose and were recorded rather than blocking. First, the token delimiter is the raw byte \xFF, which cannot be carried through UTF-8 JSONL input; the battery's if-url-delim-u00ff uses U+00FF as a proxy, and I proceeded on the assumption that the existing exclusion of the delimiter byte in the regex remains correct and needs no probe. Second, the `<br />` versus `<br>` difference was left alone because current live emits `<br />`, on the assumption that it is a later-rule frame surface whose ownership is not this rule's; if root wants it reclassified, the probe captures are in captures.json.
