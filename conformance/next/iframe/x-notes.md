# R2-next Iframe: cross-rule notes for root (not Iframe-rule corrections)

Url-family edges. The reference harness's Url rule does not linkify a refused scheme inside literal iframe text: probe muse-probe-r2next-iframe-p-git (`[[iframe git://example.com/a]]`) renders live and ftml as `<p>[[iframe <a href="git://example.com/a">git://example.com/a</a>]]</p>` while the reference leaves the URL bare. Battery case if-scheme-git shows the same. This is Url's own stage or its harness configuration, not Iframe; no Iframe file was changed for it. Battery cases if-scheme-javascript, if-scheme-data and if-url-doublequote are the adjacent Url-family shapes where all three sides happen to agree.

Greedy tail ending in a bare URL. Probe p-freelink-tail and battery case if-adj-freelink-tail use `[[iframe https://example.com/a]]\n[[https://example.com/b]]`. Live and the reference agree that the whole bare URL is absorbed into src as `https://example.com/a]][[https://example.com/b`, while the dumper stops at the first `]]` and renders the URL as a link. Root already settled this from captures-x.json and routes it as a candidate ftml divergence; I made no parse-regex change on this account, and my own live capture independently confirms root's result.

Single-quote URL family. Probes p-sq-mid and p-sq-final and battery cases if-url-singlequote-mid, if-url-singlequote-two and if-url-singlequote-final show live agreeing with the fossil's URL character class on both sides: a single quote before a later slash leaves the whole opener literal, while a single quote only in the final URL segment renders an iframe with a raw `'` in src. ftml accepts the mid-segment forms as iframes and emits `&#39;` for the final-segment form, so both are candidate ftml divergences for root's triage. The fossil character class and the render correction were deliberately left alone here; the raw-quote shape is what motivated the ENT_COMPAT render fix, which is a PHP-version artifact correction, not a Url edit.

Anchor adjacency. Battery case if-adj-anchor-around (`[[a href="/y"]][[iframe ...]][[/a]]`) leaves the anchor unpaired in the reference while the ftml pin test/iframe/anchor-iframe-foster/wikidot.html and the dumper show anchor foster-parenting around the iframe. That surface belongs to the Anchor rule and later frame shaping; no Iframe change was made. The Iftags and Comment seam cases (if-adj-iftags-seam-name, if-adj-iftags-seam-url, if-adj-comment-in-url, p-iftags-seam, p-comment-in-url) agree on all three sides and need no routing. Root's cross-rule probe x-comment-inside-iframe-attr leaves width="" live; the fossil's getAttrs plus the earlier Comment pass produce the same empty width, so that case is settled too.
