# R2 Table and Tableadv stage: differential and correction catalog (2026-11-20)

Method. This stage runs as a team of two rule owners plus a root coordinator, one owner for each of the thirty-fifth and thirty-sixth pipeline rules in this batch: Table and Tableadv, the two table forms. The loop is building a PHP reference implementation that reproduces live Wikidot behavior, the fossil Text_Wiki snapshot corrected rule by rule against live evidence: the fossil is a skeleton and never evidence, live Wikidot behavior is definitionally correct, and the evidence order is ftml corpus pins first, then frozen captures, then live sandbox probes, with fetching from live pre-approved and cached once. Earlier stages are published as the catalogs conformance-refphp/R2-INCLUDE.md, R2-FRAME.md, R2-CODE.md, R2-FORM-RAW.md, R2-MODULE.md, R2-NEXT.md, R2-LINK.md, R2-NOTES.md, R2-BLOCK.md, R2-CONTAIN.md and R2-LIST.md, and this catalog imitates their shape. Each owner reads its rule's parse and render files and the corresponding ftml behavior, builds an at-least-40-case whole-document battery covering its matching space, runs the reference before and after correction through the shared harness (ref-php/harness/batch.php, modes render and tokens) and the stage's shared ftml dumper (conformance-refphp/table/rust-dump/, preprocess_for_layout, tokenize, parse, HtmlRender over JSONL {"id","source", optional "tags"} at the read-only ftml checkout HEAD recorded beside it), probes live under its disjoint prefix (muse-probe-r2table-tbl- and muse-probe-r2table-adv-), corrects only its own two rule files while preserving the pre-correction bytes as <rule>/<File>.before.php, classifies every correction and every remaining disagreement, and writes its SECTION.md ending in COMPLETE or BLOCKED:. The root owns the shared harness and dumper, the cross-rule interactions (probed under muse-probe-r2table-x-), the catalog, and the final nine-case smoke run; the root does not do an owner's rule work except where an owner leaves it unfinished and the catalog says so. The root checked that the harness carries the page-mode configuration that sets the table css class to wiki-content-table through resetWiki (the setRenderConf('Xhtml','table','css_table','wiki-content-table') line in ref-php/harness/wiki-config.php), and records here that this class is part of the observable display shape; no harness change was needed. Prose is written in flowing paragraphs on single lines, never hard-wrapped.

## Part 2: Tableadv (conformance-refphp/table/tableadv/SECTION.md, COMPLETE)

Tableadv is confirmed against live with eight corrections in both owned files — five classified as fossil-era artifacts, two as reference bugs and one as a reference bug layered on a fossil-era artifact — with the exact pre-correction bytes preserved as conformance-refphp/table/tableadv/Tableadv.php.before.php and TableadvXhtml.before.php. The corrected grammar requires a `[[table]]` opener and `[[/table]]` closer whose body is only `[[row]]` blocks and each row body only `[[cell]]` or `[[hcell]]` blocks, with nested tables tokenized first so an inner row or cell never leaks into the outer split; any non-row or non-cell text, an unmatched opener or closer, or a row or cell alias leaves the source literal. Header-ness comes from the closer name, so `[[cell]]x[[/hcell]]` yields a `<th>` and `[[hcell]]x[[/cell]]` a `<td>`.
