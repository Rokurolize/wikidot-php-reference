# CORRECTION-REFCORR59: empty-Raw scope edges, generated empty paragraphs, close-boundary bytes, and literal U+FFFD recovery

## Adjudication

REFCORR59 re-derived the REFCORR57 remainder against the snapshot-81 corpus and used two rounds of byte-verified grouped sandbox probes on `sandbox-for-codex`. The first round covered centered-close continuation, Size/empty-Raw interaction, crossline empty-Raw whitespace, tabview empty fragments, heading/TOC trailing whitespace, and corrupted sentinel text. The second round refined the centered-close discriminator, isolated tab-opener trailing whitespace, and measured the private-use/list token-collision interaction. Every probe capture used here is stable across repeated anonymous reads and its saved source is byte-identical to the intended source.

The probes separated five warranted mechanisms:

- A paired crossline empty Raw atom (`@@\n@@`) is layout residue in a Size scope just like a single empty `@@@@` atom when it is the only remaining content before a horizontal rule or quote boundary. The Size scope closes at that boundary instead of reopening across it. When such an atom has appeared after visible content, the scope also closes at the next following horizontal rule or quote boundary after intervening inline content. Single-atom, paired-atom, image, and multiple-atom matrix cells all match live after the correction.
- Divprefilter's generated-space sentinel must survive long enough for Size to recognize a generated crossline empty-Raw line. Divprefilter still protects the sentinel from its own whitespace deletion, but the restoration now happens when Size parsing finishes, before downstream newline and paragraph rules own the line as a generated space.
- A paragraph shell containing no rendered content is absent in live output. This removes empty `<p></p>` shells left by invisible empty-Raw layout inside tabview content; it does not remove `<p><br /></p>` created by trailing whitespace after a `[[tab ...]]` opener. The round-two tab matrix shows that this break paragraph belongs to the tab opener's trailing whitespace, not to heading trailing whitespace and not to empty Raw atoms themselves.
- Live's served block serialization owns a newline byte after a closing `</div>` when bare inline text follows. This is a frame byte, not authored text. The refined Wanderers reduction, including the original emphasis-bearing tail, matches live canonically after the correction; the simpler first-round matrix already matched and remains a control.
- Literal U+FFFD recovery must distinguish two collision shapes. A literal delimiter directly before adjacent real placeholders leaks the document-local indexes of the swallowed adjacent placeholder run while later list structure survives; a literal followed by digits leading into a real placeholder instead enters the fossil pair-scan cascade in which malformed later keys remain visible. The first shape is the private-use/list matrix; the second is the corrupted sentinel matrix. Treating either shape with the other's rule either destroys valid list structure or loses the sentinel cascade. The hybrid recovery reproduces both grouped matrices, with the sentinel matrix and the private-use/list matrix strict-byte-equal to live.

Heading trailing whitespace and crossline empty-Raw whitespace required no further parser correction beyond the above frame repairs. Their residual strict-byte differences are the reference's established fossil block/script newline shell; after the established canonical comparison both matrices are live-faithful. The tabview script skeleton itself remains the known fossil/live shell difference and is not treated as a parser correction target.

## Implementation

`Raw.php` and `Heading.php` carry the empty-Raw and heading-whitespace corrections begun in this lane. `Divprefilter.php` and `Size.php` implement the generated-sentinel lifetime and Size-scope boundary ownership. `Wiki.php` implements empty-paragraph removal, close-boundary newline serialization, and origin-aware literal-U+FFFD recovery. The pre-correction copies are stored beside this record as `*.before-refcorr59`.

## Pins

`cases.jsonl` contains nine grouped matrices: six first-round matrices and three second-round discriminators. `captures.json` records the stable source-identical live captures, `expected.json` the pinned reference bytes, and `verify_refcorr59.py` checks both expected-render bytes and live-canonical fidelity. At the final local run all 9/9 expected-render byte pins and 9/9 live-canonical fidelity pins passed. The corrupted sentinel matrix and private-use/list token-index matrix are strict-byte-equal to live; the other matrices are canonical-live-faithful, with residual strict bytes confined to the established fossil serialization shell.
