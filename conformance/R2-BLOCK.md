# R2 Blockquote, Heading and Toc stage: differential and correction catalog (2026-11-20)

Method. This stage runs as a team of three rule owners plus a root coordinator, one owner for each of the twenty-fifth-through-twenty-seventh pipeline rules in this batch: Blockquote, Heading and Toc. The family is defined by shared document state: headings are collected across the whole document into the table of contents that a Toc reads at its own position, heading anchors depend on the text and repetition of every heading, and a blockquote can contain headings, lists and footnote blocks that the later rules shape, so per-rule differentials only mean anything inside whole documents and at their seams. The shared reference harness (ref-php/harness/batch.php in expand, render and tokens modes, transform.php for the smoke run) is read-only for rule owners; harness problems go to root. Before any teammate starts, root builds one shared ftml dumper at conformance-refphp/block/rust-dump/ in the Form/Raw stage's style (preprocess_for_layout, tokenize, parse, HtmlRender over JSONL {"id","source", optional "tags"}) and records the read-only ftml checkout HEAD in that directory; every cargo invocation goes through heavy-build.sh with HEAVY_BUILD_NO_SPLIT=1 as a polled background job. Live probes use the wikidot-probe CLI through its scripts/wikidot-python wrapper against sandbox-for-codex, with prefixes partitioned per rule (muse-probe-r2block-bq-, muse-probe-r2block-head-, muse-probe-r2block-toc-) and root's cross-rule prefix muse-probe-r2block-x-; fetch once, cache, reuse. Corrections land only in a rule's own two files under ref-php/text-wiki/Text/Wiki/Parse/Default/ and Render/Xhtml/, with pre-correction bytes preserved as conformance-refphp/block/<rule>/<File>.before.php. The fossil Text_Wiki snapshot under ref-php/fossil/ is a skeleton and never behavior evidence; live Wikidot behavior wins every disagreement, the evidence order is ftml corpus pins then frozen captures then live sandbox probes, and fetching from live is pre-approved. Serving-layer scope is as in earlier stages: what a rule computes from page or site state is evaluated only as far as live's anonymous saved-page view makes it observable and deterministic, and the stage owns matching, tokenizing, level and numbering computation and the observable display shape. Two standing facts from this loop's earlier work bear directly on this stage and are not relitigated: the indented blockquote-marker question is settled (the marker anchors at line start, a space-prefixed marker line is ordinary text, and the tight quoted-include shapes from the F-G14-1 relay are pinned), and the blockquote rule here is the native [[blockquote]] block plus the >-prefixed quote lines the preproc and paragraph layers shape, so each section is precise about which layer owns every shape it tests. If a question arises mid-work, the rule owner or root records the question and the assumption proceeded on in the relevant section and keeps going.

## Part 2: Heading (conformance-refphp/block/heading/SECTION.md, COMPLETE)

The corrected regex /^(\+{1,6})(\*?)[ \t]+(.*)/m recognizes levels one through six, the Wikidot no-toc * suffix and the whole horizontal-whitespace run after the prefix; a normal heading emits a start token with {type, level, text, id} and increments the per-document parser counter, while a * heading emits a distinct start-notoc token with a null id and does not increment it. The renderer now emits the id attribute only when present, so a no-toc heading renders a bare <hN><span>, and the distinct token type makes Toc's pre-existing exact type == 'start' filter exclude no-toc headings without any edit to Toc.php; a p09 token dump verifies that a document with an interleaved +* heading produces exactly two Toc items. C1 is the no-toc form (live-settled by muse-probe-r2block-head-p01-notoc-single, -p02-notoc-interleaved, -p09-toc-excludes-notoc, -p17-notoc-repeat and -p21-notoc-two-spaces, and independently by the Toc owner's muse-probe-r2block-toc-p13-skipped), C2 consumes every space or tab after the prefix (probes -p13-double-space, -p19-tab-after, -p20-three-spaces and -p21), and C3 suppresses the stray space before the id attribute. Anchors are positional and never text-derived: htmlspecialchars('toc') plus a counter starting at 0 that only + headings increment, so repeated text gets toc0, toc1, toc2 and Toc copies both the id and raw text from the start token.
