Reference correction to Rawold escaping (2026-11-22), settled by the live probe muse-probe-htmlchars-ro-trail (source ` ``A&B"C<D>E'`` `, valid, stable, saved_source_matches), whose live HTML is `<p>A&amp;B&quot;C&lt;D&gt;E'</p>`: the Rawold token fires on a body whose only apostrophe is its final character (the parse regex `([^']*[^`])` admits an apostrophe exactly there, and nowhere else), and live spells that apostrophe raw. The fossil's Render/Xhtml/Rawold.php escaped the body with a bare `htmlspecialchars()`, which defaulted to ENT_COMPAT before PHP 8.1 but defaults to ENT_QUOTES|ENT_SUBSTITUTE since, so on the harness's PHP 8.5.4 the reference emitted `E&#039;` instead. This is a PHP-version artifact of the same class as the R4-C1 Bibliography title correction; the R2 Form/Raw stage had verified Rawold unchanged on bodies without a trailing apostrophe, which is why the defect survived it. The change is confined to Render/Xhtml/Rawold.php: the body now goes through `htmlspecialchars($options['text'], ENT_COMPAT, 'UTF-8')`, so &, <, > and " stay escaped and the only behavioral differences from the bare call are the apostrophe (raw instead of `&#039;`) and invalid-UTF-8 bodies (empty string instead of U+FFFD substitution), the latter unreachable because a token body is a substring of a saved page's UTF-8 source. Pre-correction bytes are preserved beside the corrected file as Rawold.php.before-htmlchars.php (SHA-256 2c309aa86f655a881a4b372ffeb476f52249b37faa2ebfdd5865431029baa25e; corrected file SHA-256 0ba6f380f0a926185beb9ea205aabb0bd989381941fffe39590f4982bb0e6a84). Verification, firsthand, through ref-php/harness/batch.php render over the HTMLCHARS probe family (conformance-htmlchars/): before the correction the reference disagreed with live on ro-trail by exactly the `&#039;` spelling; after it, ro-trail, ro-plain and ro-interior all match the live captures byte-for-byte modulo the frame's trailing newline pair, and the nine-case smoke battery is byte-identical before and after. The Lean mirror consequence is recorded in REPORT-HTMLCHARS.md: renderRawold in LeanFtml/RawHeadingRules.lean switches from htmlSpecialCharsQuotesSubst to htmlSpecialCharsCompat.
