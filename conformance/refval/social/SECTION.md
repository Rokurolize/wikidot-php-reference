# Rule: Social (`[[social]]`, R3.17)

- **Battery**: 80 cases (`evidence/social/battery.jsonl`: 60 authored `so-*` cases + 20 live probe cases `p01`..`p20`).
- **Live probes**: 20 pages `muse-probe-refval-social-p01`..`p20` on `sandbox-for-codex`.
- **Capture-stability question (the brief's first task): CONFIRMED.** Every one of the 20 captures has `saved_source_matches=true` while `valid=false` and `stable=false`, and the captured HTML carries a span `id="social<digits>"` whose digits change on every render (the inline TITLE-substitution script references the same id). A masked double-fetch, masking `social\d+` to `social#`, is stable on 20/20 pages (`evidence/social/masked-stability.json`). The official tooling was also re-run in place (`evidence/social/captures-recapture.json`, 20/20 `saved_source_matches`): the fresh captures' masked HTML is byte-identical to the original captures on all 20 pages, so the random span id is the sole per-render noise — there are no rotating link sets — and the original captures are sound for adjudication under the social mask. The campaign probe tool's `norm()` does not mask social ids, which is why the captures were flagged unstable.
- **Rule shape**: Social is a parse-time module handoff. `Parse/Default/Social.php` returns the `\xFE module "wiki/social/SocialBookmarksModule" ... \xFE` marker directly as text (the token-based code below it is commented out, and `Render/Xhtml/Social.php` is unreachable), the same handoff shape as the Module rule family, whose expansion the harness's ozone stubs disclose as serving-layer behavior the reference does not model. The reference's observable duties are therefore which sources tokenize and what `sites` string the marker carries, and both match everything live lets us observe, on all 20 probes:
  - Tokenization edges agree exactly: `[[social ]]` with a single trailing space is literal on both sides (`p13`), `[[social  ]]` with two spaces tokenizes with no sites argument (`p14`), tab and newline separators tokenize (`p17`, `p18`), `[[social a]b]]` stays literal while `[[social a]]]` tokenizes (`p20`), the tag is case-insensitive (`p10`, `p11`), and extra spaces around the argument are trimmed into the marker (`p15`, `p16`).
  - The marker's `sites` argument predicts live's rendered link set under the module's own semantics: a single known service renders alone (`p02` digg, `p03` facebook, `p04` reddit); a comma list selects, with unknown names in a list dropped by the module (`p06` digg+reddit; `p08` facebook+reddit out of facebook, twitter, reddit); a lone unknown name falls back to the module's full default set of 13 services (`p05` twitter, `p09` unknownsite, `p20` `a`), as does a space-joined pair, which the module reads as one unknown name (`p07` `digg reddit`); and a capitalized name produces the module's degenerate single empty link, because the module's lookup is case-sensitive, while the marker carries the name verbatim (`p12` `Facebook`).
- **Disposition**: the rendered link block itself (the bookmark URLs with the page permalink and `TITLE` placeholder, the substitution script, the random span id) is the serving layer's SocialBookmarksModule output and is outside the reference's scope, on the Module precedent recorded in `ref-php/harness/ozone-stubs.php`. The module-side semantics listed above are recorded as observations feeding ftml candidate C-REFVAL2-5, not as reference defects. No Social file was edited in this mission, and the battery shows zero movement from the pre-correction renders to the corrected-tree renders.
