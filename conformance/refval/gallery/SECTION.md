# Rule: Gallery (`[[gallery]]`, R3.16)

- **Battery**: 88 cases (`evidence/gallery/battery.jsonl`: 64 authored `ga-*` cases + 24 live probe cases `p01`..`p24`), plus 4 supplementary live probes `pg01`..`pg04` (`evidence/gallery/supplementary.jsonl`, captures in `evidence/gallery/probes3-captures.json`).
- **Live probes**: 24 pages `muse-probe-refval-gallery-p01`..`p24` plus 4 pages `muse-probe-refval2-gallery-pg01`..`pg04` on `sandbox-for-codex`, all with `saved_source_matches=true`.
- **Corrections (3)**, all in `ref-php/text-wiki/Text/Wiki/Render/Xhtml/Gallery.php` (pre-correction backup `Gallery.before-refval2.php`):
  1. **External-source size class**: removed the external-URL branch's `$size = "original";` assignment. An external source item now takes the gallery's effective size class (the validated size attribute, defaulting to `thumbnail`) while its `img src` stays the URL itself, exactly as live renders it (settled by `p14`, `p15`, `pg01` size="small"). The removed assignment also poisoned every later item in the same gallery through the loop-carried `$size` variable; live shows no such poisoning (settled by `pg02`, external first then local, and `pg04`, local first then external: all items `thumbnail` with correct per-item `src`).
  2. **Item `alt` attribute**: the sources-branch item image now emits the item's parsed `alt` attribute (escaped with `htmlspecialchars(..., ENT_COMPAT, 'UTF-8')`) instead of a hardcoded `alt=""`. Live uses the `alt` text and drops `title` entirely, which the corrected render now matches (settled by `p19` and `ga-x15`; the apostrophe in an alt text stays raw, settled by `pg03`).
  3. **Empty-attachments message**: the attachments branch's empty result message changed from `Sorry, no images found attached to this page.` to live's `Sorry, we couldn't find any images attached to this page.` (settled by `p01`, `p02`, `p20`, `p21`). That branch is environment-bound (below), so this correction is verified against the live captures and the rule source rather than by an in-harness render.
- **Environment-bound branch**: the no-sources form reads the current page's attachments through `DB_PagePeer::selectByName` with `vars['pageName']` and then `DB_FilePeer`, neither of which the harness supplies (the page stub map returns null and no file peer exists in the tree), so in-harness it renders `Error selecting page.` where live renders the empty-attachments error block. This is the whole disagreement on `p01`, `p02`, `p20`, `p21`. The `flickr:` branch (`FlickrHandler`) is likewise environment-bound and is exercised by no battery case.
- **Serving surface**: on every explicit-source case, live's serving layer adds `id="gallery-box-<random digits>"`, `class="with-lb"` on anchors, `class="gallery-image-size-<size>"` on images, lightbox `<script>` blocks, the `https://sandbox-for-codex.wdfiles.com` host, and pretty-print whitespace. Under those masks plus the fossil template's trailing anchor space, the corrected reference agrees with live byte-exact on 19/24 probes and 4/4 supplementary probes (`evidence/verify-refval2.py`). The remaining probe, `p24`, differs only in paragraph framing of the literal tail around a non-tokenized inline `[[gallery]]` (both sides consume the `: a.png` line identically; live's Stage 2 splits the tail into its own `<p>`), a Stage 2 / Paragraph framing surface.
- **Comparison before vs. after**: before correction, all 24 probes differed, with substantive differences on `p14`, `p15` (external size class) and `p19` (alt). Battery movement from the pre-correction renders to the corrected renders is exactly 8 cases (`ga-x10`, `ga-x11`, `ga-x15`, `ga-x17`, `ga-x20`, `p14`, `p15`, `p19`), each audited to one of the correction classes above.
- **Smoke check**: 9/9 smoke cases byte-identical before and after the REFVAL2 corrections (swap-verified against the `*.before-refval2.php` copies).
- **R3 stage consequence**: none. `Parse/Default/Gallery.php` is unchanged; all three corrections are in the Xhtml render, which the R3 parse-phase mirror does not cover.
