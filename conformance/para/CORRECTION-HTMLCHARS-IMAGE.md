Reference correction to Image escaping (2026-11-22), settled by the live probes muse-probe-htmlchars-im-attrs, im-local and im-altamp (all valid, stable, saved_source_matches): an external src of `https://example.com/a'b.png` renders with the apostrophe raw, a link of `https://example.com/x'y?a=1&b=2` renders as `href="https://example.com/x'y?a=1&amp;b=2"`, title and alt values keep authored apostrophes raw while escaping &, a local src `htmlchars/a'b.png` renders its fallback alt as `alt="a'b.png"`, and an authored `&amp;` in an alt value double-encodes to `&amp;amp;` exactly as an ENT_COMPAT escape does. The fossil's Render/Xhtml/Image.php used bare `htmlspecialchars()` at five call sites (the src after encodeNonAscii, the attribute key, the attribute value, the fallback alt from basename(src), and the href after encodeNonAscii), which on the harness's PHP 8.5.4 defaults to ENT_QUOTES|ENT_SUBSTITUTE and spelled every reachable apostrophe `&#039;`. The change is confined to Render/Xhtml/Image.php: all five calls now pass ENT_COMPAT, 'UTF-8'. The attribute-key call's input is one of the parse whitelist's fixed names (title, style, class, alt, height, width), which contain no escapable character, so that conversion is output-neutral and is made only so no bare call remains in the file. The only behavioral difference from the bare call besides the apostrophe is invalid-UTF-8 handling (empty string instead of U+FFFD substitution), unreachable because every escaped string derives from a saved page's UTF-8 source. Pre-correction bytes are preserved beside the corrected file as Image.php.before-htmlchars.php (SHA-256 c8389998714767a8c564c4a75b22b7f47cf4a97c1b78a22e88216c89d7e49973; corrected file SHA-256 f48fcb46b1fc30dacd0b217d45b5261d8b61bfbca7b0588fddb8aa50ff39452b). Verification, firsthand, through ref-php/harness/batch.php render over the HTMLCHARS probe family (conformance-htmlchars/): the correction moves exactly im-attrs, im-local and im-altamp; im-attrs and im-altamp then match their live captures byte-for-byte modulo the frame's trailing newline pair, and im-local matches on every escaped byte, its only difference being live's serving-layer wdfiles host prefix on the src URL. The nine-case smoke battery is byte-identical before and after.
