# R2 Paragraph rule (pipeline rule 39): differential, correction, and disposition

Method. I read `ref-php/text-wiki/Text/Wiki/Parse/Default/Paragraph.php` and `ref-php/text-wiki/Text/Wiki/Render/Xhtml/Paragraph.php`, the ftml paragraph machinery in the read-only checkout (`src/parsing/paragraph/mod.rs` and `stack.rs`, `src/parsing/rule/impls/block/blocks/span.rs`, `src/parsing/rule/impls/line_owner.rs`, `src/preproc/whitespace.rs`), and the 24 pins under `test/paragraph/`. The decisive pins were `basic` (blank-line splitting and the `<p>` run shape), `whitespace-line-no-demotion`, `form-feed-whitespace-line`, `vertical-tab-whitespace-line`, `comment-line-break-demotion-tab`, and the two scored-span pins `test/span/fused-opener-scored-map-residual` and `fused-scored-residual-space`; the ftml source that decides the routed score-span item is `wikidot_scored_alias_open_joins_previous_line`, `wikidot_scored_close_joins_late_line`, `wikidot_current_ends_with_scored_alias` and `wikidot_scored_alias_open_after_break` in `src/parsing/paragraph/mod.rs`, plus the `data-ftml-score-span` marker the span block rule inserts. The fossil is a skeleton and never behavior evidence. I did not edit ftml, the harness, another rule file, or any git identity; the smoke run through root's 9-case battery is byte-identical to the pre-correction smoke capture.

Mechanism as corrected. The ordinary paragraph mechanism is unchanged: the regex `/^.*?\n\s*?\n/m` still cuts the source into runs at blank-line boundaries, `process()` still wraps a run in a `Paragraph` start/end token pair, still drops a run whose trimmed text is empty, and still suppresses the wrapper when the run begins with a token whose type is in the `skip` list (blockquote, code, clearfloat, heading, horiz, deflist, table, tableadv, list, toc, center, tabview, div and its align variants, collapsible, note, math, module variants, footnote blocks and items, bibliography and bibitem, gallery, image). The render rule is unchanged and still emits `<p>` and `</p>\n\n`. The one correction is the scored alias form: a paired `[[span_ ...]] ... [[/span]]` is now turned into an ordinary Span token pair by calling the existing Span rule's `process()` from this rule's new `parse()` override, the line-break runs on both sides are removed (keeping same-line horizontal spaces and any non-break token such as a preceding `[[div]]` opener), and a run that is exactly that scored pair keeps its bare `<span>` with no paragraph wrapper. Unpaired openers remain literal, plain spans still receive their paragraph, and scored spans inside code stay literal because the Code rule tokenizes them first. This is the paragraph-side half of ftml's scored-alias gathering; the Span rule's token grammar is reused rather than duplicated or edited. Whitespace-run collapse inside text is deliberately not performed here, for the reason given in the open-item verdict below.

Corrections and classifications. The correction is confined to the parse file; the render file is byte-identical to stage start. The same call path makes multi-line scored spans join their surrounding lines exactly as ftml does, which the fossil also missed. The pre-correction bytes are preserved verbatim as `Paragraph.php.before.php` (SHA-256 829e41e7502b9c6f119fb91ebe54f8f24527f17f73ec57311d2f711290265368) and `ParagraphXhtml.before.php` (SHA-256 0104c7b96f85cd15eea350a6411d850b071c3aa8b02a119298b7bce0205dc198); the render copy is kept even though that file was not changed, so both baselines are available. No other correction was needed: every other battery difference is outside these two files or is the frame-level surface settled below.

Verdict on open item (a), the frame space-run collapse. The collapse is owned by Stage 2 `WikiTransformation::purifyHtml`, the libtidy pass of the 2026-11-04 two-stage ruling, and Paragraph neither owns nor should attempt it. The decisive evidence is the scored-span probe p02: live renders the source `[[span_]]word1<TAB>word2[[/span]]` as `<span>word1 word2</span>` with no `<p>` wrapper anywhere, and the dumper agrees byte-for-byte while the reference keeps four spaces. A paragraph rule cannot change the bytes of a run that has no paragraph, so the collapse cannot be paragraph-owned. The same split appears on ordinary flow text in p01, p03, p05, p06 and p07 (p05 collapses four literal spaces exactly as it collapses an expanded tab), while the code control p04 keeps four spaces inside `<pre>` on live, ftml and the reference alike, which is the libtidy text-node collapse leaving preformatted content alone; the frame stage's earlier probe muse-probe-r2f-frame1 shows the same split independently. The Newline owner's independent NL-F2 evidence agrees: live probe muse-probe-r2para-nl-p04 renders the source `alpha \n beta` as `<p>alpha<br />\nbeta</p>` on live and in ftml while the reference keeps the two edge spaces, and the Newline owner placed that collapse in the whitespace or pre-layout layer rather than in the break token or the paragraph wrapper. The reference's Stage 1 therefore keeps four spaces where live shows one; that is a frame-level later-rule surface already routed as Tier 2 G2.2, and collapsing here would be an unsound global rewrite outside the two owned files. No correction was made.

Verdict on open item (b), the score-span residual. The suppression is paragraph-owned and is implemented in C1. Three distinct shapes were separated. The scored opener `[[span_]]X[[/span]]` suppresses the wrapper and joins adjacent lines on live, ftml and the corrected reference: p08 is `<span>X</span>` on all three, p11 is `<p>before<span>X</span>after</p>` on all three, and p17 joins even across two blank lines on all three; the Span owner's probe muse-probe-r2contain-span-p20 and battery pg54 agree. The score-CLASS span `[[span class="score"]]100[[/span]]` does not suppress anything: live p09 renders `<p><span class="score">100</span></p>`, ftml and the corrected reference agree (battery pg55, probes p09, p12, p14, p16), and the routed premise that the class itself suppressed the wrapper was not borne out by the saved page. The scored anchor `[[a_]]X[[/a]]` behaves like the scored span in ftml (exploratory q7, `<a href="">X</a>` bare) but the reference's Anchor rule has no scored form at all, so this stage cannot tokenize it from Paragraph.php without editing another rule's file; it is recorded below as a scope gap. Root's interaction cases x39-x41 use the class form, so they exercise the non-suppressing shape and need no Paragraph change.

Remaining disagreements and dispositions. The N1 battery differences are pg12 (Typography entity spelling on `''em''`), pg16 (the link rule's pipe handling for my deliberately awkward `[[http://example.com|example]]` source), pg24 and pg25 (the Stage 2 whitespace-run collapse, item a), pg35 (an inline `[[div]]...[[/div]]` on one line, whose newline inside the ftml `<p>` is frame surface), and pg45 (a literal inline div between text runs, where ftml's newline and the Newline rule's break placement are later-rule surface). All six are outside the two owned files or are the frame surface already dispositioned above; none was patched here. The scored-span family still differs from ftml only by the same whitespace-run collapse (probe p02, exploratory e6), and the exotic scored-span-in-div shape q8 is left alone because the dumper itself reports parse errors there and no live probe settled it. Unpaired scored openers stay literal on all three sides (q9), and multiple, nested and crossed scored spans agree structurally (e1, e3, e4, e5). Unsaveable leading, trailing and whitespace-only-line cases are covered by the dumper comparison only, which is a serving-layer save-normalization limit rather than a paragraph difference.

Candidate findings and routing items. No candidate ftml divergence was found in paragraph formation proper: on every shape the battery and probes can settle, ftml and live agree and the corrected reference follows them. PG-F1 is a routing item rather than an ftml finding: the scored anchor `[[a_]]X[[/a]]` renders bare on ftml and needs the same paragraph-layer joining and wrapper suppression as the scored span, but the reference's Anchor rule only recognizes `[[# name]]`, so the fix requires an Anchor-rule change outside this stage's two files; root should route it to the appropriate rule owner with the exploratory q7 evidence. PG-F2 is an unsettled exotic shape, a scored span on its own line inside `[[div]]`: ftml emits parse errors and leaves the div literal while the corrected reference emits `<div ><span>X</span></div>` (q8); with no live capture for that exact source I make no verdict and leave it as a coverage gap.

Questions asked and assumptions proceeded on. The first question was which of the two "score span" shapes the routed item meant: I resolved it by probing both and found that the scored opener suppresses and the score class does not, and I proceeded on live's verdict. The second was whether Paragraph could own a whitespace collapse that occurs with no paragraph: I proceeded on the negative because p02 has no wrapper, and left the surface to Stage 2. The third was whether the scored opener could be handled without editing Span.php: I proceeded by reusing the Span rule object's existing `process()` rather than duplicating its attribute grammar, which keeps the correction inside the two owned files while preserving live's attribute behavior. The fourth was whether the whitespace-only and trailing-whitespace battery cases needed live evidence: Wikidot strips those on save (three create attempts failed read-back before I replaced the sources with savable proxies), so I proceeded with dumper-only evidence for those shapes and disclosed the limit. No harness problem was found, no cargo was run, no git state was changed, and the 26 probe pages were left in place as listed in `probes/probe-map.json`.
