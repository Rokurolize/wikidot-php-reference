# R2 Span, Size, Div, Collapsible and Tabview stage: differential and correction catalog (2026-11-20)

Method. This stage runs as a team of five rule owners plus a root coordinator, one owner for each of the twenty-eighth-through-thirty-second pipeline rules in this batch: Span, Size, Div, Collapsible and Tabview, the container family. The family is defined by containers and by the span-shaped inline constructs that nest and cross inside them: span, size, color and strikethrough all render as <span> on live, and Div, Collapsible and Tabview are block containers that can hold inline content and other containers, so per-rule differentials only mean anything at the seams where these shapes meet. The shared reference harness (ref-php/harness/batch.php in expand, render and tokens modes, transform.php for the smoke run) is read-only for rule owners; harness problems go to root. Before any teammate starts, root builds one shared ftml dumper at conformance-refphp/contain/rust-dump/ in the Form/Raw stage's style (preprocess_for_layout, tokenize, parse, HtmlRender over JSONL {"id","source", optional "tags"}) and records the read-only ftml checkout HEAD in that directory; every cargo invocation goes through heavy-build.sh with HEAVY_BUILD_NO_SPLIT=1 as a polled background job because foreground bash times out at 60 seconds. Live probes use the wikidot-probe CLI through its scripts/wikidot-python wrapper against sandbox-for-codex, with prefixes partitioned per rule (muse-probe-r2contain-span-, muse-probe-r2contain-size-, muse-probe-r2contain-div-, muse-probe-r2contain-coll-, muse-probe-r2contain-tab-) and root's cross-rule prefix muse-probe-r2contain-x-; fetch once, cache, reuse. Corrections land only in a rule's own two files under ref-php/text-wiki/Text/Wiki/Parse/Default/ and Render/Xhtml/, with pre-correction bytes preserved as conformance-refphp/contain/<rule>/<File>.before.php. The fossil Text_Wiki snapshot under ref-php/fossil/ is a skeleton and never behavior evidence; live Wikidot behavior wins every disagreement, the evidence order is ftml corpus pins then frozen captures then live sandbox probes, and fetching from live is pre-approved. Serving-layer scope is as in earlier stages: what a rule computes from page or site state is evaluated only as far as live's anonymous saved-page view makes it observable and deterministic, and the stage owns matching, tokenizing, attribute handling and the observable display shape. Two standing facts from this loop's earlier work bear directly on this stage and are not to be relitigated: the inline-scope model (2026-11-04 ruling) says live's Stage 1 pairs constructs in source text and Stage 2 (the libtidy pass in WikiTransformation::purifyHtml) re-nests by HTML tag name, which is why span-shaped constructs interact the way they do; each shape tested is recorded against that two-stage model rather than re-derived. The Concatlines stage left one reference residual for this stage: the reference Div rule does not recognize a standalone [[div_]] opener (its N1), which the Div owner settles here. Prose in this catalog and in each section is written as flowing paragraphs on single lines, never hard-wrapped at a fixed column.
