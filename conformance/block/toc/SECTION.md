Mechanism as corrected. The parse rule matches [[toc]], [[f<toc]] and [[f>toc]] with the multiline regex /^(?:\n*)\[\[(f[<>])?toc( .*)?\]\](\n)*/m; group 1 is the float alignment and group 2 is the raw option tail, parsed into key/value pairs by Text_Wiki_Parse::getAttrs(). It emits a Toc list_start token carrying level 0, the parsed attr map and the align string, then walks every Heading token of type 'start' in document order and emits, per heading, an item_start token carrying the heading's id, level and a running count, the heading's raw text, and an item_end token, and finally a list_end token. The heading ids themselves are owned by the Heading parse rule, which assigns toc0, toc1 and so on from vars['headline_id'] in document order; Toc is a pure consumer of that bookkeeping. The render rule wraps a non-floating TOC in the table/tr/td shell and emits <div id="toc">, a float class for f< / f>, the toc-action-bar with Fold and Unfold links, a title div taken from the title attribute or defaulting to Table of Contents, and the toc-list div. Each entry is a div with margin-left equal to the heading level in em (the render's $min stays 0, so a level-1 heading gets 1em, a level-4 heading 4em, and skipped levels keep their numeric level), containing an anchor to the heading id; the fossil's doubled \xFC sentinel characters around the label are removed by the post-render strip_tags hack in Text/Wiki.php, so the final entry text is the plain heading label. After correction the float class tag has no trailing space, the action bar uses capitalized Fold and Unfold, and the title div honors the title attribute with htmlspecialchars(..., ENT_COMPAT, 'UTF-8'). Attribute parsing already lived in the parse rule and was already carried on the list_start token, so no parse change was needed; class, style and id options are parsed but ignored on all three sides in the legacy Wikidot layout. Toc runs after Footnote in pipeline order, so a [[toc]] inside a footnote body is consumed into the footnote token before Toc can see it and stays literal on all three sides (probe p19-toc-in-footnote, ftml's own test/footnote/body-first-line-toc-literal pin). Headings inside divs, collapsibles, retained iftags bodies, quotes and lists are collected whenever their Heading tokens survive (probes p15 through p18); a [[toc]] with an iftags span crossing its own name still matches after the hidden tag text is removed (probe p32-iftags-mid-name, ftml pin test/toc/iftags-seam-mid-name). Repeated heading text yields distinct sequential anchors toc0 and toc1 on all three sides (probe p20-repeated-text).

Corrections made. All three corrections are in Render/Xhtml/Toc.php only; the parse file is byte-identical to stage start (after SHA-256 b9c4ff60f1a55cc8a2a20c05c18ac09e73bee5cdab4fa85ea293f5d6faf4ddcd), and the corrected render SHA-256 is 7b296aca63b38d6eafa3058aede77c14734eaf4ca441cd7fee67e612bfb82f22, both passing php -l. C1 replaces the fossil's _('fold') and _('unfold') calls with literal Fold and Unfold, classified as a fossil-era artifact: the fossil ships no gettext catalog and the read-only harness stub returns the lowercase key unchanged, while live and ftml use the capitalized catalog labels. The live evidence is root's probe muse-probe-r2block-x-x-toc-basic and my p01-basic, and the ftml pins under test/toc/ use the capitalized labels consistently. C2 makes the title div render the parsed title attribute when present, falling back to Table of Contents, escaped with ENT_COMPAT so apostrophes stay raw; the fossil parsed the attribute but never emitted it, so this is a fossil-era artifact manifesting as a reference bug. Live probes p02-title (Contents), p03-title-empty (empty title), p04-title-entities (目次 &amp; &lt;notes&gt;), p05-quoted-close (a]]b inside a quoted value) and p34-title-apostrophe (it's &amp; fine) settle it, and the corrected reference matches live byte-for-byte on that surface. C3 removes the trailing space after the float class attribute (class="floatright"  became class="floatright"), classified as a fossil-era artifact manifesting as a reference bug; root's live probe muse-probe-r2block-x-x-toc-float-right and my p08-float-left and p09-float-right settle it and ftml already matched live. C1 and C3 are exactly the two seams root relayed from the cross-rule probes; C2 came from my own focused probes. No correction was classified as a PHP-version artifact or a harness matter for this rule. A question that arose mid-work was whether an apostrophe in the title should be escaped; the assumption carried until p34 was that ENT_COMPAT matches live (by analogy with the Footnoteblock title correction in R2-NOTES.md), and p34 then confirmed it, so no unresolved assumption remains.

Remaining disagreements and dispositions.
