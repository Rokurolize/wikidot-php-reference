# CORRECTION C-STAGE2-2 — The suppressed empty div still bounds its following text (REFCORR2 lane, 2026-11-22)

Status: APPLIED in this tree. An empty div whose head carries no effective attribute is suppressed on live, but the suppressed pair still counts as a block boundary: the text after it is not paragraph-wrapped, and a leading newline becomes a break. The reference's parse claimed no tokens for the suppressed pair, which left the following text to a fresh paragraph. The correction claims the pair with a `vanished` flag and suppresses the tags at render instead. Recorded as candidate C-STAGE2-2 in stage2/REPORT-STAGE2.md §5 (corpus case con-x24: reference `<p>[[/div]]</p>`, live `<br />\n[[/div]]`; the F-R2-51 family, R2 routing name M44).

## Why this is a Stage 1 matter, not a Stage 2 effect

The Stage 2 model's inventory has no rule that turns a paragraph into a leading break, and running the model over the uncorrected Stage 1 output for con-x24 leaves `<p>[[/div]]</p>` unchanged (verified firsthand by the REFCORR2 lane against the canonical stage2/stage2-model/Stage2.lean). The break therefore has to arise in Stage 1's own composition. The R2 Div section had already recorded the residue half of this shape as class S ("the vanished empty div leaves a <br> on live but no <br> in the reference's paragraph frame, which is unfixable inside Div.php without crossing the Paragraph rule's token contract"); this correction crosses exactly that contract in the smallest way, by keeping the pair in the token stream.

## The settling evidence

The mechanism was isolated by fresh probes on sandbox-for-codex, 2026-11-22 (pages muse-probe-refcorr2-divn-*; cases in conformance-refcorr2/probe-cases.jsonl and probe-cases-2.jsonl, captures in conformance-refcorr2/probe-captures.json and probe-captures-2.json; every capture cited below is valid, stable, and saved-source-matching). A stray closer alone (divn-r2, source `[[/div]]`) serves `<p>[[/div]]</p>`, paragraph-wrapped, exactly as the reference renders it: the residue text alone explains nothing. The same closer text after a suppressed pair (divn-s5, the con-x24 source re-probed) serves `<br />\n[[/div]]`, unwrapped. A mid-document suppressed pair (divn-s11, `before\n[[div]]\n[[/div]]\nafter`) serves `<p>before</p>\n<br />\nafter`: the text before the pair is wrapped, the text after it is bare with a leading break. A suppressed pair alone (divn-s12) serves the empty string. The quoted twin of con-x24 (divn-s4) serves `<div class="a"></div>\n<br />\n[[/div]]`: with an effective attribute the pair is real (the giant lazy match takes class="a" from the spanning attribute tail, as the R2 record describes), and the following residue is post-block in exactly the same way, a behavior the uncorrected reference already reproduced for that shape. The frozen R2 captures agree: empty-plain and score-empty (`[[div]]\n[[/div]]\nB` and the scored form) serve `<br />\nB`, and empty-attr serves the kept div followed by `<br />\nB`. The discriminator between the wrapped and unwrapped residue is therefore the pair's presence in the token stream, and nothing else. Two designed probes are recorded as undeliverable rather than as evidence: a page whose source begins with a newline (divn-r1, divn-r3) cannot be saved as authored, because live's save layer strips the leading newline (the create step's read-back verification fails; the saved page holds the stripped source), so the standalone leading-newline residue shape does not exist as a saved page; it arises only mid-pipeline, where the probes above settle it.

## The correction (reference)

Parse/Default/Div.php: the empty-value unset now runs before token creation, and when no effective argument remains and the trimmed body is empty, the start and end tokens are claimed with an additional option `'vanished' => true` instead of the parse returning only the doubled leading newline. Every existing replacement shape (the scored and unscored framings, the leading-newline handling) is unchanged; only the token claim and the flag are new. Render/Xhtml/Div.php: `token()` returns the empty string for a token carrying the flag, for both types. Before-copies: ref-php/text-wiki/Text/Wiki/Parse/Default/Div.php.before-refcorr2.php (SHA-256 b4a0386e406fc88e639df1ddc6669743f55d9df9be0e1287c4959ec3351966ff) and ref-php/text-wiki/Text/Wiki/Render/Xhtml/Div.php.before-refcorr2.php (SHA-256 cafbe1b533481a11c2906d884e089826614e21f8e45b4e703fbe1147abf6fca4, the R4-C3-corrected file); corrected files SHA-256 fe8acf876e18cea529a65d073fbe2d113bdce44bb5ae7079e5b46010b539e8d6 (parse, shared with correction C-STAGE2-1) and d58c73ee8328e0c3d77df5c660491e07da5f350cc5847b79988a87b3c006e3e4 (render). The Stage 2 model needs no change: with the corrected Stage 1, the model's T10 statement (an empty div element is kept) is untouched, because an attributeless empty div no longer reaches Stage 2 as an element from this reference, and the one Stage 2 battery case for pruning (p31) is an attributed div, which is still emitted and still kept.
