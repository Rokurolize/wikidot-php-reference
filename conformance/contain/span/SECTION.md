# R2 container family stage: Span rule section (2026-11-20)

Mechanism as corrected. The parse rule keeps the fossil regular expression `'/\[\[span(\s.[^\]]*)?\]\]((?:(?R)|.)*?)\[\[\/span\]\]/msi'`, which pairs an opener carrying at least one whitespace and one head character with the first same-type closer in source order and recurses through `parse()` until the source stops changing. That source-pairing is live's Stage 1; the later libtidy re-nesting by HTML tag name (the 2026-11-04 inline-scope model) is recorded below and is not re-derived here. `process()` now trims horizontal whitespace off the body edges, parses the head with the inherited `getAttrs`, and builds the token's `args` from a live whitelist: `class`, `style`, `role` and `type` are kept by exact key, `id` is kept with the user-id prefix `u-`, `data-*` keys are kept with the key lower-cased, and every other key (including `title`, `TITLE`, event handlers and arbitrary names) is dropped. A source-empty value is omitted. `id` is inserted first and the surviving attributes follow source order, which is the order live emits; an unattributed span whose body is empty after trimming is elided from the source entirely, while an attributed empty span is kept. The `%%...%%` hypothesis from the fossil brief is not a span on either side: ftml treats `%%name%%` as a delayed runtime-placeholder literal and live probe `muse-probe-r2contain-span-p19-percent` renders `%%hidden%%` literally, so no `%%` branch was added. The render rule now emits `<span` followed by one space per attribute and `>`, and `</span>` for the end token, with no leading double space and no forced empty `style`; values pass through `htmlspecialchars` with `ENT_COMPAT` so live's `a&b` to `a&amp;b` and `a"b` to `a&quot;b` are reproduced. Both files pass `/usr/bin/php -l`.

Remaining disagreements and their dispositions. SPAN-F1 is a candidate ftml divergence with cosmetic impact: for p16 and battery s20 ftml serializes the span attributes alphabetically as `class`, `data-d`, `id`, `style`, while live and the corrected reference emit `id` first and then source order; both forms are semantically identical HTML and the difference is the serving layer's attribute re-serialization, so root should route it as a low-priority frame-level later-rule surface rather than a Span defect. D2 is the score span: ftml and live both render `[[span_]]X[[/span]]` as a bare `<span>X</span>` on probe p20 and battery s41, while the reference leaves the call literal, because the scored opener owns the root paragraph and suppressing that paragraph belongs to the Paragraph rule, outside this lane's two files; this is a frame-level later-rule surface, not a candidate ftml divergence. D3 is the colour rule's trailing semicolon, where the reference emits `style="color: red;"` and ftml and live emit `style="color: red"` in s30, s33, s36, s38 and p26; root already recorded this as a Color-rule surface outside the two Span files and no Span edit was attempted. D4 is a literal-form whitespace surface in s04: `[[span ]]  [[/span]]` is unmatched by both parsers, and ftml collapses the two interior spaces to one while the reference keeps both; live p33 settled the related `[[span ]]X[[/span]]` form as literal and matching the reference, and the space count is frame-level surface, so no finding is claimed. D5 is the inline-scope model's later-rule surface in s50 and s57: ftml's Stage 2 re-nests the span around each structural run when a `[[div]]` or heading and list cross it, while the fossil pairs the source text in Stage 1 and produces different `<br>` placement and nesting; this is the settled two-stage model, not a Span token defect, and live was not probed for those exact crossing shapes. D6 is the counter-bearing collapsible id in s51, normalized away per root's harness audit. No candidate ftml divergence is claimed for the `%%` form, the attribute whitelist, the `u-` prefix, edge-space trimming or empty-span elision, because ftml and live agree with the corrected reference on all of them.

Questions asked and assumptions proceeded on. The first question was whether the fossil brief's `%%...%%` hypothesis should be implemented; the assumption was no, and p19 plus ftml's delayed-placeholder code confirmed that `%%` is not a span. The second was whether attribute values containing a bare apostrophe are escaped; the assumption was `ENT_COMPAT`, which leaves apostrophes raw in line with the loop's earlier live finding on heading text, and this shape was not separately probed because all four attribute probes covered ampersands, double quotes, key casing and empty values. The third was whether the score span should be matched despite the paragraph-suppression requirement; the assumption was no, because emitting Span tokens without removing the enclosing paragraph would still disagree with live and would exceed the two-file scope, so it is recorded as a residual for root. The fourth was ftml's delayed-attribute marker case where `class="@@a@@"` yields `class=""` on the wikidot surface; the reference cannot model that marker without the delayed-attribute subsystem, so it is left as serving-layer scope with no live probe.
