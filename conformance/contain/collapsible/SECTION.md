# R2-contain Collapsible section: differential and correction (2026-11-20)

Mechanism as corrected. This rule owns the `[[collapsible options]]...[[/collapsible]]` block pair and the Wikidot-layout HTML frame it renders. Layer ownership is as follows: the preproc and newline layers decide where a collapsible head anchors; the fossil parse regex `/(\n)?\[\[collapsible(\s.*?)?\]\](.*?)\[\[\/collapsible\]\] */msi` is applied once per document with `preg_replace_callback`, so its non-greedy body already implements the G1.2 first-closer discipline (the first `[[/collapsible]]` closes and any same-type openers seen before it remain literal body text, with no same-type counting), and its `getAttrs()` reader accepts only double-quoted `key="value"` pairs with case-sensitive keys; the Paragraph and Typography rules downstream wrap and format the body; this rule's renderer emits the outer frames. Live probes (all 17 cached muse-probe-r2contain-coll- pages) settle that the current live frame is the class-based Wikidot form: `<div class="collapsible-block"><div class="collapsible-block-folded"[ style="display:none"]><a class="collapsible-block-link" href="javascript:;">SHOW</a></div><div class="collapsible-block-unfolded"[ style="display:none"]>[top hide link]<div class="collapsible-block-content">BODY</div>[bottom hide link]</div></div>`, with a hide link wrapped in `<div class="collapsible-block-unfolded-link">`. There are no element ids, no `$('...')` onclick handlers, and no passthrough of class/id/style/data-* attributes onto the outer div (the attribute-bearing `basic/wikidot.html` frozen pin is stale relative to current live). Labels are rendered with spaces as `&nbsp;`, tabs as four `&nbsp;`, line breaks as a plain space and control characters dropped; the default show label is `+ show block` and the default hide label is `– hide block` with an en dash. `folded="no"` or `"false"` hides the folded handle and shows the content; `hideLocation` accepts only the exact values `bottom` and `both` for non-default placement and everything else, including `neither`, falls back to a top hide link. `showText`/`hideText`, single-quoted values and unquoted values are not live keys and are ignored, which the fossil's `show`/`hide` reader already models correctly. The parse rule and token contract are unchanged; only the render rule was edited. The inline-scope model (2026-11-04 ruling) is not re-derived here: the nested-same-type and collapsible-in-block shapes tested below are block-level pairing shapes recorded by the G1.2 discipline, and the inline content inside the block is ordinary body text whose formatting belongs to later rules. Serving-layer scope is respected: only the anonymous saved-page view is used, and random tab/collapsible ids and date attributes are masked before comparison.

Corrections made, with classifications. C1 (fossil-era artifact, manifesting as a reference bug) rewrote `Text_Wiki_Render_Xhtml_Collapsible::token()` to emit the live class-based frame instead of the fossil's id-and-JavaScript frame: the old output used `<div id="collapsible-block-N-folded">` anchors with inline `$('collapsible-block-N-...').style.display=...` onclick handlers and bare `<div>` wrappers, which current live never renders; the corrected output uses `collapsible-block-folded`, `collapsible-block-unfolded`, `collapsible-block-unfolded-link`, `collapsible-block-content` and `collapsible-block-link` classes with `href="javascript:;"` anchors and no ids or scripts. The numeric `count` token option is left intact in the token stream for compatibility but is no longer consulted, so the harness-owned static-counter leak cannot affect output. C2 (fossil-era artifact) replaced the label rendering: the fossil printed `+ show block` and `- hide block` with literal spaces and an ASCII hyphen, while live prints `+&nbsp;show&nbsp;block` and `–&nbsp;hide&nbsp;block` with an en dash; the corrected `wikidotLabel()` helper applies the live space/tab/newline/control-character rewriting and htmlspecialchars, with defaults matched to live. C3 (PHP version artifact) replaced the unguarded `$args['folded']`, `$args['show']`, `$args['hide']`, `$args['hideLocation']` reads with `isset` guards; under PHP 8.5.4 with E_ALL the fossil raises four distinct "Undefined array key" warnings per token (captured in php-warnings-before.txt), a class of notice that was silent in the fossil's PHP 5 era, and the corrected file emits none (php-warnings-after.txt is empty). No parse-rule change was needed: its non-greedy first-closer regex, double-quote-only attribute reader, case-insensitive opener and case-sensitive keys all agree with live on every shape tested, so the parse file was preserved byte-for-byte. Pre-correction bytes are preserved as Collapsible.parse.before.php (SHA-256 5af5aac07a67edc48f3a8776965551aad115e7679007e8601830e9a752945cf4) and Collapsible.render.before.php (SHA-256 42de04b37a0ba629e6a2cb1fabd5adb37d3a4ff7803f3dd97933895cde986575); the corrected render is also kept as Collapsible.render.after.php (SHA-256 21b021f9ac414350a55c62398dcd493b52bc30b4cf17ef4f74415adcc4775871).
