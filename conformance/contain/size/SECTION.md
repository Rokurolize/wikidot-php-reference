# R2-contain Size section: differential and correction (2026-11-20)

Mechanism as corrected. The Size rule owns the Wikidot `[[size value]]...[[/size]]` construct. The parse rule's regex matches a case-insensitive `size` opener followed by a value and a `[[/size]]` closer, trims the value, and accepts it only when it is one of the nine exact-lowercase named sizes (xx-small, x-small, small, medium, large, x-large, xx-large, smaller, larger) or a numeric value of one to five `[0-9.]` characters ending in `%`, `px` or `em`; the outer regex's case-insensitive flag applies to the tag spelling, while the value checks are case-sensitive, which is exactly live's behaviour on the corpus pins name-case-title, name-case-uppercase, size-uppercase-larger, size-uppercase-px and size-uppercase-em. The numeric grammar was verified against live: five characters are accepted (probes boundary-5-px and boundary-5-pct), six are rejected (long-px, long-pct, boundary-6-em), and the fossil's one-to-five-character limit is therefore correct and was left untouched. The renderer emits `<span style="font-size:<value>;">` and `</span>` with no padding, matching live and ftml on every accepted value form; the render file needed no correction and its pre-correction bytes are preserved. Three body-handling corrections were made in the parse rule after the value check: discarded C0 control bytes are removed from the body, ASCII spaces and tabs are dropped at every line end within the body (including immediately before the closer), and a construct whose body has no visible content is consumed entirely rather than emitting an empty span. The body regex now pairs innermost constructs first and `parse()` recurses, so a nested pair that becomes empty is also consumed; for non-empty nesting this yields the same start/end token nesting as the fossil's recursive-body regex, and the token option shape `{size, type}` and `{type}` is unchanged. Because size is a span-shaped construct in the settled inline-scope model, its interaction with span, color, strikethrough and bold is a Stage 2 re-nesting by HTML tag name that this reference's sequential token model does not reproduce; those crossings are recorded below as root-owned interactions and were not re-derived or hacked into this rule.

Corrections and classifications. C1 (fossil-era artifact manifesting as a reference bug) is the removal of discarded C0 control bytes from the body: ftml's Wikidot-layout pin whitespace-size-body-nul shows live rendering `[[size 120%]]A<NUL>B[[/size]]` as `<p><span style="font-size:120%;">AB</span></p>`, while the fossil passed the NUL through (a standalone plain-text NUL is also kept by the reference frame and is a separate later-rule surface, not corrected here). C2 (fossil-era artifact manifesting as a reference bug) drops trailing ASCII spaces and tabs at line ends inside the body: live probes space-before-close, multi-space-close, tab-close and internal-space-newline show the spaces dropped, while newline-close, newline-only-body and space-newline-body show the line break itself kept and nbsp-close shows a non-breaking space kept, so the strip is deliberately `[ \t]+(?=\n|$)` rather than a generic rtrim. C3 (fossil-era artifact manifesting as a reference bug) suppresses empty and whitespace-only bodies: probes empty-body, ws-body and empty-nested all render nothing on live, and ftml agrees, whereas the fossil emitted `<p><span style="font-size:100%;"></span></p>`; the nested-empty case required changing the body matcher to pair innermost constructs first so the suppression applies inside-out, with zero changes to the other 79 battery renders. No correction is classified as a PHP version artifact or a harness matter. The pre-correction bytes are preserved as Size.parse.before.php (SHA-256 3e7cd33e001471f4320a11e8e5059b47fa0dcde2f1657f2bcb018c9c66c563f6) and Size.render.before.php (SHA-256 14c5d218a451e94d8864865ef99c307e7ad82db216f1eedb4f093dc48abe43bc), also recorded in before-sha256.txt; after digests are in after-sha256.txt. Only the parse file changed; the render file is byte-identical to its before copy. The harness is read-only and was not edited.

Battery and differential numbers. battery.jsonl holds 80 whole-document cases generated by make_battery.py, covering every accepted and rejected value form (percent, px, em, leading and trailing decimals, multi-dot, dot-only, named sizes, pt/rem/vh, negatives, plus signs, exponent and NaN/inf, junk, uppercase values and units, nbsp padding, absent value), opener case and head variants (uppercase, title, mixed, leading space, double space, tab and newline separators, equals form, quoted value, entity and escaped heads, extra closer bracket, attribute-like heads), empty and whitespace bodies, unterminated and stray closers, closer spelling variants, same-rule nested and crossed pairs, the span-shaped family (span, color, strikethrough) in both nest directions and crossed, inline content inside div/blockquote/list/heading, block content inside size, a size scope crossing nested divs, inline bold crossings, code, entities, Unicode, NUL and multiple pairs. The reference harness produced 80 render and 80 token records before and after with empty stderr, and the shared dumper produced 80 records at the recorded HEAD a61ae005d9e837171a3d2b91cf8fc2df7a3d8ae8 with empty stderr. Raw whole-string agreement with ftml rose from 0/80 to 2/80 and structural agreement (frame-level inter-tag whitespace, `<br />`/`<br>`, `<div >`/`<div>` and `&#39;` normalized) rose from 64/80 to 68/80. Render output changed in exactly four cases: sz47-empty-body, sz48-whitespace-body, sz51-space-before-close and sz79-nul-body. Token values in start-id order changed in exactly two cases, sz47 and sz48; the apparent key-by-key diff on 32 later token records is the read-only harness's function-static token id counter shifting after those two pairs are removed, a harness matter disclosed in findings-for-root.txt and normalized in the comparison, not a semantic change. Full before and after diffs are in compare-report-before.txt and compare-report-after.txt.

Probe numbers. Thirty-seven run-owned pages were created on sandbox-for-codex under the disjoint prefix muse-probe-r2contain-size- through scripts/wikidot-probe via scripts/wikidot-python: 26 in probe-cases.jsonl (value-grammar boundaries, head variants, empty and trailing-space bodies, nesting, span/color/bold crossings, div and list interaction), 8 in probe-extra-cases.jsonl (five- and six-character boundaries, multiple spaces, newline, tab and nbsp before the closer, nested empty), 2 in probe-edge-cases.jsonl and 1 in probe-edge2-cases.jsonl (newline-only bodies and internal space before a newline). Every capture is valid=true, stable=true across two independent anonymous GETs and saved_source_matches=true; one whole-map capture hit a transient HTTP 503, so the eight-page batch was recaptured in eight single-page chunks and merged, with the chunk maps, logs and stderr sidecars kept alongside. All pages were left in place and are listed in the four map files. Live HTML was masked once with probe.norm imported through SourceFileLoader as the skill prescribes, cached in the four captures files and reused for every comparison; the corresponding local renders are cached in probe-ref-render.jsonl (before), probe-ref-render-after.jsonl, probe-ftml-dump.jsonl and the three follow-up ref renders. On the 26 main probes, structural reference-versus-live agreement rose from 19/26 before to 22/26 after, ftml-versus-live is 22/26, and all-three agreement rose from 15/26 to 18/26; across all 37 probes the corrected reference agrees structurally with live in 33/37. The render cases that changed on the main probes are empty-body, ws-body and space-before-close, and all eight follow-up boundary and whitespace probes agree with live after correction.

Remaining disagreements and dispositions. Two are candidate ftml divergences for root to route as M-style findings, itemized with evidence in findings-for-root.txt: SIZE-F1 is ftml accepting numeric size values longer than five characters where live and the fossil reject them (long-px, long-pct, boundary-6-em, battery sz11/sz12), and SIZE-F2 is ftml rejecting multi-dot and dot-only numeric values that live accepts (multi-dot, dot-only, battery sz13/sz15). Both are ftml-side and ftml was not edited. Four probe disagreements and eight battery cases are root-owned cross-rule interactions rather than Size divergences: crossed-bold and sz74 re-nest as `<strong><span>...</span></strong>` on live and ftml but cross in the reference's sequential token model; list-in-size, size-crosses-div and sz69, sz70, sz75 reopen the size scope in each block on live and ftml but the reference spans block boundaries; crossed-span and sz57-sz59 differ only by the Span renderer's `<span  class="x" style="">` surface; sz64 differs only by the Div renderer's `<div  class="d">` surface. Live's anonymous serializer inserts pretty-print newlines around block containers and drops the final newline after `<br />` inside a span, and ftml spells the break `<br>` while live and the reference use `<br />`; these are frame-level surfaces owned by later rules and the serving layer and were not emulated here. No serving-layer question arises for Size: its matching, value grammar and display shape are fully observable and deterministic in the anonymous saved-page view, and this rule computes nothing from page or site state.

Questions and assumptions. A question arose about whether the fossil's five-character numeric limit reflected live, because ftml accepts unbounded lengths; the live boundary probes settled it as correct and the assumption to leave the value grammar alone was confirmed, with the ftml side recorded as SIZE-F1. A second question was whether trailing spaces before a newline should be dropped; live internal-space-newline and space-newline-body settled that they are, while newline-close and nbsp-close settled that line breaks and non-breaking spaces are not, and the correction was scoped accordingly. A third question was whether to reproduce the live serializer's newline injection; the assumption proceeded on is that it is later-rule frame surface and structural comparison is the rule-level measure. Only the two owned rule files were touched, no git commit was made, no git identity variable was set, and the read-only ftml checkout was not modified.
