SIZE-F1 (candidate ftml divergence, battery sz11/sz12 and live probes long-px, long-pct, boundary-5-px, boundary-5-pct, boundary-6-em). ftml's legacy wikidot_size_value in src/parsing/rule/impls/block/blocks/size.rs accepts a numeric size whose digit run has unbounded length: the dumper renders [[size 123456px]]X[[/size]] as <p><span style="font-size:123456px;">X</span></p> and likewise for 1000000%. Live Wikidot rejects both: saved-page probes muse-probe-r2contain-size-long-px and -long-pct render the source literally. The boundary is five [0-9.] characters: muse-probe-r2contain-size-boundary-5-px (12345px) and -boundary-5-pct (12345%) render as spans, while -boundary-6-em (123456em) stays literal. The fossil PHP rule's /^[0-9\.]{1,5}(em|px|%)$/ already matches live exactly here, so no reference correction was made and ftml was not edited. Suggested M-style routing: ftml should impose the five-character cap for legacy layout values.

SIZE-F2 (candidate ftml divergence, battery sz13/sz15 and live probes multi-dot, dot-only, trailing-dot). ftml rejects numeric values with more than one dot or with a dot as the entire number: the dumper reports BlockMalformedArguments and leaves [[size 1.2.3px]]X[[/size]] and [[size .px]]X[[/size]] literal. Suggested M-style routing: ftml's wikidot_size_value dot discipline should accept multiple dots and a leading dot-only value to match live Wikidot.
