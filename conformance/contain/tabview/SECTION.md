# R2 Tabview section: differential and correction (2026-11-20)

Mechanism as corrected. The Tabview rule owns `[[tabview]]` / `[[tabs]]` blocks with `[[tab LABEL]] ... [[/tab]]` children, case-insensitive openers and closers, mixed-alias view closers, nesting, and the inline one-line form; it does not own the Paragraph, Span, Div or Collapsible surfaces that appear inside its panels. The fossil skeleton's regex-and-token mechanism is retained: the view opener, each tab head and body token, and the closing script remain the same token stream, and the doubled literal opener text (`[[tabview class="x"]]` renders `class="x" class="x"` before the navset) is live behavior confirmed by probe muse-probe-r2contain-tab-p08 and ftml, not a defect. What changed is confined to the label surface and one PHP 8 guard. Labels now pass through a parse-side normalizer that collapses ASCII whitespace runs to one space, maps a missing or whitespace-only label to the literal word `untitled`, and maps a label carrying raw inline markup (a `@@...@@` / `@<...>@` pair, or a `\xFF`-delimited token placeholder left by an earlier rule) to the empty string; the render then HTML-escapes the label with `htmlspecialchars(..., ENT_COMPAT, 'UTF-8')` and emits a bare `<a href="javascript:;"></a>` for the empty label instead of an `<em>` wrapper. `ENT_COMPAT` is explicit because PHP 8.1 changed the default to `ENT_QUOTES|ENT_SUBSTITUTE`, which would emit `&#039;` where live keeps a raw apostrophe (the same PHP-version issue the NOTES stage routed for Footnoteblock); probes q01 and q02 settle that live escapes `&`, `<`, `>` and `"` but not `'`. The view's `class`, `id` and `style` head values stay ignored by the rule, as on live where they surface only as the doubled literal text. Every shape tested belongs to the container-family Stage 2 re-nesting surface: inline content inside a tab panel and block containers inside a tab panel were recorded against the settled inline-scope model rather than re-derived, and cross-rule containment (div and collapsible inside a tab, tab inside a div, span and bold inside a tab) was exercised but its frame differences are attributed to the owning rules.

Corrections made, with classifications. C1 (fossil-era artifact) is the render-side label escaping just described: the fossil interpolated the raw token option into `<em>`, so `class="c" A`, `A &amp; B` and `<em>x</em>` came out unescaped where live and ftml emit `&quot;`, `&amp;amp;` and `&lt;em&gt;...`; live-settled by probes p04, p05 and p06 and by battery tv09, tv16 and tv17. C2 (fossil-era artifact manifesting as a reference bug) is the bare-anchor branch for a label that resolves to nothing: the fossil's `($tab['title'] ? ... : 'untitled')` turned a deliberately empty label into `<em>untitled</em>` and, for a raw-construct label, leaked the earlier rule's `\xFF` token delimiter into the HTML, which is invalid UTF-8 and made the harness's plain `json_encode` return false, so batch case tv52 produced a blank render line and `"output":false` in tokens mode; live probe p07 and ftml both render `<li class="selected"><a href="javascript:;"></a></li>`, and C2 plus C3 fix the leak in the rule itself with no harness edit. C3 (fossil-era artifact) is the parse-side `_tabTitle()` normalizer: it collapses whitespace runs, supplies `untitled` for an absent label, and returns the empty label for raw or tokenized constructs, settled by probes p02 (`[[tab A  B]]` renders `A B`), p03, p07 and p14 and by ftml's `wikidot_tab_head_label`, `wikidot_tab_head_title_value` and `wikidot_tab_head_has_raw_construct` logic in `src/parsing/rule/impls/block/blocks/tabs.rs`. C4 (PHP version artifact) replaces `if ($attr['class'])` with `if (!empty($attr['class']))` in the parse rule; PHP 8 raises an undefined-array-key warning on a view opener with no attributes (`transform.php` shows it on stderr), older PHP did not, and the change is behavior-neutral.
