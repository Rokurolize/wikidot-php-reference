## Mechanism as corrected

Parse rule (ref-php/text-wiki/Text/Wiki/Parse/Default/Div.php, corrected SHA-256 b4a0386e406fc88e639df1ddc6669743f55d9df9be0e1287c4959ec3351966ff, pre-correction bytes preserved as Div.parse.before.php with SHA-256 a52b4e5bb745b2232c02224cad749cfc42a56040b099888432204c76f8155c7d). The rule matches a block-div opener at the start of a physical line whose body begins on the next line and whose first same-type closer ends it, using a recursive body group that keeps first-closer discipline. The corrected regex adds a capture for the scored alias marker, so a standalone [[div_]] or [[div_ attrs]] opener now forms a div just like the unscored form; this is the Concatlines N1 residual settled here. The attribute head is restricted to Wikidot's allowlist class, id, style, role, type and data-* with case-sensitive names; data-* names are lowercased with first-wins duplicate handling, id values are isolated with the u- prefix (whitespace-only becomes u-, already-prefixed values are unchanged), every value has control characters dropped and whitespace runs collapsed to one space, class values lose trailing spaces, empty-valued attributes are dropped, and emitted attributes are sorted by name to match live's spelling. An empty div with no effective attribute is suppressed entirely and leaves only its surrounding blank line. The scored form's body is paragraph-stripped: leading and trailing newlines are removed, blank-line runs disappear, and single newlines remain for the Linebreak rule; nested scored divs keep their separator because the scored form emits its captured leading newline once rather than twice. The fossil's removal of visibility:hidden and display:none from style is gone, because live keeps hidden styles.

Render rule (ref-php/text-wiki/Text/Wiki/Render/Xhtml/Div.php). This file was not edited and is byte-identical to its pre-correction state (SHA-256 dcfe6d17df673a8730cfd49852ef3a744706e8e1bce9c7ab9efcb29855071cec, preserved as Div.render.before.php). It still renders a start token as an open tag with the parsed attribute string and an end token as a closing tag. The fossil's '<div >' wrapper with its trailing space, and the corresponding double space before an attribute, are frame-level surface owned by the later Tighten and purifyHtml rules as the BLOCK stage settled; no render-side correction was made for them.

## Corrections made

C1 (fossil-era artifact that is also a reference bug). The fossil's regex /(\n)?\[\[div(\s.*?)?\]\] *\n.../ could not match a scored opener because it required whitespace or the closing bracket immediately after div, so a standalone [[div_]] form stayed literal in the reference while live and ftml rendered a paragraph-stripped div. The regex now captures the optional underscore and the process method paragraph-strips the body for that form. Live evidence is the score-basic, score-attr, score-two-lines, score-empty, score-attr-empty, score-attrs-full, score-attrs-id, score-uppercase and score-inline probes under this prefix, with the ftml pins test/div/basic and test/div/attribute-allowlist.

C2 (fossil-era artifact that is also a reference bug). The fossil kept only class and style, never isolated ids, and preserved raw attribute names and values, while live and ftml emit the full allowlisted set with u- id isolation, lowercase data-* names and normalized values. Evidence is the attr-allowlist, attr-allowlist-mixed, attr-id, attr-id-prefixed, attr-id-space, attr-data-empty-suffix, attr-class-space, attr-role-type, attr-data, attr-dupe-data, attr-single-quote and attr-unquoted probes and the corresponding ftml pins.

C3 (reference bug). The fossil always emitted an empty <div></div> for an opener/closer pair with no content and no effective attribute, while live and ftml drop the container and leave the blank line. Evidence is the empty-plain and empty-at-eof probes and the ftml pins test/div/empty-attributeless-vanishes and empty-attributed-stays.

C4 (fossil-era artifact). The fossil stripped visibility:hidden and display:none from style, while live and ftml keep hidden styles verbatim; the ftml pin test/embed/wikidot-iframe-styleframe-name-div/wikidot.html renders <div style="display:none"> for [[div_ style="display:none"]], and the attr-style-hidden-display, attr-style-hidden-vis and attr-style-hidden-mixed probes confirm it. All four corrections are confined to the parse file; the render file stayed byte-identical and both files pass php -l.

## Remaining disagreements, dispositions, and candidate findings

Class S (frame-level surface owned by later rules, not Div divergences and not corrected): the reference's <div > wrapper and <div  attr="..."> double-space spelling against live's <div> and single space; <br /> versus <br> spelling; the reference's <p> wrapper around otherwise bare text against live's bare text plus <br> at a vanished empty div's line; pretty-print newlines around block containers; and the Tabview owner's injected YAHOO script block in div-in-tabview and nested-in-tab, which that owner explicitly classifies as frame-level later-rule and serving-layer surface. The earlier Collapsible '- hide block' against en-dash '– hide block' difference inside div-in-collapsible and scored-in-collapsible belonged to the pre-correction state: after the Collapsible owner landed its render correction at 14:45, both battery cases and the div-in-collapsible probe are all-three with live's class-based frame and en-dash &nbsp; labels, so no Div-side residual remains there. Root's harness audit disclosed that Collapsible::$count and Tabview's private static $_counter leak across batch cases, so counter-bearing ids are normalized in compare.py and no id shift was scored as a correction. No serving-layer scope gap arose because all 35 saved sources matched byte-for-byte; source shapes Wikidot would rewrite on save were not used.

DIV-F1 (candidate ftml divergence, route to root for M-style numbering). For a scored div holding a nested scored div followed by trailing text (`[[div_]]` / `1` / `[[div_]]` / `2` / `[[/div]]` / `3` / `[[/div]]`), live and the reference both keep a break after the inner div while the shared ftml dumper drops it: live renders `<div>1\n<div>2</div>\n<br />\n3</div>` (probe muse-probe-r2contain-div-nested-scored, saved source byte-matching and stable across two anonymous GETs), the corrected reference renders `<div >1<br />\n<div >2</div><br />\n3</div>`, and ftml renders `<div>1\n<div>2</div>\n3</div>`. Under the settled inline-scope model this sits at the Stage 1 block-div pairing plus Stage 2 re-nesting seam: the reference's Linebreak rule places its break before the nested div while live's purifyHtml pass places it after, and ftml emits none, so the surviving three-way split may ultimately prove to be frame surface; I record it as a candidate ftml divergence with evidence rather than calling either local side wrong, and made no Div edit for it. No other candidate ftml finding arose from this rule's battery or probes.

The Concatlines stage's N1 residual is settled here: live and ftml both render a standalone [[div_]] opener as a real paragraph-stripped div, the corpus pins confirm the same shape, and the corrected reference now recognizes it; the earlier Concatlines continuation case a\\\n[[div_]] also now agrees structurally, so no residual is handed back.

Questions recorded rather than silently resolved: the vanished empty div leaves a <br> on live but no <br> in the reference's paragraph frame, which is unfixable inside Div.php without crossing the Paragraph rule's token contract and is recorded as class S; the Collapsible and Tabview surface differences inside div nesting belong to those owners and were not touched; and the hidden-style stripping was settled by a corpus pin rather than by a probe because test/embed carries a live wikidot.html for exactly that shape.
