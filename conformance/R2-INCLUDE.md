# R2 Include rule: first differential and correction catalog (2026-11-20)

Method: the reference harness (ref-php/harness/batch.php, expand mode: only the Include rule runs, expanded source out) against the two live-derived baselines built by the G1.4/G1.4b work: the 14 G1.4b probe expectations (live renders, expected-live.jsonl) and the 114-case G1.4 grid (ftml outputs, rust-out.jsonl; ftml there is live-verified except for finding F-G14B-1 shapes, which the grid avoids). Page maps are identical on both sides (harness/pages.php). Live authority is GRAMMAR-INCLUDE.md (S/G/Q/R/X rules); the fossil text is the hypothesis under test.

## Headline results

- Substitution (the fold): the reference matches live on 14/14 G1.4b probes, byte-identical content including the cycle (e5) and self-then-second (e14) shapes. The only difference is the fossil's unconditional "\n\n" splice padding (class P below).
- Grid: 73/114 cases agree textually after line-ending and padding normalization. The remaining 41 fall into the classes below; roughly a dozen of those are disposition-equal (classes P and M) rather than behavioral divergences.

## Classes

P. Padding convention (not a divergence). The fossil pads every splice with "\n\n" on both sides, unconditionally. ftml's include() pads with one line ending per side only where caller text exists (G1.3 rules U1-U6). Both are their own pipeline's convention and converge at render in the probed shapes. The Lean G1.3 splice model follows ftml (its subject); no action.

M. Includer surface (not a rule divergence). For a missing page the fossil emits the production error block as wikitext ("\n\n[[div class=\"error-block\"]]\nPage to be included %s can not be found!\n[[/div]]\n\n"); the grid's ftml side emits the DebugIncluder marker <MISSING-PAGE %s>. Cases: missing, missing-mid, colon-page, multi-colon (multi-colon additionally differs in normalization: fossil keeps 'a:b:c', ftml's normalize merges earlier colons to 'a-b:c', an R-layer item under C4). No action on the rule; the comparator should treat these as disposition-equal.

C1. Line endings (CORRECTED 2026-11-20, refined the same day). The fossil Include regex anchors ]] at end-of-line, so no include fired on CRLF text (5 grid cases). Prefilter (rule 2) normalizes all line endings to \n, but runs after Include. Correction, final form: the harness input stage normalizes \r\n to \n only (batch.php and transform.php). A lone \r is NOT normalized: it is still present at the Include stage in the fossil's pipeline order (Prefilter converts it afterwards, for downstream rules), and the scanner/grammar split treats it asymmetrically, which the rewritten rule mirrors exactly: the scanner's \s+ admits \r but its line starts and candidate end (S4) do not; the block grammar's whitespace excludes \r while its terminator (G1) admits a lone \r. The first C1 form (full normalization) scored worse (it fired on cr-after, term-cr-eof, cr-no-line-start, q-cr-term, where ftml stays literal); the refined form plus the C2 rewrite agrees on all of them. ftml's include() preserves \r\n in caller text where the reference is \n-normalized; that is a whole-pipeline Wikidot convention (Prefilter), not an Include rule property.

C2. Scanner shape (CORRECTED 2026-11-20). The rule's regex scanner is replaced by a hand scanner implementing the adjudicated grammar (refExpandPass / refFindCandidate / refParseBlock / refSegments in the rewritten Include.php), keeping the fold, the fetch, the error block, and the recursion loop. Two mechanics the grid forced during the rewrite: the Q3 fallback is the unquoted parse from the line start (which the '>' prefix makes fail), not a parse from the match (q-broken-continuation); and the scanner/grammar whitespace and terminator split of C1 is implemented as two distinct sets. Sub-shapes as originally cataloged, all fossil-literal or fossil-reject where live/ftml accept:
- Opener whitespace: the fossil regex has one literal space after "include"; live admits \s+ including tabs and newlines (multi-space, tab-after, newline-after, double-newline-after).
- Page-name charset: [a-zA-Z0-9\s\-:] rejects '.', '_', '#', '/' (dotted-page, underscore-ref, template-ref, host-as-page, extra-hash, extra-slash, default-cat).
- Terminator and resumption: a failed candidate in ftml consumes through the first valid terminator (term-x-then-other: both includes stay literal); the fossil regex retries per line independently. term-cr-in-tail: the fossil's lazy tail over-consumes a second ]].
- Argument segments: the fossil splits the tail with explode('|') and no comment awareness (arg-comment-pipe loses the comment's tail and the pipe inside a comment splits); an unterminated comment is a whole-block parse failure live/ftml, but the fossil includes anyway (arg-unterminated-comment). Stray bracket tolerance (stray-* cases) currently agrees in content.

C3. Quoted includes (CORRECTED 2026-11-20, same rewrite: refQuotedAttempt with candidate-end then whole-region bounds, prefix stripping, and offset mapping back to the original text). The fossil has no quoted-include mechanism: unspaced quoted forms (>[[include ...]]) stay literal in the reference, while live silently deletes the consumed range (GRAMMAR Q1-Q3, the adjacency condition). 13 grid cases (q-* and multi-mixed). In production this behavior lives in the include layer around the parser; the reference adds it to its Include stage per the adjudicated Q rules.

C4. Reference resolution and cross-site fetch (CORRECTED 2026-11-20). The fossil resolved every ref against the current site only, after WDStringUtils::toUnixName. The rule now carries the R layer directly (refResolveRef, refSplitPage, refCanonicalSite, refNormalize in Include.php: parse_include's structure, split_page extras, the .wikidot.com canonicalization, and wikidot-normalize's step order implemented in PHP), and the stub DB grew selectBySiteAndName with Display-form keys. One structural deviation from ftml, by live evidence: malformed site forms fall back to whole-run-as-page instead of erroring (the L6 / C5 disposition). The toUnixName sub-differential is thereby closed for the include path: the reference no longer routes refs through toUnixName at all. refNormalize is exact for ASCII; non-ASCII is bounded (this PHP has no intl or mbstring: no NFKC, ASCII-only case fold), the same fragment bound as the G1.4 Lean driver. All 6 site grid cases and all 9 normalization/extra cases now resolve to ftml's exact page names; their remaining textual diff is class M only. site-empty-page (:sandbox:) resolves by the fallback to 'sandbox' (the fossil's disposition); ftml leaves it literal. Unprobed against live; recorded as an open sub-shape, not silently harmonized.

C5. Colon-edge refs (ADJUDICATED 2026-11-20, live probes). ::page and :foo: ftml rejects them as non-includes (parse_include Err, text stays literal); the fossil trims the colons and treats them as includes of 'page'/'foo'. Live agrees with the FOSSIL's disposition: three sandbox pages (muse-probe-c5-double, muse-probe-c5-single, muse-probe-c5-plain; all captures valid, stable, saved_source_matches=true; evidence conformance-refphp/c5/captures.json) render [[include ::page]] and [[include page]] as the identical missing-page error for "page", and [[include :foo]] as the missing-page error for "foo". So the C2 scanner rewrite must NOT import ftml's parse_include rejection for these shapes; leading-colon page refs resolve to the stripped page name. This is an ftml-vs-live divergence in its own right, recorded as finding F-R2-1 and routed to the Wikijump-side chat. One surface difference the same probes exposed: live's missing-page message is the current text 'Included page "page" does not exist' with a create-it-now edit link, where the fossil's message is the older 'Page to be included %s can not be found!'. The disposition (error block, stripped name) matches; the message text is a separate small correction (class M update, render-level target recorded in the C5 captures).

## Pipeline-frame notes (for later R2 stages)

- Prefilter (rule 2) also: expands tabs to 4 spaces, empties whitespace-only lines, prepends \n and appends \n\n, compresses 3+ newlines to 2, strips the üü sequence. Tab expansion in particular is a whole-pipeline Wikidot convention with no ftml counterpart at the parse layer; flag for the Tier 2/3 work, not for the Include stage.
- The fossil Include parse() recurses its substitution up to 5 passes (nested includes expand level by level). ftml's include() is one pass by design (deepwell re-invokes). The reference keeps the fossil recursion; the Lean models target ftml's single call, so this is a pipeline-frame difference, recorded here rather than harmonized.
