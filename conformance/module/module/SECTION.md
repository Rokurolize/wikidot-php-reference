# R2 Module rule: differential, correction, and section (2026-11-20)

Method. I compared three sides over one 52-case battery and one 20-case live probe set. The reference side is the shared read-only harness ref-php/harness/batch.php in modes render and tokens (outputs ref-render-before.jsonl / ref-render-after.jsonl, ref-tokens-before.jsonl / ref-tokens-after.jsonl, ref-probe-render-before.jsonl / ref-probe-render-after.jsonl, ref-probe-tokens-before.jsonl / ref-probe-tokens-after.jsonl, with empty stderr throughout). The ftml side is the one shared dumper at conformance-refphp/module/rust-dump/target/release/r2module-rust-dump, run over the same battery and probe sources at the read-only checkout HEAD 97bed049ddeadc54981f6d9577bd78fcb212abd9 recorded in conformance-refphp/module/rust-dump/FTML-HEAD.txt (ftml-dump.jsonl and ftml-probe-dump.jsonl). The live side is 20 saved anonymous page views on sandbox-for-codex.wikidot.com under prefix muse-probe-r2mod-module-, created and captured with the bundled wikidot-probe CLI (probe-cases.jsonl, probe-map.json, captures.json, probe-create.log, probe-capture.log); all 20 are valid, stable=true and saved_source_matches=true. Probes use LF-only sources with trailing newlines stripped because Wikidot normalizes them on save (an initial attempt with trailing newlines and a trailing-spaces case failed read-back verification); the whitespace forms stay in the local battery, where the harness's Prefilter and ftml's preprocess normalize them. Evidence order when sides disagreed was ftml corpus pins, then frozen captures, then live probes; live behavior won every disagreement. The battery and probe sources are reproducible with make_battery.py and the side-by-side probe view with compare.py in this directory.

## Mechanism as corrected

Parse rule (ref-php/text-wiki/Text/Wiki/Parse/Default/Module.php). The rule still matches `[[module Name attr]]` openers at a line start, with case-insensitive names in [a-z0-9_\-/]+, an optional raw attribute string, zero or more spaces then a newline after the opener, and an optional body closed by `[[/module]]`. It still loops preg_replace_callback until the source stops changing, still applies the self-nesting defense that rewrites a match containing more than one opener to `[[module654`, trims moduleName, attr and body, and emits `"\n\n" . addToken(...) . "\n\n"`. The one correction is that the optional body group now requires at least one body character (`(.+?)` instead of `(.*?)`): an empty body no longer consumes the `[[/module]]` closer, so the closer survives as literal text, which is what live renders for both unknown and known modules. Live also accepts names with a leading digit, a leading underscore, a leading hyphen or an internal slash (all produce the unknown-module error block), so the fossil's name charset is live-correct and was left untouched; ftml is the side that rejects these. The harness's shared Prefilter pads the source with a leading and two trailing newlines and converts lone CR to LF, so no-newline, CRLF, lone-CR, tab-after-opener and spaces-then-newline openers all match in the reference; ftml agrees, and this is a shared frame/harness matter, not a Module-rule divergence.

Render rule (ref-php/text-wiki/Text/Wiki/Render/Xhtml/Module.php). For a module this site cannot use (the root-owned harness stub returns false for every name outside ftml's nine known names), the rule now emits the live unknown-module error block verbatim: `<div class="error-block">[[module <em>NAME</em>]] No such module, please <a href="https://www.wikidot.com/doc:modules" target="_blank">check available modules</a> and fix this page.</div>`. The `<div class="error-block">` wrapper still comes from renderError(). For a module the site can use, the rule still emits the fossil `\xFE module "<template>" <urlencoded attr> \xFE` handoff marker (rendered as `þ` in the output); its serving-layer expansion is out of scope in this loop. Because Text_Wiki_Render_Xhtml_Module654 extends this class without overriding token(), the error-block correction also applies to module654 unknown names, and live confirms that shape.

## Corrections made

C1 (fossil-era artifact, manifesting as a reference bug). The fossil render rule used the old wording "Module <em>%s</em> does not exist or can not be used within this site." Live saved-page probes muse-probe-r2mod-module-mod-unknown, -mod-unknown-mixed, -mod-attr-on-unknown, -mod-name-leading-digit, -mod-name-leading-underscore, -mod-name-slash and -mod-probe-module654-basic all show the "No such module" block above with a doc:modules link and no rel attribute, byte-for-byte; ftml's wikidot_unknown_module_error matches it. Replaced the message string and kept the renderError wrapper and gettext call. This changed 14 battery render outputs, all unknown-module cases.

C2 (fossil-era artifact, manifesting as a reference bug). The fossil body group `(.*?)` consumed an empty `[[/module]]` closer. Live probes muse-probe-r2mod-module-mod-probe-unknown-empty-body and -mod-probe-known-empty-body both show the closer surviving as `<p>[[/module]]</p>`, and ftml's own corpus pin test/module/css-empty-module-paragraph-break/wikidot.html shows the same literal closer for a CSS module. Requiring one or more body characters fixed this and changed 3 battery outputs (mod-body-empty, mod-two-adjacent-body, mod-nested-two-openers) plus both empty-body probes; non-empty bodies, unterminated blocks, stray closers, mid-line/leading-space openers and the self-nesting rewrite are unchanged. Pre-correction bytes are preserved as Module.parse.before.php and Module.render.before.php (SHA-256 9b9922673c43eab and 042ac14ab263491c).

No PHP-version artifact and no harness matter required a correction. One question arose: a body consisting only of whitespace would still satisfy `(.+?)` after the harness Prefilter strips whitespace-only lines, so the closer could still be consumed there; I proceeded on the assumption that live treats such a body as empty and that the general live rule is "empty body leaves the closer literal", and recorded the residual as an open edge rather than inventing a correction.

## Battery and probe numbers

The battery is 52 cases. Before correction, 17 of 52 render outputs differed from the corrected tree (14 from C1, 3 from C2). After correction, 17 of 52 match ftml exactly once frame-level trailing whitespace and `<br />` versus `<br>` are normalized; 21 of 52 differ only by serving-layer marker versus TODO-placeholder surface (known module names, attributes, module bodies and opener-newline variants); 5 differ by the name-charset issue F1; and 9 remain in the body/closer/cross-rule group described below. No battery case errored on either side. The 20 live probes split, after canonicalizing the known-module marker, the TODO placeholder, live's module widget HTML and the rel attribute, as 14 agreed by all three sides, 4 where the corrected reference and live agree but ftml diverges (F1 in three, F3 in one), 2 where ftml and live agree and the reference differs only by the out-of-scope marker, and 0 where all three disagree.

## Remaining disagreements, dispositions, and candidate findings

Class S (frame-level surface owned by later rules, not Module divergences): the fossil `\xFE` marker versus ftml's `<p>TODO: module X</p>` versus live's real module widget HTML (probes mod-basic, mod-body-present, mod-probe-known-empty-body, mod-probe-nested); the trailing `\n\n` the reference leaves around literal and block content; the one inter-block space live keeps between a module box or error block and a following literal closer; ftml's `<br>` versus the reference's `<br />`; and the reference's verbatim typed module name in the marker versus ftml's canonicalized name. All are serving-layer expansion or join/surface shaping and were not corrected.

F1 (candidate ftml divergence, route to coordinator). ftml's `wikidot_valid_module_name` at src/parsing/rule/impls/block/blocks/module/rule.rs requires the first byte to be an ASCII letter and rejects `/`, so `[[module 123abc]]`, `[[module _foo]]`, `[[module -foo]]`, `[[module foo/bar]]` and `[[module foo/bar-baz_qux]]` stay literal paragraphs in ftml, while live renders the unknown-module error block for the first, second and fourth (probes muse-probe-r2mod-module-mod-name-leading-digit, -mod-name-leading-underscore, -mod-name-slash) and the corrected reference does the same for all five. The fossil regex is live-correct here; no reference change was made.

F2 (candidate ftml divergence, route to coordinator). ftml emits two different unknown-module error blocks: without a rel attribute from wikidot_unknown_module_error, and with `rel="noopener noreferrer"` from render/html/element/module.rs when the body starts on the next physical line (Module::Runtime). Live uses the no-rel shape in both cases (probes muse-probe-r2mod-module-mod-unknown and -mod-body-unknown-newline), and so does the corrected reference; the battery shows this on mod-body-unknown-newline and mod-nested-unknown-in-body.

F3 (candidate ftml divergence, route to coordinator). For an unknown module with an empty body, ftml consumes the `[[/module]]` closer and emits the rel-bearing error block, while live emits the no-rel error block plus the literal closer (probe muse-probe-r2mod-module-mod-probe-unknown-empty-body); the corrected reference matches live. ftml's known-module empty body already agrees with live on its own css-empty-module-paragraph-break pin.

Cross-rule note for the root (not a Module-rule finding): the self-nesting defense on `[[module css]]\n[[module rate]]\n[[/module]]` produces Module plus Module654 tokens in the reference, while ftml parses both as nested modules and the live probe muse-probe-r2mod-module-mod-probe-nested renders an empty page body; module654-vs-module adjacency and alias-closer cases in the battery (mod-adjacent-module654, mod-module654-module-closer, mod-module-opener-module654-closer, mod-two-adjacent-body) are likewise left for the root's cross-rule integration. No ftml file was edited.
