## Mechanism as corrected

Both Modulepre files are unchanged from the canonical record; the rule needed no correction. The parse rule (ref-php/text-wiki/Text/Wiki/Parse/Default/Modulepre.php) is a pure source-rewriting prefilter: its regex /^\[\[module654\s([a-z0-9_\-\/]+)(\s+.*?)?\]\](?:(.*?)\[\[\/module\]\])?/ims matches a line-start [[module654 NAME attr]] opener with an optional body to [[/module]], and process() rewrites only the leading [[module654 to [[module. It emits no tokens, which is why the render rule (Render/Xhtml/Modulepre.php) has an empty token() and the token dumps show no Modulepre tokens. This rewrite is not a fossil curiosity: live saved pages show it directly. Probe no-newline-literal renders a source [[module654 css]]text as the paragraph <p>[[module css]]text</p>, and probes inline-body and unknown-inline-tail likewise show the rewritten module spelling in otherwise-literal output, while probes trailing-spaces, upper-case and mixed-case openers show that the rewrite's exact line-start and case boundaries are also live-correct where it fires. Leading-digit and slash-containing names are claimed live (error blocks) exactly as the fossil name charset claims them, so there is no name-charset correction to make here. The module654-only uppercase forms that Modulepre does not touch are owned by Module654 itself.
