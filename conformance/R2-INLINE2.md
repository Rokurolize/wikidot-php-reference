# R2 Colortext, Strong, Emphasis, Underline, and Strikethrough stage: differential and correction catalog (2026-11-20)

Method. This stage runs as a team of five rule owners plus a root coordinator, one owner for each of the forty-fourth through forty-eighth pipeline rules in this batch: Colortext, Strong, Emphasis, Underline and Strikethrough, the paired-marker emphasis family plus the color span. It follows the four-owner R2-INLINE1 stage that opened the inline family. The loop is building a PHP reference implementation that reproduces live Wikidot behavior, the fossil Text_Wiki snapshot corrected rule by rule against live evidence: the fossil is a skeleton and never evidence, live Wikidot behavior is definitionally correct, and the evidence order is ftml corpus pins first, then frozen captures, then live sandbox probes, with fetching from live pre-approved and cached once. Earlier stages are published as the catalogs conformance-refphp/R2-INCLUDE.md, R2-FRAME.md, R2-CODE.md, R2-FORM-RAW.md, R2-MODULE.md, R2-NEXT.md, R2-LINK.md, R2-NOTES.md, R2-BLOCK.md, R2-CONTAIN.md, R2-LIST.md, R2-TABLE.md, R2-PARA.md and R2-INLINE1.md, and this catalog imitates their shape. The shared reference harness (ref-php/harness/batch.php in expand, render and tokens modes, transform.php for the smoke run, pages.php and ozone-stubs.php) is read-only for rule owners; root owns it and any stub or reset it needs, and discloses changes here. Before any differential started root built ONE shared ftml dumper at conformance-refphp/inline2/rust-dump/ in the Form/Raw stage's style (preprocess_for_layout, tokenize, parse, HtmlRender over JSONL {"id","source", optional "tags"}) against the read-only ftml checkout at /home/roku/src/Rokurolize/ftml and recorded its HEAD beside it in FTML-HEAD.txt; every cargo invocation went through tools/heavy-build.sh with HEAVY_BUILD_NO_SPLIT=1 as a polled background job. Each owner built an at-least-40-case whole-document battery, ran the reference before and after correction and the shared dumper over it, probed live under its own disjoint prefix (muse-probe-r2in2-color-, muse-probe-r2in2-strong-, muse-probe-r2in2-em-, muse-probe-r2in2-u- and muse-probe-r2in2-strike-), and wrote its SECTION.md ending in COMPLETE or a BLOCKED: reason; corrections landed only in that rule's own parse and render files, with pre-correction bytes preserved as <File>.before.php. Root owns the cross-rule interactions, the catalog and the smoke battery, and probes live under muse-probe-r2in2-x- where the sections leave an interaction unsettled. The two-stage inline-scope model (the 2026-11-04 ruling recorded in MEMORY and exercised in the CONTAIN and LIST stages) is standing context: these paired markers pair in source text at Stage 1 and are re-nested by the Stage 2 repair stack where several of them render as the same span tag; this stage owns the reference's Stage 1 behavior, and crossings that only Stage 2 can settle are recorded as frame-level, not patched. Two inherited residuals are settled here: the Colortext owner resolves the trailing semicolon in the reference's color style, and the Strong owner settles which layer clips a strong span at a table cell boundary. Prose in this catalog and in every SECTION.md is written as flowing paragraphs on single lines, never hard-wrapped at a fixed column.
