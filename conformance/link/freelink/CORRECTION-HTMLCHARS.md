Reference correction to Freelink escaping (2026-11-22), settled by the live probes muse-probe-htmlchars-fl-label, fl-url, fl-anchor and fl-extra (all valid, stable, saved_source_matches), which drive an apostrophe through every string the renderer escapes: the pipe label (`O'Brien &amp; <x> "q" é` renders with the apostrophe raw, the authored entity double-encoded to `&amp;amp;`, and <, >, " escaped), the bare-URL target and its label (apostrophe raw in both href and text), the anchor suffix (`#an'chor&x` renders as `#an'chor&amp;x` in the href), and the /#/ hash-route suffix (apostrophe raw). Live's spelling is exactly `htmlspecialchars(..., ENT_COMPAT, 'UTF-8')` on every one of these surfaces. The fossil's Render/Xhtml/Freelink.php used bare `htmlspecialchars()` at all seven call sites (text in the URL branch, text in the unreachable site branch, text in the main branch, url, page, anchor, extra), which on the harness's PHP 8.5.4 defaults to ENT_QUOTES|ENT_SUBSTITUTE and spelled every reachable apostrophe `&#039;`. The change is confined to Render/Xhtml/Freelink.php: all seven calls now pass ENT_COMPAT, 'UTF-8'. The page call's input is the WDStringUtils::toUnixName slug, which cannot contain an apostrophe, and the site branch is unreachable after the R2-LINK parse correction; both were converted with the rest so no bare call remains in the file, and neither conversion changes any output. The only behavioral difference from the bare call besides the apostrophe is invalid-UTF-8 handling (empty string instead of U+FFFD substitution), unreachable because every escaped string is a substring of a saved page's UTF-8 source or a slug derived from it.
