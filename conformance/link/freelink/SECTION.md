# R2-link Freelink rule: differential, correction, and section (2026-11-20)

Method. I compared three sides over one 60-case battery and one 35-case live probe set. The reference side is the shared read-only harness ref-php/harness/batch.php in modes render and tokens, run before and after correction into ref-render-before.jsonl, ref-render-after.jsonl, ref-tokens-before.jsonl and ref-tokens-after.jsonl, with matching probe counterparts ref-probe-render-before/after.jsonl and ref-probe-tokens-before/after.jsonl and the one-case extra-probe files ref-probe-extra-render-after.jsonl and ref-probe-extra-dump.jsonl; all stderr sidecars are empty. The ftml side is the shared dumper conformance-refphp/link/rust-dump/target/release/r2link-rust-dump run over the same sources at the read-only checkout HEAD 97bed049ddeadc54981f6d9577bd78fcb212abd9 recorded in the dumper's FTML-HEAD.txt, into ftml-dump.jsonl and ftml-probe-dump.jsonl, both with empty stderr. The dumper's HtmlRender call has no page-existence resolver, so it always emits the existing-page shape and never emits newpage; existence polarity is therefore compared reference-versus-live only, exactly as the stage brief states. The live side is 35 saved anonymous page views on sandbox-for-codex.wikidot.com under prefix muse-probe-r2link-free-, created and captured with the bundled wikidot-probe CLI through scripts/wikidot-python (probe-cases.jsonl, probe-map.json, captures.json, plus the late one-case probe-extra-cases.jsonl, probe-extra-map.json and captures-extra.json, and the create/capture logs); all 35 are valid, stable and saved-source-matching, and their sources were fetched once and cached. I also created the two exact target pages muse-probe-r2link-free-exists and muse-probe-r2link-free-exists2 (target-cases.jsonl, target-map.json, target-create.log) so live mirrors the root-owned reference existence map in pages.php. Evidence order when sides disagreed was ftml corpus pins, then frozen captures, then live probes; live won every disagreement it settled. The battery is reproducible with make_battery.py, the probe set with make_probes.py, and the side-by-side reports with compare.py and compare_probes.py; the corrected parse rule is reproducible from its preserved before-bytes with gen_parse_fix.py, which embeds the transliteration table read from ftml's read-only src/parsing/rule/impls/link_triple_transliteration.rs. No ftml file, shared harness file, git commit or git identity variable was changed by this owner.

## Mechanism as corrected

Parse rule (ref-php/text-wiki/Text/Wiki/Parse/Default/Freelink.php). The rule still matches a triple-bracket opener and closer anywhere on a line, but the matcher is now one non-bracket target followed by an optional pipe label in which further pipes are allowed, instead of the fossil's bracket-and-pipe-free page plus alpha-initial hash anchor plus pipe-free label. Processing now peels a hash anchor or a /#/ hash-route suffix off the target, rejects the genuinely empty target and the anchor-only target without a leading space as literal (live leaves [[[|Label]]], [[[#a|L]]] and [[[#a]]] untouched), rejects the malformed multi-hash forms home###, a##b and a#b#c as literal, and keeps a leading : or / in the auto display text of a bare target. A bare URL with no leading space is recognized as an external target, while a leading-space URL remains a local slug as live and the corpus pin test/link/triple require. Non-ASCII target characters are transliterated through the 468-entry table ftml uses for legacy triple links, with unmapped characters acting as separators, and a leading _default: category is dropped; the old fossil rule that stripped a leading underscore and set a nonbr option is gone because live preserves that underscore. All live-settled shapes are recorded in corrections C1 through C7 below.

Render rule (ref-php/text-wiki/Text/Wiki/Render/Xhtml/Freelink.php). The class still extends the shared Wikilink renderer, but now overrides token() for two live-settled differences. It emits an external href for a URL target, and it appends the anchor plus any hash-route suffix to the href in both the existing-page and new-page branches; the inherited Wikilink renderer appended the anchor only for existing pages, so a new page with [[[scp-series#section|Label]]] lost its #section on live and ftml keep it. Everything else is preserved from the parent: the existence callback, the newpage CSS class and empty new_text from the shared wiki-config.php, the internalLinksExist/NotExist bookkeeping, the new_text_pos handling, and the fossil textFromTitle page-title lookup that enters on an empty pipe label.

## Corrections made

C1 (fossil-era artifact manifesting as a reference bug; parse before SHA-256 879da7397cf8f39e4b9285120eed70a05caba04abf65298da30aa902bb2281e1 and render before SHA-256 e729cda5d141e8966db6a74062cfa5a29de0a0cb93550f2e4588e76a268dca8b). The fossil anchor subpattern required an ASCII letter immediately after #, so [[[scp-series#001|...]]] and the bare [[[scp-series#001]]] fell to literal, and the inherited Wikilink new-page branch omitted the anchor from the href for alpha, dash, underscore and colon anchors. Live probes p-anchor-digit, p-anchor-alpha, p-anchor-dash, p-anchor-underscore, p-anchor-colon, p-anchor-plain and p-anchor-label-only-space, together with the corpus pins test/link/triple and test/link/triple-anchor-spaced, settle the full shape. The parse side now peels any #suffix off the target and the render side appends it in both existence branches. This changed eight battery render records and seven probe render records. A question recorded here rather than silently resolved: live's [[[ # | Label ]]] form maps to /#, which the corrected rule produces, but a bare [[[#a|L]]] with no leading space is literal on live and is guarded explicitly because ftml's own rule rejects it there.

C2 (fossil-era artifact manifesting as a reference bug, same preserved before bytes). The fossil label subpattern excluded pipes, so [[[page-slug|A|B|C]]] fell to literal; live and ftml render the label A|B|C with the page slug page-slug. The probe pair p-dup-pipes and p-dup-pipes-spaced and battery cases dup-pipes and dup-pipes-spaced settle it, and the corpus pin test/link/triple carries the same shape. The matcher now lets the label contain every non-bracket character including further pipes, while the first pipe still separates target from label.

C3 (fossil-era artifact plus harness matter, same preserved before bytes). The fossil process() split a :: target into a site and a page and the inherited renderer then read GlobalProperties::$URL_DOMAIN, which the shared harness does not define, so [[[site::page|Label]]] fataled in the reference. Live probe p-fossil-cross renders it as a local slug /site:page, and ftml agrees; WDStringUtils::toUnixName already collapses :: to a single colon. I removed the :: special case so the target is normalized locally, which both fixes the shape and removes the harness fatal without editing shared files. Battery cases fossil-cross-site and fossil-cross-site-no-page moved from fatal errors to local links.

C4 (fossil-era artifact, same preserved before bytes). The fossil stripped a leading underscore from every target and set a nonbr display flag, an old Text_Wiki convention that live no longer follows: probe p-underscore renders [[[_some-page|Label]]] as /_some-page, not /some-page. The fossil also left a leading _default: category in the slug, while probe p-default-category and corpus pin test/link/triple-colon-keep show /a. Both behaviors were replaced with live-shaped handling in the parse rule.

C5 (fossil-era artifact, both files, same preserved before bytes). The fossil had no notion of a URL target or a /#/ hash route, so [[[https://example.com/|Example]]] became the local slug /https:example-com and [[[MAIN/#/page|Hash routing]]] fell to literal. Probes p-url-plain, p-url-trailing-space and p-url-hash-route, backed by corpus pins test/link/triple and the inline assertions in ftml's link_triple.rs, settle the external href and the /main#/page shape. The parse rule now recognizes the URL only without a leading space and carries a hash-route suffix out to the renderer. A star-prefixed external target would additionally need target="_blank" on live; that shape is not in this battery and is left as a coverage note rather than an invented correction.

C6 (fossil-era artifact, same preserved before bytes). The fossil called WDStringUtils::toUnixName directly on a non-ASCII target, which yields an empty slug, while live transliterates Cyrillic, Greek and Latin names through an explicit table. Probe p-cyrillic settles [[[документ]]] as /dokument and corpus pins test/link/triple-slug-transliteration, triple-cjk-page and triple-slug-compat cover the wider family. The corrected parse rule embeds ftml's 468-entry table as PHP data and maps unmapped characters to separators; it avoids mbstring, which is not installed in the harness, by splitting with preg_split('//u').

C7 (fossil-era artifact, same preserved before bytes). In the no-label branch the fossil always stripped everything through the first colon, so [[[:scp-wiki : system : Recent Changes]]] displayed scp-wiki : system : Recent Changes. The late probe p-cross-colon-spaced (valid, stable and source-matching) shows live and ftml keep the leading colon in the display text, :scp-wiki : system : Recent Changes. The parse rule now keeps a leading : or / in that branch while still stripping an ordinary category prefix such as system: from [[[system:Recent Changes]]].

The two rule files' corrected SHA-256 values are 787720cc0b7dbe5bd874765a62b6a6cb68c99757532caae0cf486608b3b0d9f6 for the parse file and 7d0a2835a8b2c3797c8cc2e6876c540085ab0a4a7e0f7ef4e536dc6eace29d41 for the render file; both before-bytes copies were compared byte-for-byte against the originals before editing and the hashes are recorded in before-sha256.txt. All seven corrections are fossil-era artifacts or reference bugs except C3's harness-fatal component, which was removed by not using the fossil site path rather than by editing any shared stub.

## Battery and probe numbers

The 60-case battery covers both existence polarities and case variation against the stub map, opener and closer variants including double, quadruple and quintuple brackets and truncated closers, malformed and unterminated forms, empty and whitespace targets and labels, duplicate pipes, digit and alpha anchors, cross-site colon and fossil :: forms, category and multi-colon forms, URLs with leading, trailing and no space, hash routes, mid-line and line-start positions, adjacent freelinks, star and underscore targets, and Cyrillic and CJK targets. Before correction 40 of 60 reference render records agreed with the dumper under canonicalization of the dumper's missing newpage class and the reference's trailing newlines; after correction 56 of 60 agree, with the four remaining differences itemized below. Sixteen battery render records changed and 54 of 60 token records changed, the latter mostly because every recognized Freelink token now carries the extra and url option keys, with the substantive token changes confined to the anchor, label, alias, URL, hash-route and transliteration cases. Only one after record is an error, the textFromTitle stub case described below; every stderr sidecar is empty.

Of the 35 live probes, all are valid, stable and saved-source-matching. Before correction 15 agreed on all three sides, 2 agreed reference-plus-live, 16 agreed ftml-plus-live and 1 had all three disagree; after correction 32 agree on all three sides, 2 agree reference-plus-live against ftml, none agree ftml-plus-live, and 1 still has all three disagree. The change is entirely due to the C1 through C7 corrections; no probe was dropped or re-captured to improve the count, and the one late probe was added because its colon-label shape was the only battery shape live had not settled. The two all-reference-plus-live cases are the candidate ftml divergences F1 and F2. Existence polarity was checked in both directions: muse-probe-r2link-free-exists and its uppercase and mixed-case forms render as existing links on both reference and live, and muse-probe-r2link-free-new-page renders with the newpage class on both, while the dumper always shows the existing shape.

## Remaining disagreements, dispositions, and candidate findings

Class S (frame-level surface owned by later rules, not Freelink divergences). The reference leaves two trailing newlines after the paragraph where the dumper emits none, and its line-break spelling is <br /> where ftml emits <br> on battery case second-line and probe p-noline-start; both are Typography and frame shaping and were not corrected. The dumper's absent newpage class is a serving-layer consequence of its fixed existence resolver, not a rule difference.

Serving-layer scope. The textFromTitle branch on [[[muse-probe-r2link-free-exists2|]]] still records a fatal in the reference, explicitly as the one Error: record in ref-render-after.jsonl and probe p-exist2-empty-label in compare-probes-after.txt, because the inherited Wikilink renderer calls DB_PagePeer::instance()->selectByPrimaryKey($exists) with the boolean returned by the harness callback, so there is no page identity available to a title stub; I asked root for a stub and root declined it, confirming that page titles are real site state and that this fatal is a harness-side boundary, not a rule correction or a padded render record. Live settles the shape as the page's real title (>probe exists2</a>), while the dumper emits the slug, so this one probe is all-disagree and is recorded as serving-layer scope rather than as a reference or ftml error. Existence itself is real site state: live treats system:recent-changes as an existing Wikidot system page where the stub map marks it new, and this polarization is reference-versus-live only. External URL fetching and the page-title lookup are likewise outside this stage.

F1 (candidate ftml divergence, route to coordinator for an M-number continuing from M18). The quintuple-bracket form [[[[[SCP-001-EX]]]]] renders as [[<a href="/scp-001-ex">SCP-001-EX</a>]] on live and in the corrected reference, while the dumper renders [<a href="/scp-001-ex">[SCP-001-EX</a>]]. Evidence is probe p-quint with capture muse-probe-r2link-free-p-quint, battery case triple-quint, and the corpus pin test/link/triple showing the quadruple form; no ftml file was edited.

F2 (candidate ftml divergence, route to coordinator). A whitespace-only target [[[   |Label]]] renders as <a class="newpage" href="/">Label</a> on live and in the corrected reference, while the dumper leaves [[[ |Label]]] literal. Evidence is probe p-whitespace-target and battery case whitespace-target. No ftml file was edited and no reference change beyond keeping the already-correct fossil behavior was made.

Cross-rule seams are left to root's integration and are noted in findings-for-root.txt: freelink inside an Iftags-suppressed body, inside a math label position, and the boundary between a freelink and the Iframe greedy tail already adjudicated in R2-NEXT.md M8. One coverage note: a star-prefixed external triple link would need a target="_blank" render surface that live has but this battery does not probe, so it was not added. No ftml file, shared harness file, or other rule's file was changed by this owner, and no git commit or git identity variable was used.
