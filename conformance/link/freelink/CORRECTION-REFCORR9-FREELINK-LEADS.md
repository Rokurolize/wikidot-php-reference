Mechanism. The `/default:x` versus `/_default:x` split is a `WDStringUtils::toUnixName` consequence, not two different strip rules. The anchored regex of Freelink.php line 203 misses all four leads, so `$slugSource` keeps the lead byte. For the ASCII form feed and the ASCII star the non-ASCII transliteration gate is false; `toUnixName` (fossil WDStringUtils.php lines 112-134) turns 0x0C or 0x2A into `-`, then line 120 rewrites the following `_` to `-` because it is not colon-preceded, and line 121 strips the leading dashes, leaving `default:x`. For U+2028 and U+FEFF the gate is true, `freelink_transliterate` maps the unmapped code point to a leading ASCII space, `trim` removes that space, and the literal `_default:` is preserved by lines 119-131, leaving `_default:x`. Live consumes all four leads and strips the whole category, giving `/x`. The fix therefore widens the existing byte-oriented leading-run class by exactly the three evidenced lead shapes (0x0C, E2 80 A8, EF BB BF) and handles the star separately. The star is not whitespace: it is the new-tab marker that REFCORR3 already consumes on `$trimmed` for the URL branch. This unit adopts a separate narrow ordering rule, not a `\*` alternative in the whitespace class and not a live-side-only normalization: a single leading `*` at byte zero of the raw target is consumed on `$slugSource` under the identical no-leading-space guard before the anchored strip, so the category match succeeds. The byte check is on `$slugSource` itself rather than on `$starUrl`, because PHP `trim()`'s default charlist (" \t\n\r\0\x0B") is wider than the `[ \t]` leading-space test and could otherwise strip the wrong byte. The display-text path still reads `$raw` unchanged, so no authored label moves. No unevidenced Unicode whitespace is admitted: 0x0A, 0x0D and 0x00 remain unstorable/untestable and unchanged, U+2029, U+2000 and U+2002 were exercised as controls and do not move, and the full Unicode White_Space class and PCRE `\s` are deliberately rejected as in REFCORR8.
