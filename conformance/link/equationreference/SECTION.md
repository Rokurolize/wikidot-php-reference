# R2-link Equationreference rule: differential, correction, and section (2026-11-20)

Method. I compared three sides over one 57-case battery and one 26-case live probe set. The reference side is the shared read-only harness ref-php/harness/batch.php in modes render and tokens; because the fossil Math rule keeps its label-to-number map in the process-static Text_Wiki_Parse_Math::$equationsArray, I ran every case in a fresh /usr/bin/php process through the local driver run_isolated.py, writing ref-render-before.jsonl, ref-tokens-before.jsonl and their probe counterparts, and then re-ran the identical driver after analysis into the matching -after.jsonl files. Empty stderr sidecars accompany each side. The ftml side is the one shared dumper at conformance-refphp/link/rust-dump/target/release/r2link-rust-dump, run over the same battery and probe sources at the read-only checkout HEAD 97bed049ddeadc54981f6d9577bd78fcb212abd9 recorded in conformance-refphp/link/rust-dump/FTML-HEAD.txt (ftml-dump.jsonl and ftml-probe-dump.jsonl, both with empty stderr). The live side is 26 saved anonymous page views on sandbox-for-codex.wikidot.com under prefix muse-probe-r2link-eref-, created and captured with the bundled wikidot-probe CLI through scripts/wikidot-python (probe-cases.jsonl, probe-map.json, captures.json, probe-create.log, probe-capture.log and probe-capture-retry.log). All 26 captures are valid, stable and source-matching; one capture pass aborted on a transient HTTP 503 for p-pipe and the retry fetched all 26 pages successfully, so no page was dropped and no validity was padded. Sources are LF-only with trailing newlines stripped because Wikidot normalizes them on save. Evidence order when sides disagreed was ftml corpus pins, then frozen captures, then live probes; live behavior won every disagreement it settled. The battery is reproducible with make_battery.py, the probes with make_probes.py, the reference snapshots with run_isolated.py, and the reports with compare.py and compare_live.py in this directory; the full reports are compare-before.txt, compare-after.txt, compare-probe-before.txt and compare-live.txt. Two questions arose and are recorded here rather than silently resolved. The first was whether the canonical reference side should be a normal batch run or isolated per-case runs: the batch run demonstrably leaked equation numbers, so isolation was used, and root's later disclosed per-case reset in the shared harness independently removed the same leak without any edit by me. The second was whether the render file should be changed to emit &#39; so as to match ftml's attribute serialization: because live emits a literal single quote, I proceeded on the standing rule that live wins and made no such change.

## Mechanism as corrected

Parse rule (ref-php/text-wiki/Text/Wiki/Parse/Default/Equationreference.php). The file is byte-identical to its pre-correction state (SHA-256 e8d2fbd52057ba71bed2cbf6637f0adb3423038d4168f020df956dcf5bf786db) and was not edited. It keeps the fossil regex /\[\[eref (.*?)\]\]/, which requires a literal lowercase `eref` opener followed by a space, takes the first following close bracket pair on the same line, trims the captured argument, and emits an Equationreference token with a single label option. Text_Wiki's input prefilter normalizes a tab to a space before rule processing, so `[[eref<TAB>a]]` produces label a just as `[[eref a]]` does; `[[eref]]` without the space, `[[EREF a]]`, `[[eref_a]]` and `[[equation a]]` are left literal, and a label with more than one word such as `[[eref a b]]` is kept whole after trimming. A bare `[[eref ]]` or whitespace-only label yields an empty label and still emits a token. Every one of these shapes is confirmed on all three sides by the battery and by live probes p-no-arg, p-uppercase, p-two-spaces, p-tab, p-multiword, p-empty-arg and p-whitespace-label; no parse-regex change was justified.

Render rule (ref-php/text-wiki/Text/Wiki/Render/Xhtml/Equationreference.php). The file is byte-identical to its pre-correction state (SHA-256 e8c65d694ad9db6d5c66faf40439b2a93905f4cf01c6e513a02998c792d6737c) and was not edited. It reads Text_Wiki_Parse_Math::$equationsArray, takes the number for the token label, reads the xhtml math id_prefix render configuration (unset in the reference harness, so empty), and emits `<a class="eref" href="javascript:;" onclick="WIKIDOT.page.utils.scrollToReference('equation-<prefix><number>')"><number></a>`. An undefined label makes the array lookup empty, so the anchor has an empty target suffix and no visible number, which is the live shape on p-undefined, p-case-label and every undefined-label battery case. Because Math's parser runs earlier in the pipeline and populates the static array for the whole page, a forward reference resolves to the equation defined later (p-forward, e03, e49), a duplicated label resolves to the last definition (p-dup, e07), and a case-mismatched label does not resolve (p-case-label, e33). The Math stage's settled shapes in R2-NEXT.md part 5 are the ground for all of these: equation numbering is source order from one, the equation list belongs to Math, and this rule only consumes it.

## Corrections made

No corrections were made, and therefore no classification applies and no pre-correction byte copies were required. I state this positively rather than padding the section with an artificial change: on the 57-case battery and the 26 live probes the fossil Equationreference rule already reproduces live's matching space, label handling, number lookup, forward and duplicate resolution, undefined-label empty anchor, and the exact bytes of the anchor element, including the literal single quote in the onclick attribute. The only side that differs from live on the anchor is ftml, and the standing rule forbids changing either ftml or a reference rule on a shape where live and the fossil already agree. The four reference snapshot pairs are byte-identical under cmp, and the two rule-file SHA-256 values are unchanged from the start of the stage. The cross-case equation-number leak found at the start is recorded below as a harness matter, not as a rule correction; it was in the shared driver and has been fixed by root without touching this rule.

## Battery and probe numbers

The 57-case battery covers the canonical defined and forward-referenced forms, undefined labels, mid-line and line-start positions, two equations and multiple references, duplicate labels, opener spelling and case variations (EREF, Eref, equation, eqref, eref_a, eref-a), whitespace and empty labels, tabs and doubled spaces, unterminated and over-bracketed forms, multi-word, hyphen, underscore, pipe and equals labels, and adjacency with Math, Mathinline, code, div, collapsible, footnote, blockquote and bold. Before correction the reference and ftml agree on the eref shape (anchor target plus visible number plus leftover literal syntax) in 57 of 57 cases, and after correction in 57 of 57; raw whole-string agreement is 0 of 57 because of frame padding and the stubbed Math path, rising to 31 of 57 after canonicalizing &#39; entities, <br> spelling and trailing newlines. There are no token-mode differences: the Equationreference token options and Math token ids are identical before and after, and every stderr sidecar is empty. The reference and ftml agree on the eref shape in 26 of 26 probe cases before and after as well. Of the 26 live probes, all 26 are valid, stable and source-matching, all 26 agree on all three sides at the eref shape level, and none are reference-plus-live-only, ftml-plus-live-only or all-disagree. Restricting to the 21 probes that produce an anchor, the reference anchor bytes equal the live anchor bytes in 21 of 21, whereas ftml differs from live in 21 of 21 and from the reference in 21 of 21 solely by the quote-entity spelling. Raw whole-page agreement is naturally lower: live and the reference differ in trailing paragraph newlines, the Math block's stubbed error path, and wrapper padding from Div and blockquote, none of which is this rule's surface.

## Remaining disagreements, dispositions, and candidate findings

Class S (frame-level surface owned by later rules, not Equationreference divergences): the reference's trailing `\n\n` after a paragraph versus live's single newline; the reference's `<div >` with a space inside the tag versus live and ftml `<div>`; the newline padding inside blockquote and div wrappers; and ftml's `<br>` versus the reference's and live's `<br />` in the adjacent-Math case p-adjacent. These are serializer and wrapper differences that earlier stages already recorded as later-rule surface, and I did not correct them here. Class T (serving-layer scope): the substituted no-op LatexRenderer makes the reference Math render take the fossil "equation has not been processed correctly" failure path while live and ftml emit an equation-number span and image markup, and the reference therefore places a leading newline differently around the math block; this is the shared stub's known boundary, and real image generation, real-page equation lists and LaTeX environment selection remain outside this rule. The Math rule's own attribute-key and \include/\input gaps recorded in R2-NEXT.md part 5 are not mine to adjudicate. No live-settled reference error remains: every disagreement I could attribute to this rule's own matching, label or number behavior was absent on the probes.

F1 (candidate ftml divergence, route to coordinator and assign an M-number). In Wikidot legacy layout ftml's HtmlContext escapes the single quotes of the eref onclick attribute to &#39;, producing `<a class="eref" href="javascript:;" onclick="WIKIDOT.page.utils.scrollToReference(&#39;equation-1&#39;)">1</a>`, while live Wikidot and the fossil/reference both emit the raw quote `<a class="eref" href="javascript:;" onclick="WIKIDOT.page.utils.scrollToReference('equation-1')">1</a>`. The 21 anchored probes settle this byte-for-byte, for example muse-probe-r2link-eref-p-defined, p-undefined, p-dup, p-tab and p-midline, and battery cases e01 through e08 show the same split against the dumper. ftml's own corpus test wikidot_math_preserves_live_block_boundaries_and_dom has expected Wikidot HTML containing &#39;, so the entity is intrinsic to ftml's renderer rather than a dumper artifact. The reference was not changed and no ftml file was edited.

Coverage gaps are stated rather than padded. The probe set deliberately avoided LaTeX environment bodies and \include/\input forms because live's save filter refuses those sources, which the Math stage already recorded; those shapes are covered only in the local battery through the shared stub. Equation numbering inside footnotes, bibliographies and suppressed Iftags bodies is root's cross-rule integration and was noted rather than owned here. Any future live probe of the quote serialization should reuse the cached captures in this directory rather than creating a second set. No ftml file, shared harness file outside root's disclosed reset, git commit or git identity variable was changed by this rule owner.
