## Mechanism as corrected

Parse rule (ref-php/text-wiki/Text/Wiki/Parse/Default/Concatlines.php). Concatlines has no regex property: its entire matching space is the backslash-newline pair in the source left after the fifteen earlier rules have tokenized their spans. The corrected rule still removes a backslash immediately followed by a newline, and still does so in a single left-to-right pass, so in a run such as `a\\\n\nb` only the original pair is removed and the newly adjacent backslash and newline are not joined again. This single-pass shape is deliberate: live renders that run as `<p>a\<br />\nb</p>` byte-for-byte like the reference, while ftml's join_continued_lines in src/preproc/whitespace.rs repeatedly replaces the pair and is the divergent side. The one behavioral change is a continuation whose next line is a standalone div opener: the backslash is dropped but the newline is kept, so `a\\\n[[div]]` becomes `a\n[[div]]` and the div renders as a block on the following line instead of being pulled into the preceding paragraph. The lookahead regex `^\[\[div_?(?:[ \t].*)?\]\]$` is ASCII-case-insensitive and mirrors ftml's Wikidot continued-div-opener check; it covers `[[div]]`, `[[DIV]]`, attribute forms and `[[div_]]`, and it deliberately does not cover malformed openers such as `[[division]]` or `[[divx]]`, which remain ordinary joins. Continuations inside Code, Raw and Math bodies are still protected by the earlier rules' tokenization rather than by any new check in this rule.

Render rule (ref-php/text-wiki/Text/Wiki/Render/Xhtml/Concatlines.php). This file was not edited and is byte-identical to its pre-correction state (SHA-256 56aa72b9b58a98b4694512778ef7d0e69e8f9cd9fc01f77af16a243f12386416); the rule emits no token and its token() method returns the empty string. No render-side correction was needed because every live-settled divergence in this stage is a source-shape or later-rule surface matter.

## Corrections made

C1 (fossil-era artifact manifesting as a reference bug, preserved as Concatlines.parse.before.php with SHA-256 6ee6a3183d2d1f8501a72b3185e3a1dbcfe89f901bca1fc1067c6dca4c5c41cc before editing; corrected file SHA-256 f507d8fc69320801808006ac961faa257e92842b2626fa65b015f96b638876ac). The fossil's blind str_replace joined a continuation immediately before a standalone div opener, so the reference rendered `a\\\n[[div]]` as `<p>a<div ></p>` with the div opener fused into a paragraph, while live renders `a\n<div>` with the opener on its own line and ftml renders the same block shape. The lookahead exception above changes five battery render outputs (div-opener, div-opener-attrs, div-opener-upper, div-opener-tab, div-opener-underscore) and the five matching probe render outputs, and moves those five div cases from reference-alone against live-and-ftml to all-three agreement on the join decision. I tried keeping both the backslash and the newline first and rejected that variant: it leaves a visible literal `a\` where live shows a bare `a`, so the drop-backslash-keep-newline form is the one that matches live's observable source shape. No cascade change was made, because three live probes show the fossil's single pass is correct and ftml is the side that diverges.

## Battery and probe numbers

The 59-case battery covers plain joins and backslash/newline count variations (9 cases), whitespace and line-ending edges (9), cascades across repeated pairs (6), literal-span interiors and boundaries for Code, Raw, Math and Comment (12), div and span opener adjacency in pipeline order (9), adjacency with Freelink, Equationreference, Iframe, Date, IfTags, Mathinline, URL, Heading and Blockquote (10), and case and Unicode variations (4). Under the frame-normalizing comparison in compare.py, reference/ftml agreement is 48 of 59 both before and after correction; under exact HTML comparison after only `<br />` to `<br>` normalization it is 29 of 59 both before and after. Those totals do not move because the five corrected div cases still differ from ftml at the frame surface (`<p>a</p>` and `<div >` in the reference against a bare `a` and `<div>` in ftml and live) and because the cascade, Code-opener, Math-opener and Math-serving cases remain as itemized below. Five render records changed and no stderr was emitted. Raw token IDs shift for nineteen later cases because the harness uses one global token counter per process and the div cases consume different token counts, but only three token shapes changed: div-opener-underscore gains one Newline token from this correction, and freelink-cont and freelink-cont-space gain Freelink option keys from the Freelink owner's concurrent edit at 12:59 and 13:01, which is not a Concatlines change; the Freelink render outputs did not change.

Of 35 probe sources attempted, the backslash-crlf source was dropped because Wikidot rewrote its CRLF pair on save and read-back verification failed, which is a serving-layer line-ending boundary that live cannot settle and remains in the local battery only. The remaining 34 probes all produced valid, stable captures with byte-identical saved sources. Two whole-batch capture attempts hit transient Wikidot 503 responses after 32 and 25 pages and wrote no JSON, so run_capture.sh re-ran the same CLI over seven-case map slices with retries and merged the five part files into captures.json; this is a serving/harness matter, not a reference finding. After correction the 34 probes split into 25 all-three agreements, 5 reference-plus-live against ftml (three cascade cases, cont-into-code and date-cont), 3 ftml-plus-live against the reference (math-block-labeled, div-opener-underscore and eref-cont) and 1 all-disagree (cont-into-math). The two math cases among the three ftml-plus-live disagreements are the known stubbed equation surface, and div-opener-underscore is a Div-rule gap, both itemized below.

## Remaining disagreements, dispositions, and candidate findings

Class S (frame-level surface owned by later rules, not Concatlines divergences and not corrected): the reference's `<p>a</p>` wrapper and `<div >` or `<div  class="box">` attribute spelling against live's bare `a` and `<div>` in all five div-opener probes; the `<br />` versus `<br>` spelling and trailing-newline padding around paragraphs, Code blocks and Blockquotes; the tab expansion difference in tab-backslash-newline, where both sides join but the reference expands a tab to four spaces and ftml to one; the trailing-space difference in backslash-space-newline, backslash-tab-newline and backslash-two-spaces-newline, where both sides correctly refuse to join and only the earlier whitespace pass differs; and the stubbed "equation has not been processed correctly" block in Math, Equationreference and cont-into-math. These are serving- or frame-layer matters and no reference change was made for them.

F1 (candidate ftml divergence, route to coordinator). ftml's join_continued_lines repeatedly removes backslash-newline pairs, so `a\\\n\nb` renders as `<p>ab</p>`, while live and the reference render `<p>a\<br />\nb</p>` after a single pass. Evidence: probes muse-probe-r2link-concat-two-backslash-two-nl, -three-backslash-three-nl and -four-backslash-two-nl, battery cases with the same ids, and ftml's own test linear_line_continuation_join_matches_repeated_replacement in src/preproc/whitespace.rs. No reference change was made; the fossil is correct here.

F2 (candidate ftml divergence, route to coordinator). ftml requires a standalone `[[code]]` opener after a continuation, so `a\\\n[[code]]` stays literal, while live and the reference join the continuation and recognize the code block. Evidence: probe muse-probe-r2link-concat-cont-into-code and battery cont-into-code. The reference's additional mid-line paragraph/Code wrapper difference is class S.

F3 (candidate ftml divergence, route to coordinator). The same opener-recognition split holds for `[[math]]`: live and the reference join `a\\\n[[math]]` and recognize a math block, while ftml leaves the opener literal. Evidence: probe muse-probe-r2link-concat-cont-into-math and battery cont-into-math. The reference-versus-live equation markup difference in that probe is the stubbed serving surface, so this probe is the sole all-disagree case for reasons that are two separate, already classified matters.

F4 (candidate ftml divergence, route to coordinator). ftml joins a continuation inside a Date call before parsing it and renders an odate span, while live and the reference parse the Date call first and leave `[[date 12345]]` literal. Evidence: probe muse-probe-r2link-concat-date-cont and battery date-cont. This is a pipeline-order split in ftml's preprocessing, not a Concatlines error and not a reference change.

F5 (candidate three-way divergence, route to coordinator and the Iframe owner). For `[[iframe http://exa\\\nmple.com]]`, ftml joins the URL to `http://example.com`, live's Iframe rule has already captured the pre-continuation text and renders `src="http://exa/"`, and the reference renders `src="http://exa\"`. Concatlines cannot settle this because the Iframe rule tokenizes before it runs, so no reference change was made here; the live-versus-ftml join split is a candidate ftml finding and the backslash-versus-slash spelling is a frame-level Iframe surface. Evidence: probe muse-probe-r2link-concat-iframe-src-cont and battery iframe-src-cont.

N1 (reference gap outside this rule, route to coordinator and the Div owner). The reference's Div rule does not recognize `[[div_]]` even when it stands alone at the start of a document, so div-opener-underscore still renders literal in the reference while live and ftml render a div. My C1 correction correctly preserves the continuation for that opener, so the remaining difference is not a Concatlines matter. Evidence: probe muse-probe-r2link-concat-div-opener-underscore, battery div-opener-underscore, and a scratch harness check of `[[div_]]\nx\n[[/div]]`, which renders literal on the uncorrected and corrected reference alike.

Questions recorded rather than silently resolved: whether the div-exemption should keep or drop the backslash was settled by live's bare-`a` render, and variant B was adopted; CRLF and lone-CR sources cannot be settled by live because Wikidot normalizes line endings on save, so they stay in the battery as serving-layer boundaries; and the two transient Wikidot 503 capture failures were handled by chunked retries of the same CLI rather than by any reference or harness edit. No ftml file, shared harness file, git commit or git identity variable was changed by this rule owner.
