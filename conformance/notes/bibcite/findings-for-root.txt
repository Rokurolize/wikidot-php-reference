F1 (candidate ftml divergence, route to coordinator and assign an M-number continuing from R2-LINK's M27). In Wikidot legacy layout ftml escapes the single quotes of a bibcite onclick attribute to &#39;, producing onclick="WIKIDOT.page.utils.scrollToReference(&#39;bibitem-1&#39;)", while live Wikidot and the fossil/reference both emit the raw quote onclick="WIKIDOT.page.utils.scrollToReference('bibitem-1')". This is the same serializer split the Equationreference owner already routed in R2-LINK (their F1): live settles it byte-for-byte on the anchored probes muse-probe-r2notes-bibc-p-id-defined, p-id-two-cites, p-id-forward, p-dup-label, p-comment-label, p-anchor and p-footnote, and ftml's own corpus pin test/footnote/comment-bibcite-label/wikidot.html contains the &#39; spelling, so the entity is intrinsic to ftml's renderer and not a dumper artifact. It affects 7 of the 18 probes and all 22 anchored battery cases at the raw-byte level. The reference was not changed.

F2 (candidate ftml divergence, route to coordinator). ftml accepts a run of two or more spaces between `bibcite` and the label, while live leaves the whole call literal. Live probe muse-probe-r2notes-bibc-p-two-space (source `((bibcite  alpha))`, with a matching bibliography) renders `<p>((bibcite alpha))</p>` and no citation; p-three-space (`((bibcite   A9))`) does the same. The reference leaves both literal because its regex has a single `\s`; ftml collapses the space run into one Whitespace token and emits an anchor. Battery case bibc-13-def-two-space shows the same split. ftml's test tests/wikidot_inline_bibcite.rs asserts an error span for `((bibcite   A9))`, so its own pin is on the wrong side of live here.

F3 (candidate ftml divergence, route to coordinator). ftml accepts a tab as the `bibcite` label separator, while live leaves the call literal. Live probe muse-probe-r2notes-bibc-p-tab-sep (source `((bibcite<TAB>Tabbed))`, with a matching bibliography) renders the literal call; the Text_Wiki prefilter turns the tab into four spaces, so the reference's single `\s` cannot match. Battery case bibc-12-def-tabbed-cite shows the same split. ftml's test tests/wikidot_inline_bibcite.rs asserts an error span for `((bibcite\tTabbed))`, again against live.

F4 (candidate ftml divergence, route to coordinator). ftml rejects a newline between `bibcite` and the label, while live resolves the citation. Live probe muse-probe-r2notes-bibc-p-newline-sep (source `((bibcite\nalpha))` followed by a bibliography defining alpha) emits `<a href="javascript:;" class="bibcite" id="bibcite-1-12625a" ...>1</a>`; the reference also resolves it because PHP's `\s` includes the newline, while ftml renders the call literally because `Token::LineBreak` is in its invalid set. Battery case bibc-33-undef-newline-after-bibcite shows the same split. F2, F3 and F4 share one root cause in ftml's separator handling: the inline rule consumes exactly one Whitespace token and bans LineBreak, whereas live's Text_Wiki regex consumes exactly one whitespace byte including a newline after prefilter.

S1 (serving-layer scope, not a reference or ftml error; disposition requested). Live emits bibcite anchor ids of the form `bibcite-<index>-<five digits>a`, for example bibcite-1-82730a on muse-probe-r2notes-bibc-p-id-defined, bibcite-1-81110a on p-id-forward, and bibcite-1-73487a plus bibcite-2-67729a on p-id-two-cites. The suffix is stable across repeated anonymous fetches of the same saved page but differs between pages with identical source semantics, so it is a per-save generated DOM id, not a function of wikitext. The fossil reference emits `bibcite-<index>` with no suffix and ftml emits a fixed-seed stand-in `bibcite-<index>-81349a`; both differ from live only in that unpredictable value, while agreeing with live on the anchor's index, target, visible number and attribute order. I did not fabricate a deterministic suffix in the reference, because no live-settled value exists to copy and doing so would only replace one non-matching byte string with another. Please record this as serving-layer scope in the catalog and decide there whether a canonical placeholder is wanted. The same reasoning covers the stable-id property that ftml's src/render/html/random.rs documents.
