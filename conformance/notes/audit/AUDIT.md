R2-notes shared-harness audit: cross-case document-state leakage in the footnote and bibliography family (root-owned, disclosed in conformance-refphp/R2-NOTES.md).

Question. The LINK stage found a real process-static leak in Math: Text_Wiki_Parse_Math::$equationsArray is static and had to be reset per batch case. The brief directs root to audit batch.php for the same trap in this family's state before teammates start, because a differential polluted by leaked state is worse than no differential.

Method and evidence. The battery conformance-refphp/notes/audit/state-leak-battery.jsonl has seven whole-document cases in one batch.php render stream: a footnote defined with a footnoteblock, a bare footnoteblock with no note, a second footnote expected to be numbered 1 again, a bibliography with a bibitem and a cited label, an undefined bibcite with no bibliography, a second bibliography expected to restart at 1, and a mixed footnote-plus-bibcite document. Outputs are in batch-render.jsonl and tokens in batch-tokens.jsonl, with the pre-reset batch.php preserved as batch.php.before.php (SHA-256 f8640409b069c85779d0751fff32eea969483e7a52f908dbbc830459d4260c4b). Findings: case b renders an empty footnotes area; case c numbers its note 1; case e returns the "Bibliography item not found" error span; case f numbers its entry 1. A control that runs each case alone through transform.php in a fresh PHP process produces the same semantics (the only text difference is transform.php's trailing newline stripping, a pre-existing mode difference unrelated to state). Source inspection confirms why: Text_Wiki.php declares vars as an instance property (public $vars = array(), line 352), batch.php constructs a new Text_Wiki per case, and the six footnote/bibliography rules read and write only $this->wiki->vars['footnotes'], ['bibitems'] and ['bibitemIds'], lazily initializing them. A grep of all statics in ref-php/text-wiki/Text/ finds no footnote or bibliography static; the only process-static on the family's path is Math's equationsArray, reset by the LINK stage and incidentally read into an unused $refs local by the Footnote render rule. addToken() has a static id counter (Wiki.php line 1046) that advances across cases in tokens mode, but it only numbers token array keys and is output-neutral.

Action. Because the evidence shows no actual footnote/bibliography leak, no behavioural fix was required. As minimal, disclosed insurance against any future fossil change, batch.php now resets the three family vars explicitly immediately after each Text_Wiki is constructed in the render and tokens branches; the pre-reset file is preserved above. The reset is behaviour-neutral: re-running the battery after the change produced output byte-identical to the pre-reset run (batch-render-after-reset.jsonl), with no syntax errors and empty stderr. Teammates therefore run their differentials against a harness in which this family's state cannot cross a case boundary.

Second harness matter (R2-notes, root-owned, disclosed in conformance-refphp/R2-NOTES.md). The Bibliography owner reported that batch.php injected $wiki->vars['page'] only when a case declared a non-empty "tags" array, so an untagged case left the Iftags parse rule with no page object; that rule drops its whole body when the page is absent, which is not the same as an untagged page and made cases bib51-iftags-kept and bib52-iftags-closer-inside render an empty bibliography region. With tags:["unrelated"] the same cases matched live exactly (probe p11/p12). Root changed all three mode branches to inject a RefPage unconditionally, with an empty tag set when the case has no tags, preserving the R2-next comment's stated intent that absent tags means an untagged page. Verification is in audit/iftags-fix-check.jsonl and audit/iftags-fix-check.jsonl.out: untagged, tags:[] and tags:["unrelated"] now all produce the same live-matching render for both cases, and php -l is clean. Only Iftags reads vars['page'] in the reference tree, so no other rule is affected. transform.php is a one-document driver with no tags input and was not changed; its smoke battery contains no Iftags case.
