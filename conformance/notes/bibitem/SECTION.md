# R2-notes Bibitem rule: differential, correction, and section (2026-11-20)

Method. I compared three sides over one 52-case whole-document battery and one 22-page live probe set. The reference side is the shared read-only harness ref-php/harness/batch.php in modes render and tokens, run with /usr/bin/php; every snapshot has an empty stderr sidecar. The ftml side is the shared dumper at conformance-refphp/notes/rust-dump/target/release/r2notes-rust-dump, run over the same sources at the read-only checkout HEAD 6a029bf416651e0d68408f7c977b4cae30ebec55 recorded in FTML-HEAD.txt, with empty stderr. The live side is 22 saved anonymous page views on sandbox-for-codex.wikidot.com under prefix muse-probe-r2notes-bibi-, created and captured with the bundled wikidot-probe CLI through scripts/wikidot-python; all 22 are valid, stable across two independent anonymous GETs and source-matching by sha256, and the pages were left in place. Captures were fetched once, cached in captures.json (plus probe-map.json, probe-create.log, probe-capture.log and the two extra-probe logs for the whitespace-only bodies) and reused; no credentials were printed. Evidence order on disagreement was ftml corpus pins, then frozen captures, then live probes, with live winning every shape it settled. The battery is reproducible with make_battery.py, the probes with make_probes.py, the reference snapshots with the batch.php command line in the brief, and the reports with compare.py, compare_live.py and make_report.py. The full reports are compare-before.txt, compare-after.txt, compare-live-before.txt, compare-live-after.txt and the consolidated compare-report.txt.

## Mechanism as corrected

Parse rule (ref-php/text-wiki/Text/Wiki/Parse/Default/Bibitem.php). Bibitem has no regex of its own; the Bibliography owner's Parse/Default/Bibliography.php scans the block body and calls Bibitem::process with the matched label and value. Bibitem::process trims the value after replacing newlines with spaces, registers $this->wiki->vars['bibitems'][$label] = $content, computes $id = count($this->wiki->vars['bibitemIds']) + 1 and stores bibitemIds[$label] = $id, so numbering is one plus the number of distinct labels seen so far: bell, bell, guy renders 1., 2., 2. and a citation to bell resolves to 2, exactly what live probe p-dup and the frozen corpus pin bibliography-duplicate-definition show. It emits a start token with label, id, type start and the new empty boolean, the raw trimmed content, and an end token. The label grammar is [a-z0-9]+ case-insensitively, so uppercase and digit-leading labels form and hyphen, underscore and dot labels stay literal; live probes p-uppercase-label, p-digit-label and p-hyphen-label settle all three. The separator is the Bibliography matcher's \s? before the colon and \s after it, so no space before the colon still forms, two spaces before it do not, and no space after it does not; probes p-two-spaces-before-colon, p-no-space-after-colon and p-mixed-lines agree. When the \s consumes a line break after an empty body, the following line becomes the value, so : a : followed immediately by : b : Bravo. renders one entry whose body is ": b : Bravo."; live probes p-empty-then-entry and p-two-empty confirm this, and p-empty-blank-entry shows that a blank line instead yields two entries, the first empty.

Render rule (ref-php/text-wiki/Text/Wiki/Render/Xhtml/Bibitem.php). A start token emits <div class="bibitem" id="bibitem-<id_prefix><id>"> and then the period, a space only when the body is not empty, and the id; an end token emits </div>. The harness leaves id_prefix unset, so the id is bibitem-N as on live. The wrapper, the visible number and the id were already byte-correct against live on all 22 probes; the only change is the conditional separator. Nested inline markup in the value is emitted as source text between the two tokens and is formatted by later rules, which is why **bold**, //ital//, {{code}}, self-citations, footnotes, size and span all appear inside the div on live, reference and ftml; probes p-nested-markup, p-self-cite, p-nested-footnote, p-span-inline and b41 confirm the composition.

## Corrections made

One correction, C1, landed in both of my files and is classified as a fossil-era artifact manifesting as a reference bug: the fossil's render emitted $id . '. ' unconditionally, so an empty entry rendered "N. " with a trailing space, whereas live's saved-page HTML renders "N." with no space. Live settled this on four probes, p-empty-body, p-empty-blank-entry, p-space-only-body and p-tab-only-body, and ftml's renderer already branches on elements.is_empty() in src/render/html/element/bibliography.rs, so the fossil snapshot, not live and not ftml, was the outlier. The parse file now adds an 'empty' => ($content === '') option to the start token and the render file uses empty($options['empty']) to choose the separator, with empty() chosen so a token produced by any other caller still gets the old space rather than a missing one. Pre-correction bytes were preserved before editing as Bibitem.parse.before.php with SHA-256 7722075b1b10a8cb5c4febbe96acb940ca9a0e303808c40e3a6d20a153ea024d and Bibitem.render.before.php with SHA-256 70c75bfa6e1c8395048672d94a5daa65371f8ad962c040732bc7cfb3f2e5b0ea; the corrected files hash to b231e3fdfe900c04de4421e9246ac448b807a1f37df43602e236b3ddf54dc3ee and 8e031b79d66fa256183107867af58a6ef815711d2dbeb03c80a035e8190911fc. Both pass php -l. No other rule file, no shared harness file and no ftml file was changed by me, and there was no git commit or git identity variable.

## Battery and probe numbers

The 52 battery cases cover single and multiple entries, adjacent and separated duplicate labels, the bell/bell/guy numbering case, empty and whitespace-only bodies, empty bodies followed by a value or a blank line, nested italics, bold, links, self-citations, footnotes, code, span and size, forward and backward citations, undefined labels, citation-only and block-only documents, title and hide options, hyphen, underscore, uppercase, digit-leading and long labels, malformed separators, unterminated blocks, non-definition bodies, mixed valid and invalid lines, tabs, div/collapsible/table adjacency, footnoteblock and footnote adjacency, a second bibliography block and special characters. Against the dumper, before correction raw whole-string agreement was 0/52, bibitem-family shape agreement 41/52 and bibitem-div agreement 47/52; the raw figure rose to 29/52, shape to 42/52 and bibitem-div to 48/52 after correction, with most of the raw jump coming from the inter-div whitespace fix the Bibliography owner made during this run. Because teammates edited Bibliography, Footnoteitem and Footnoteblock during my run, I produced a controlled-before snapshot with every teammate's current file and only my two files reverted: that snapshot has raw agreement 28/52, so my correction alone accounts for 29/52 minus 28/52, one battery case. Isolated A/B changes exactly one battery render case, b07-empty-body, and four of the 22 probe render cases, each only 'N. ' to 'N.'; token mode changes only by the added boolean 'empty' option on Bibitem start tokens in 44/52 battery and 19/22 probe cases, with no rule, label, id or content change. Against live, before and controlled-before both had live==reference 16/22, live==ftml 19/22 and all-three 14/22; after correction live==reference is 20/22, live==ftml 19/22 and all-three 18/22. The four newly matching probes are exactly the empty-body ones. The remaining two live==reference mismatches are p-self-cite and p-span-inline, and the three live==ftml mismatches are p-self-cite, p-nested-footnote and p-special-chars. Every stderr sidecar for all four reference runs and both ftml runs is zero bytes.

## Remaining disagreements, dispositions, and candidate findings

Class S (frame-level surface owned by later rules, not Bibitem divergences): the reference's <span style=""> against live and ftml <span> in p-span-inline and b49; the reference's <br /> against live and ftml <br>, its <div > with a space inside the tag, its indented <dl> and trailing paragraph padding; and the inter-div whitespace that the Bibliography owner removed during this run. None of these is inside Bibitem's two files and I did not correct them. Class T (serving-layer scope): live's bibcite anchor id carries a six-hex suffix stable across two fetches of one page but different across pages, while ftml emits a fixed per-index suffix and the reference emits none; this is per-render noise in the citation surface owned by Bibcite, not a Bibitem correctness claim. The empty-body space itself is the one live-settled shape where the fossil was wrong and is now corrected.

F1 (candidate ftml divergence, numbered for the coordinator and routed in findings-for-root.txt). ftml escapes an ASCII apostrophe to &#39; in both text and onclick attributes inside bibliography entries, while stable direct anonymous GET captures of live show the raw apostrophe. Probes p-special-chars, p-nested-footnote and p-self-cite and battery cases b42, b14 and b13 carry the evidence, and ftml's own unit test in src/render/html/element/bibliography.rs encodes &#39; in expected Wikidot HTML, so the entity is intrinsic to its renderer rather than a dumper artifact. No ftml file was edited and no reference rule was changed on this shape. There is no Bibitem-specific candidate ftml divergence: the div wrapper bytes, the distinct-label numbering, the empty-body rule, the label charset and the separator grammar all agree with live.

Coverage gaps are stated rather than padded. Probes deliberately restricted themselves to the anonymous saved-page view, so configured id_prefix values, site-specific bibliography titles and non-anonymous role differences remain outside this rule's claim. Numbering when entries sit inside suppressed Iftags bodies, included content and multiple footnotes is root's cross-rule integration and was noted, not owned; battery cases b35 through b39 exercise div, collapsible, table and footnote adjacency locally but live ownership of those seams belongs to the coordinator. The question of whether live's missing empty-body space originates in Text_Wiki or in libtidy is not directly observable from a saved page; I proceeded on the assumption that the reference harness must reproduce live's observable saved-page HTML and that a live-settled shape in Bibitem's own div prefix is therefore correctable here. Any future probe of the quote serialization should reuse the cached captures in this directory rather than creating a second set.
