Mechanism. Raw's four-or-more-@ scanner claims an empty Raw token `['Raw', ['text' => '']]` whose placeholder in the stored body is `\xFF<id>\xFF`. Tighten deletes that placeholder and the Raw renderer emits no bytes, so a body consisting only of such a placeholder (optionally surrounded by whitespace that the process trims) is empty on live. `Parse/Default/Footnote.php` now strips empty-Raw placeholder tokens from the trimmed body before storing it at `vars['footnotes'][id-1]`, so the existing `$body !== ''` test in `Render/Xhtml/Footnoteitem.php` sees the live emptiness without that render rule changing. `Parse/Default/Bibitem.php` strips the same placeholders from its trimmed content only to compute the start token's `empty` flag; the stored `vars['bibitems'][$label]` body and the emitted content keep the exact original bytes. Both strippers replace only placeholders whose token entry is exactly `['Raw', ['text' => '']]`; a literal remainder (fn-six keeps `@@`) and a non-empty Raw token (fn-free's `x`) are left intact. No token entry is added, removed or reindexed, and no compared field is added for the side effect; the only compared-value changes are the footnote body for fn-empty/fn-ws/fn-six and the Bibitem `empty` flag for bib-empty, each mirrored identically in the Lean side.
