# R2-notes Part 5: Bibliography

Mechanism as corrected. The Bibliography rule is pipeline position 23 and overrides parse() with a null regex. Its parse pass claims a lowercase [[bibliography ...]] opener at a line start through the first [[/bibliography]] closer at a line end (with optional trailing blanks), converts each ": label : text" line in the body into a Bibitem entry token by calling the Bibitem rule before the join, and lays the resulting body out as one logical line so the later line-anchored rules (list, deflist, table, div, heading and their kin) never see a line start inside it; unanchored rules such as Bibcite, Span, Size and the strong/emphasis passes still form there. The corrected parse now walks the body with an alternation pattern whose definition branch consumes the trailing line break and whose residual branch keeps the authored text: a newline token is placed before a residual run and again after it when an entry follows, consecutive residual lines are separated by one space, and definition entries sit adjacent with no separator. Runs of ASCII whitespace inside a residual line collapse to one space, while a non-breaking space is preserved. The render pass emits <div class="bibitems"> plus a <div class="title"> with the parsed title (default "Bibliography", omitted when the title is the empty string), the body tokens, and </div>, and it now also renders the new opaque newline token as a literal newline. Those newline tokens are placeholders during parsing, so the final Tighten pass never sees them and later line-anchored rules cannot form, but the renderer reproduces live's residual line breaks.

Remaining disagreements and dispositions. Candidate ftml divergence BIB-F1 (proposed M30) is the empty title: live and the reference omit the title div while ftml emits an empty one; the reference is live-correct and no change was made. BIB-F2 (proposed M31) is the separator between consecutive residual lines: live and the reference use one space, ftml uses none, and both live probes and a frozen pin settle it. BIB-F3 (proposed M32) is a footnote-family tail spacing difference seen in p13, where live and the reference have a space before the footnotes footer and ftml does not; root should route it to the footnote owner. A correction belonging to another rule is the empty bibitem value: live, ftml and the pin render "4." while the fossil Bibitem render prints "4. ", so it is routed to root for the Bibitem owner and not edited here. A harness matter is also routed to root: batch.php only sets vars['page'] for cases with non-empty tags, so untagged iftags cases drop their body before Bibliography runs; an A/B test with tags:["unrelated"] makes both iftags cases match live exactly. The remaining differences are frame-level or later-rule surfaces: bibcite id suffix and quote escaping, the empty style attribute on a bare span, typography numeric entities, table interior whitespace, and paragraph and deflist wrappers outside the bibitems region; live probes confirm these are not Bibliography divergences. The numbered list with evidence is in findings-for-root.txt.

Questions and assumptions carried forward. The brief's note that whole documents are required was read as a battery-design constraint rather than a claim that the fossil rule only matches a bibliography occupying the entire source; cases with prose before and after the block (bib01, bib02) form on all three sides, so no matching change was made on that basis. The live probes cannot settle parser-internal newline handling directly, so the read-only ftml corpus pins and the double-fetched saved pages were used together to fix the observable layout; where the pins and the live saved page differ only in libtidy's inter-element newlines, the frame difference was normalized away and the entry and residual bytes were compared exactly. No ftml file, shared harness file, git commit or git identity variable was used.
