# R2 List rule (pipeline rule 33): differential, correction, and disposition

Method. I read `ref-php/text-wiki/Text/Wiki/Parse/Default/List.php` and `ref-php/text-wiki/Text/Wiki/Render/Xhtml/List.php`, the ftml rule sources `src/parsing/rule/impls/list.rs`, `src/parsing/rule/impls/block/blocks/list.rs`, `src/render/html/element/list.rs` and `src/tree/list.rs` in the read-only checkout, and searched the 389-case `test/list/` corpus plus the list shapes in misc, blockquote and span pins. The fossil hypothesis that List matches line-start `*` and `#` runs with space-indentation depth was confirmed as a hypothesis, but its structural details were corrected: live requires column zero for the first marker, one space after the marker, one nesting level per leading space, and it drops empty items. Evidence order was corpus pins first (notably `native`, `native-wikidot-structure`, `native-literal`, `native-skipped-depth-empty-parent`, `only-empty-items-keep-paragraph`, `whitespace-only-item-vanishes` and the `wikidot-li-*` families), then the shared dumper at ftml HEAD a61ae005d, then live saved-page probes. All prose here describes live behavior as the oracle; no ftml file was edited, no cargo was run, and the shared harness and dumper were used read-only.

Mechanism as corrected. The outer regex still finds a maximal run of marker lines and is unchanged, so run boundaries, marker-type changes at column zero, blank-line splits and continuation lines are computed exactly as before. `process()` now collects the run's item lines first, strips leading spaces after the marker from each body, and drops a whitespace-only item unless a deeper item immediately follows, in which case it survives as an empty list item holding the child list; a run with no surviving items returns no tokens and therefore no list. Zero-based depth replaces the fossil's one-based level. Opening a depth skip emits one nested list for the child level and one inline list-item wrapper (`<li style="list-style: none; display: inline">`) for each further missing level, with the list-type taken from the deep item's marker; the parse records, per open list, whether its last child was an item or a wrapper so closing can emit the right shape. The Xhtml renderer emits `<ul>`/`<ol>` with a newline after the tag, a newline before a nested list that is inside an ordinary item, no such newline when the nested list is inside a wrapper, `</li>` before the list close for an item tail and no `</li>` for a wrapper tail, and closes wrappers without trailing newlines. This reproduces the live and pinned nested-list shape byte for byte; the fossil's tab-based pretty-print indentation is gone. The token rule name, token option vocabulary for item starts and ends, and all downstream contracts are preserved, with new `sublist_start`, `sublist_end`, `in_sublist` and `tail` options added.

Corrections and classifications. C1, empty-item and empty-container handling (fossil-era artifact, routed here by NOTES and CONTAIN and confirmed live): the fossil emitted an empty `<li>` for `* `, `# `, whitespace-only bodies and all-empty runs; live probes p01, p02, p04, p05 and p08 and pins `native` and `whitespace-only-item-vanishes` show those items vanish and an all-empty run emits no list at all, while probes p06 and p07 and pin `native-skipped-depth-empty-parent` show an empty item survives when it holds a child. C2, extra spaces after the marker (fossil-era artifact): the fossil kept the surplus space in the body; live probe p11 (`*  two spaces` -> `<li>two spaces</li>`) and the dumper settle that it is stripped. C3, skipped-depth wrappers (fossil-era artifact): the fossil opened a single nested list for a multi-level jump; live probes p09 and p10 and pins `native` and `native-skipped-depth-empty-parent` show one inline-style wrapper per missing level. C4, nested-list whitespace and pretty-printing (fossil-era artifact): the fossil inlined nested tags and indented with four-space pads; live probes p06, p07, p09 and p10 and the pins show the newlines and wrapper closes described above. C5, per-level item count reset (reference bug exposed during the rewrite): the one-based `unset($itemcount[$level + 1])` became wrong under zero-based depth and produced a stray `</li>` when a sibling list reopened a level; battery cases `d08-sibling-sublists` and `m03-child-switch` caught it and the reset is now `unset($itemcount[$level])`. The exact pre-correction bytes are preserved as `List.php.before.php` (the parse rule, from `Text/Wiki/Parse/Default/List.php`) and `ListXhtml.before.php` (the Xhtml render rule, from `Text/Wiki/Render/Xhtml/List.php`); the render copy is named with the Xhtml suffix to distinguish it from the parse copy.

Battery and probe numbers. `battery.jsonl` has 59 whole-document cases generated by `make_battery.py`, covering single-step depth changes, skips, returns, marker-type changes at root and nested levels, mixed ordered and unordered nesting, space and tab indentation, empty and whitespace-only items, block and inline item content, paragraph, heading, quote, code, hr and div interruption, unterminated runs at EOF, and malformed and literal forms. Before correction the reference agreed with the dumper on 17 of 59 cases under the stage's frame join normalization and disagreed on 42; after correction it agrees on 50 of 59, with 41 of 59 byte-identical before any normalization. All four capture files have matching empty `.err` sidecars, and neither driver produced a case error. The live set is 13 probe pages under the exclusive prefix `muse-probe-r2list-list-` on sandbox-for-codex, all 13 valid with two identical anonymous GETs and `saved_source_matches=true`; sources, fullname map, raw captures, both probe-side driver outputs, the adjudication script and its report are under `probes/`. Against live the corrected reference matches 10 of 13 probes and the dumper matches 10 of 13 under frame normalization, with the same three cases differing for each side.

Remaining disagreements and dispositions. Nine battery cases still differ from the dumper after normalization, and none is owned by List: `b02`, `b04` and `b10` are inter-block newline joins from the paragraph and frame rules; `b05` is blockquote inner padding; `b06` is a monospace-rule space difference (`<tt> code </tt>` against `<tt>code</tt>`); `b08` is the frame rule's `<hr />` against `<hr>`; `b09` is Div's doubled attribute space and inner padding; and `d09` and `d11` are the leading-space strip on literal paragraph lines already recorded as class S surface in R2-FORM-RAW. Probe p08 differs only by one frame newline before a trailing paragraph. LIST-F1: on probes p09 and p10 the current live page inserts a newline after each inline wrapper `<li>` and before its close, while the pinned dumper and the corpus `wikidot.html` pins put the nested list immediately after the wrapper tag; the tag structure is identical and the difference is whitespace inside the wrapper only, so I kept the reference aligned with the pins under the stated evidence order and hand the whitespace question to root as a candidate ftml divergence with anonymous live captures attached. LIST-F2: ftml has an explicit `[[ul]]`/`[[ol]]`/`[[li]]` list block (`test/list/block`, `block-fail`, `fused-*` and others, with real list output in their `wikidot.html` pins) that the fossil reference has no rule for, so those sources stay literal on the reference side; this is a coverage gap outside my two owned files, not a correction I could make here, and root should route it with the other cross-rule interactions. The G1.5 F-G15-1 post-list-break material is ftml-side context for these differentials, not a reference question; the post-list cases here all settle at frame level. No serving-layer question arose: every shape was decided from the anonymous saved-page view.

Questions and assumptions. The tab-indent live probe was dropped before saving because Wikidot normalizes a tab out of saved source, so `saved_source_matches` cannot hold for it; I relied on the Prefilter rule's tab-to-four-spaces conversion, battery case `d10-tab-indent`, and the dumper's three-wrapper output instead, and recorded that as the assumption taken. Probe pages for empty markers needed a trailing sentinel line because Wikidot trims trailing document whitespace on save; the sentinel is a following paragraph and does not change which empty items survive. I proceeded on the standing rule that pins precede probes when the two disagree on whitespace, which is the only place the evidence order mattered.
