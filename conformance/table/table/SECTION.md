# R2 Table rule (pipeline rule 35, the || cell-separator form): differential, correction, and disposition

Method. I read `ref-php/text-wiki/Text/Wiki/Parse/Default/Table.php` and `ref-php/text-wiki/Text/Wiki/Render/Xhtml/Table.php`, the corresponding ftml sources `src/parsing/rule/impls/table.rs` (in particular `parse_cell_start`, which decides how `~`, `=`, `>` and `<` are consumed), `src/parsing/rule/impls/block/blocks/table.rs`, `src/render/html/element/table.rs` and `src/tree/table.rs` in the read-only checkout, and searched the 148-entry `test/table/` corpus. The decisive pins were `simple` (spans, `~` headers, alignment, inline content and two-cell rows), `unspaced-marker-literal` (markers need the following space; `||~ H ||` is a `<th>` but `||~Head||` and `||~~ A ||` are literal, and `|| ~ Head ||` is literal because the marker is not the first cell character), `simple-aligned-colspan`, `simple-unterminated-row`, `simple-unterminated-row-opener-only`, `fail`, `simple-eof`, `simple-followed-by-paragraph`, `simple-trailing-whitespace`, `simple-comment-cell-trim`, `simple-cell-carry-in` and `tf-nested-table`. Evidence order was corpus pins first, then the shared dumper at the recorded ftml HEAD a61ae005d9e837171a3d2b91cf8fc2df7a3d8ae8, then anonymous saved-page probes on sandbox-for-codex. The harness sets the table css class to `wiki-content-table` through `ref-php/harness/wiki-config.php`, so that class is part of the observable shape. No ftml file was edited, no cargo was run, and the harness and dumper were used read-only. The fossil is treated as a skeleton throughout; the dumper is pinned and never rebuilt here.

Mechanism as corrected. The outer regex `/\n((\|\|).*)(\n)(?!(\|\|))/Us` and the line-oriented loop are unchanged, so run boundaries, blank-line splits between tables, cell splitting on `||`, trimming of each cell body, span accumulation from empty cells into a following non-empty cell, and the marker grammar are exactly as the pins require: `> `, `= `, `< ` and `~ ` are recognized only as the first two characters of a cell, so `|| ~ Head ||` correctly stays a literal `~ Head` in a `<td>` while `||~ Head ||` makes a `<th>`; repeated or unspaced markers stay literal. Two corrections were made. C1 removes the fossil's pretty-print layer from the Xhtml renderer: `<table>` no longer emits leading or trailing blank lines, `<tr>` and cell tags no longer carry four- and eight-space indentation, and cell tags no longer contain the stray space before `>` (`<td >` became `<td>`). The newline after each cell and each row, the `colspan`, the `style="text-align: ...;"` attribute and the `wiki-content-table` class are preserved, and the embedded `<caption>` and `format` paths still work. C2 makes the parse rule emit one empty cell when a row has no non-empty cell at all, which covers all-empty pipe rows, a bare `||`, and a row whose only text sits after the final unmatched pipe, as the pins `fail` and `simple-unterminated-row-opener-only` and live probe p03 require. The accumulated span is deliberately not carried into that empty cell because live probe p03 shows span one for `||||` and `||||||`; spans are still carried into a following content cell, which `simple` and `simple-aligned-colspan` require. Token names and option vocabulary are unchanged apart from the new empty cell tokens.

Corrections and classifications. C1, renderer surface (fossil-era artifact): the indents, blank lines and stray attribute space are the fossil's pretty-printing, not live output; pins such as `simple/wikidot.html` and `simple-followed-by-paragraph/wikidot.html` and every live probe show the compact shape, so the render rule now emits it. C2, empty rows and unterminated rows (fossil-era artifact, with one live-only detail): the fossil discarded the whole row when no cell had content; live and the pins emit one empty cell, so the parse rule now emits a `cell_start`/`cell_end` pair with span one in that case. The pre-correction bytes are preserved verbatim as `Table.php.before.php` (parse rule, from `Text/Wiki/Parse/Default/Table.php`, SHA-256 615a562690df3d6e1a6c6415e6f6a14f7dcadcc2258b58cba9eb1bfb83e57254) and `TableXhtml.before.php` (Xhtml render rule, from `Text/Wiki/Render/Xhtml/Table.php`, SHA-256 dd18368fe3d0ec0ce27299339d53281579a9451bb45f2449bef7ab26e049d324); the render copy carries the Xhtml suffix to distinguish it from the parse copy.

Questions and assumptions. The `|| ~ Head ||` shape was the leading question: pins `unspaced-marker-literal` and `simple` settle it as literal, and live probes p01 and p02 confirm that the spaced form is literal while the unspaced form is a header, so it is live truth and not a marker-grammar difference I needed to correct. Probe sources carry a trailing sentinel paragraph `x` because Wikidot trims trailing document whitespace on save; the sentinel is after the table and does not affect any table shape. The `< ` left-alignment marker needs a following space and only applies after a `||` delimiter, which probe p05 confirms. The read-only ftml checkout advanced from a61ae005d to f9dc0e41086de31f2be6d42d4e7e5f085bcb8220 mid-stage on a module-only commit (#1540) that changes no table source or pin; per root's instruction I kept using the already-built dumper pinned at a61ae005d, did not rebuild cargo, and did not re-run any differential at the new HEAD. The final captures were produced while the Tableadv owner was concurrently correcting that rule, so they describe the corrected tree at the time they were taken. I proceeded on the standing rule that pins precede probes when the two disagree on shape, which mattered only for the frame newline and never for a table cell or row shape.
